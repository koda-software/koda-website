---
title: Upgrade and uninstall
description: "Review and install a new version of an Opero extension, confirm an upgrade that deletes data, and uninstall an extension with or without its data."
---

This page covers installing a new version of an extension, and removing it. Upgrading needs `org.extensions.update` and uninstalling `org.extensions.delete`. A package with data scopes is upgraded only by an organization owner.

## Upgrade an extension

<Steps>
<Step>
### Get the new version

Upload the new version's zip as you uploaded the first one; see [Install an extension](/docs/en/extensions/install#install-a-package). A catalog package's new version arrives on its own when the installation's administrator uploads it.
</Step>
<Step>
### Check the update card

The extension's page shows **Update available** in its side column, with the new version and whether anything blocks it. Its version in the list of installed extensions gets an arrow.

![An update is available, and nothing blocks it](/docs/_assets/extensions/upgrade/update-available.webp)
</Step>
<Step>
### Review the update

Press **Review update**. When several newer versions are uploaded, **Version to install** chooses one. **New in this version** shows the changelog of every version after the installed one, when the package has a [changelog](/docs/en/extensions/reference/listing#the-changelog).

![The upgrade review with the changelog of the newer versions](/docs/_assets/extensions/upgrade/review-changelog.webp)

The rest of the review is the [install review](/docs/en/extensions/install#the-install-review). **What it adds** lists only what changes: items marked **Modified** or **Removed**, and a count of the items that stay as they are.
</Step>
<Step>
### Upgrade

Press **Upgrade**. Then do what **After it runs** lists, for example verify the connection again.
</Step>
</Steps>

A version never changes once uploaded. Uploading the same file again changes nothing, and a different file with the same version is refused. **Withdraw this version** on an available package's card stops anyone from installing that version; an installation that runs it keeps running it.

## What a new version can change

Rules that use a step keep working across versions, as long as the step's action keeps its name. The review warns about everything else, and blocks what would break your configuration.

| The new version | What happens | Code |
| --- | --- | --- |
| Removes a rule step your rules use | Blocked until those rules stop using it. | `step.in_use` |
| Removes a template filter a rule uses | Blocked. Templates are not checked, so a template that still uses it fails later. | `filter.in_use` |
| Removes a trigger a rule starts on | Blocked until no rule uses it. | `trigger.in_use` |
| Removes data fields of a trigger a rule uses | A warning. Check the rules that read them. | `trigger.data_field_removed` |
| Removes an action your own blocks run | Blocked until those blocks change. | `block_action.in_use` |
| Drops a query an active SQL list, report or block uses | Blocked until they stop using it. | `query.in_use` |
| Drops an object or a field, or clears a field's values | **This upgrade deletes data**; see [below](#when-an-upgrade-deletes-data). | |
| Drops a dictionary | It is deleted, or kept as your own when something still uses it. | `dictionary.released` |
| Removes a form, a list or a page your configuration uses | The form is deleted, the list or page archived. Your pages show a notice, and menu items to the page are hidden. | `form.in_use`, `list.in_use`, `page.in_use` |
| Removes the only form of an object | A warning: members cannot open or create its records until you build a form. | `object.formless` |
| Removes a block your pages place | Those pages show a notice in its place. | `block.removed_placed` |
| Drops a package permission roles grant | The grants are removed with it. | `permission.grants_removed` |
| Changes the connection's credentials | The connection is switched off until you verify it again. | `connection.reverify_required` |
| Drops a setting's value, or makes it no longer fit | The value is dropped. | `settings.value_dropped` |
| Adds a required setting without a default | The extension stops until you fill it in. | `settings.incomplete_after_upgrade` |
| Stops a schedule, or changes when or for whom it runs | A stopped schedule's run state is deleted; a changed one follows the new schedule at once. | `schedule.removed`, `schedule.changed` |
| Asks members for more | Every connected member must connect again; until then nothing runs for them. | `member.reconsent_required` |
| Asks for new hosts or data scopes, or adds triggers or schedules | Shown as **New in this version**, for you to agree to. | |

## When an upgrade deletes data

When the new version drops an object or a field, or changes a field so that its values must be cleared, the review opens with **This upgrade deletes data**. Each loss is listed with its number of records.

![An upgrade that deletes an object and a field; it waits for confirmation](/docs/_assets/extensions/upgrade/data-loss.webp)

**Upgrade** stays off until you tick **I understand that this data is deleted for good.** If the data to lose changes before you confirm, the upgrade is refused, the review is read again, and you tick the box again.

<Callout type="warn" title="Deleted data cannot be recovered">
Records of a dropped object and values of a dropped or cleared field are gone after the upgrade. There is no undo.
</Callout>

## Uninstall an extension

<Steps>
<Step>
### Open the uninstall dialog

On the extension's page, open **More actions** (the three dots in the header) and choose **Uninstall**. The dialog first reads what the uninstall would take with it.
</Step>
<Step>
### Read what stops and what goes

Rules of your organization that use the extension's steps or triggers are listed first: active ones stop and are quarantined, inactive ones cannot be enabled until you remove the extension's steps from them. **Always removed** unfolds what goes in every case.

![The uninstall dialog: keeping or deleting the data, and what is always removed](/docs/_assets/extensions/upgrade/uninstall-dialog.webp)
</Step>
<Step>
### Choose what happens to the data

For an extension with objects or dictionaries, choose **Keep the data** or **Delete the data**; see [Keep or delete the data](#keep-or-delete-the-data).
</Step>
<Step>
### Confirm

Press **Uninstall and keep the data** or **Uninstall and delete the data**. An extension without data has one **Uninstall** button.
</Step>
</Steps>

### What is always removed

| Part | What happens |
| --- | --- |
| Rules, template filters, triggers and blocks | Removed. |
| Schedules | They stop, and their run state is deleted. |
| The connection | Removed with every stored credential. |
| Settings | Removed. |
| Saved queries | Deleted when nothing uses them; kept as your own when an SQL list, report or block uses them (**Kept as your own**). |
| Forms | Deleted, with nothing generated in their place. The dialog lists objects left without a form, and the access you set on the forms, which is lost. |
| Lists and pages | Archived as removed. Menu items to the pages are hidden, and come back if you install the extension again. |
| Members' connected accounts | Disconnected. The package's disconnect action runs for each member first. |
| Package permissions | Removed from the roles that grant them. |

### Keep or delete the data

| Choice | Objects with their records, the module and the dictionaries |
| --- | --- |
| **Keep the data** (recommended) | Kept as your own: editable, and back in the management lists. Installing the extension again takes them over. |
| **Delete the data** | Deleted for good, with the forms, view layouts and Custom Lists built on the objects, and your own reference fields that point at them. Rules that name an object stop (quarantined). A dictionary something else uses is kept. |

**Delete the data** cannot be chosen when you lack a permission it needs; the choice names them (**You lack: …**). Deleting is also refused while a saved query that is kept reads a table it would drop: stop using that query in its lists, reports or blocks first. In both cases nothing is changed.

<Callout type="warn" title="Rules that use the extension stop">
Uninstalling cannot be undone. Your rules that use the extension's steps or start on its triggers are quarantined. Installing the extension again and switching its connection on lets you save and enable them again.
</Callout>
