This page takes an extension from a zip file to an installed extension that is ready to set up. You work on **Extensions** in the organization's administration, under **Integrations**.

## Before you start

| You need | For |
| --- | --- |
| `org.extensions.create` | Uploading a private package and installing. |
| `org.extensions.read` | Seeing the list, the review and an installed extension's page. |
| The permissions to create what the package brings | Installing. The review lists them under **Needed to install**; the built-in administrator role holds them all. |
| The modules the package needs | Installing. Most packages need Rules; a package with objects also needs Objects, one with queries the Queries module. |
| The organization owner role | Installing a package that asks for access to data. |

## Where packages come from

| Kind | Shown as | Who adds it |
| --- | --- | --- |
| Private package | **Private package** | Someone in your organization uploads the zip. Only your organization can install it. |
| Catalog package | **Catalog** | The installation's administrator uploads it and grants it to organizations. You do not upload anything. |

Both kinds wait under **Available to install** until someone installs them.

## Install a package

<Steps>
<Step>
### Upload the zip

On **Extensions**, press **Upload package** and choose the zip file, at most 10 MB. Opero checks the package and runs its contract tests before anything is stored.

![The upload dialog after the check: ready to upload, every contract test passed](/docs/_assets/extensions/install/upload-checked.webp)

**Ready to upload** means the package is valid. When the check finds problems, each is listed with its file and code; fix them in the package and choose the file again.
</Step>
<Step>
### Review it

Press **Upload and review**. The package is stored and its review opens at once: the install review for a new package, or the upgrade review when an earlier version is installed. The review shows everything the package will do before anything changes; see [The install review](#the-install-review).

![The install review: the verdict, what it adds, what it can reach and what to do after installing](/docs/_assets/extensions/install/review-dialog.webp)

If you close the review, or the package comes from the catalog, it waits under **Available to install**. Each card says what the package adds and what it reaches, and **Details** opens the author's [listing](/docs/en/extensions/reference/listing). Press **Review and install** on the card to open the review again.

![Packages available to install, each with what it adds and what it reaches](/docs/_assets/extensions/install/available-cards.webp)
</Step>
<Step>
### Install

Press **Install**. The extension's page opens with the notice that it is installed.
</Step>
<Step>
### Finish setting up

**Finish setting up** lists what is left before the extension can run, usually its settings and its connection. Each step has a button that opens the right place.

![The setup checklist after install: the connection is still to do](/docs/_assets/extensions/install/setup-checklist.webp)

Continue with [Run an installed extension](/docs/en/extensions/after-install#configuration).
</Step>
</Steps>

Authors can also upload and install from the command line with `opero-ext push` and `opero-ext install`; see [Command-line tool](/docs/en/extensions/reference/cli#consent).

## The install review

The review is the same dialog for an install, an [upgrade](/docs/en/extensions/upgrade-and-uninstall) and a retry after a command stopped part-way. Nothing changes until you confirm.

| Part | What it tells you |
| --- | --- |
| The verdict | A banner at the top, shown only when something needs your attention: the number of problems to fix first, the owner-only notice, or **Ready to install** when the package takes over things you already have. Warnings that do not block are folded under **N non-blocking warnings**. |
| **What it adds** | Everything the package installs, grouped by kind: rules and rule steps, template filters, objects, saved queries, blocks, forms, lists, pages and the connection. Everything listed is managed by the extension. |
| **What it can reach** | The hosts its rules may call outside Opero, its access to your organization's data, and scripts it runs on pages. Each comes with the author's reason. |
| **Adds blocks for your pages** | Each block, with the script it runs in members' browsers, if any (**Show script**). |
| **Adds permissions for company roles** | The package permissions members need to use what it offers. Installing grants them to no one. |
| **What members can use** | Each block button, record command and link, with the permission it needs. |
| **Links to other sites** | For each record link, what it sends from members' browsers and to which host. |
| **Screens members will see** | Its forms, lists and pages. Pages are visible to every member of every company until you narrow them. |
| **Runs on its own** | Its schedules: how often each runs, for whom, and what it runs. |
| **Member accounts** | What members are asked for when they connect their own account, and what is stored. Installing connects no member. |
| **After you install** | What you still have to do: set up the connection, add pages to a menu, give permissions to company roles. |
| **Needed to install** | Shown when something is missing: each permission marked **You have it** or **Missing**, each module **Module available** or **Not available here**. |

A part appears only when the package has something for it.

### Access to data

A package can ask to read and change its own records, run its queries, change contractors, send email and notifications, or generate documents. Each scope is shown with a fixed sentence and the author's reason.

![Data scopes a package asks for, each with the author's reason](/docs/_assets/extensions/install/review-data-access.webp)

Any rule that uses the package's steps can then do this in the company it runs in, without its author's own permissions.

<Callout type="warn" title="Only an organization owner can grant data access">
For a package with data scopes, the verdict reads **Only an organization owner can install this extension.** for anyone else, and the install stays off. The same applies to its upgrades and retries.
</Callout>

### What your consent covers

Installing agrees to the hosts, the data scopes, the triggers, the schedules, the member connection and the screens the review shows. A later version that adds any of these, or widens them, is shown as **New in this version** and has to be agreed to again.

### When the review changes

If something changes while the dialog is open, for example a rule starts using a step, confirming shows "The plan changed since it was shown. Review the updated plan and confirm again." with the new review.

| You see | What to do |
| --- | --- |
| **N problems to fix first** | Read each problem. Most need a change in your organization first, or a new version of the package. |
| **Needed to install** with **Missing** | Ask an administrator who holds the permission, or enable the module. |
| A warning that two keys overlap | Another installed extension has a key that overlaps this one. Install only one of them, or ask the author for a different key. |
| **Ready to install**, saying it takes over things you already have | The package installs something under a name you already use. Read the warnings, then confirm. |

The codes behind each problem are listed in [Error codes](/docs/en/extensions/error-codes#in-the-install-review).
