---
title: "Part 3: Check and pack"
description: "Validate the Hello extension, read a problem report, pack the zip and run its tests on an Opero server before you upload it."
---

In this part you check the finished folder and pack it. At the end you have `hello-ext-0.1.0.zip`, and you know its tests pass on Opero.

<Steps>
<Step>
### Validate the folder

Run the check from inside the package folder.

```bash title="Terminal"
opero-ext validate .
```

```txt title="Output"
hello-ext 0.1.0 is valid.
```
</Step>

<Step>
### Read a problem report

When something is wrong, every problem in every file is listed with its code, file, line and place. This is the report for a misspelt `label` in the hello action and the host `api.httpbin.org` in the greet rule:

```txt title="Output"
  action.invalid  actions/hello/action.yaml:1
    actions/hello/action.yaml must have required property 'label'
  action.invalid  actions/hello/action.yaml:2 #/lable
    "lable" is not a key actions/hello/action.yaml knows.
  rule.host_not_declared  actions/greet/rule.yaml:9 #/steps/0/config/url
    Host "api.httpbin.org" is not listed in permissions.network.

3 problems found.
The package is not valid.
```

[Error codes](/docs/en/extensions/error-codes) explains each code and how to fix it.
</Step>

<Step>
### Pack it

`pack` checks the folder again and writes the zip next to it. The same folder always gives the same zip, byte for byte; `--out` chooses the file name.

```bash title="Terminal"
opero-ext pack .
```

```txt title="Output"
Wrote …/hello-ext-0.1.0.zip (5710 bytes; listing images 1325 bytes)
```

The zip holds the fifteen files `extension.yaml` reaches and the three files of the [listing](/docs/en/extensions/reference/listing), nothing else. `listing images` is the size of the icon and any screenshots.
</Step>

<Step>
### Run the tests on Opero

This step is optional: the upload runs the same tests. Sign in once, then run every case on the server without storing anything.

```bash title="Terminal"
opero-ext login --server https://opero.example.com/mcp
opero-ext test . --server https://opero.example.com/mcp
```

```txt title="Output"
Result  Part    Test                          Name
PASS    hello   actions/hello/tests.yaml#/0   a name gets a greeting
PASS    verify  actions/verify/tests.yaml#/0  a valid token is accepted
PASS    verify  actions/verify/tests.yaml#/1  a refused token fails
PASS    greet   actions/greet/tests.yaml#/0   the greeting is sent
PASS    greet   actions/greet/tests.yaml#/1   a 429 is reported as rate limited

5 of 5 tests passed.
```

Add `--org <organizationId>` when you belong to more than one organization. `test` needs the **Extension authoring** module and stops with exit 4 without it.
</Step>
</Steps>

<Callout type="idea" title="The quickest loop">
Run `validate` after every edit, `test` when the files are valid, and upload when the tests pass.
</Callout>
