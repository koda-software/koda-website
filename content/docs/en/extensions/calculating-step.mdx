---
title: A step that only calculates
description: "Build a small Opero extension with a Margin rule step written as a script, with no connection and no network access."
---

A step does not have to call anything. This package adds a **Margin** step (`x-calc-ext.margin`) that takes a price and a cost and returns the margin and its percentage. It has no connection and no network access, so it runs as soon as it is installed.

<Steps>
<Step>
### Scaffold

Start from the scaffold, add the action, and delete the example `actions/hello` folder. `init` also writes the listing and the files for your editor, as in the [tutorial](/docs/en/extensions/tutorial/start-the-package).

```bash title="Terminal"
opero-ext init calc-ext --name Calc
cd calc-ext
opero-ext add action margin
```
</Step>

<Step>
### Write the manifest

Replace `extension.yaml`, which no longer lists `actions/hello`:

```yaml title="extension.yaml"
# The package's contents: every feature it installs is listed here.
manifestVersion: 2
extension: calc-ext
version: 0.1.0
name: Calc
description: Calculation steps for rules.
publisher: Your company
requires:
  modules: [rules]

actions:
  - actions/margin
```
</Step>

<Step>
### Describe the action

The input fields become the step's form; `help` opens from a question mark next to the label.

```yaml title="actions/margin/action.yaml"
action: margin
label: Margin
description: Computes the margin and the margin percentage of a price and a cost.

input:
  price: { type: text, label: Price, help: "A decimal number, written as text.", required: true }
  cost: { type: text, label: Cost, required: true }
output:
  margin: { type: number, label: Margin }
  marginPercent: { type: number, label: Margin (%) }

run: run.js
tests: tests.yaml

expose:
  ruleStep: { category: data }
```

<Callout type="warn" title="Declare inputs as text">
The values a rule gives a step are checked against its input fields when the rule is saved, so a field typed `number` accepts only a fixed number, not `{{ record.price }}`. Type the inputs as `text` and convert them in the script.
</Callout>
</Step>

<Step>
### Write the script

Throwing an error fails the step.

```js title="actions/margin/run.js"
/** @type {import('../../.opero/types').Action<'margin'>} */
const run = ({ input }) => {
  const price = Number(input.price);
  const cost = Number(input.cost);
  if (!Number.isFinite(price) || !Number.isFinite(cost) || price <= 0) {
    throw new Error('The price and the cost are numbers, and the price is above zero.'); // [!code highlight]
  }
  const margin = Math.round((price - cost) * 100) / 100;
  return {
    margin,
    marginPercent: Math.round((margin / price) * 10000) / 100,
  };
};
export default run;
```
</Step>

<Step>
### Test it

The first case compares the exact result; the second proves that bad input fails.

```yaml title="actions/margin/tests.yaml"
- name: a price of 200 and a cost of 150 give 25 percent
  input: { price: "200", cost: "150" }
  returns: { margin: 50, marginPercent: 25 }

- name: text that is not a number fails the step
  input: { price: abc, cost: "150" }
  fails: true
```
</Step>

<Step>
### Validate and pack

```bash title="Terminal"
opero-ext validate .
opero-ext pack .
```

</Step>
</Steps>

## After install

[Install the zip](/docs/en/extensions/install) as usual. There is nothing to set up: no settings and no connection, so the extension is **Running** at once. The step is listed under **Data** in the rule builder, because it declares `category: data`.

In a rule, the step saves its result as `margin`, so later steps read `{{ margin.marginPercent }}`:

```json title="A step in one of the organization's rules"
{
  "type": "x-calc-ext.margin",
  "contextKey": "margin",
  "config": { "price": "{{ trigger.data.price }}", "cost": "{{ trigger.data.cost }}" }
}
```

## When a step is too much

If the calculation converts a single value, a [template filter](/docs/en/extensions/reference/filters) is lighter than a step. If only one rule needs it, a **Run script** step written directly in that rule needs no extension at all.
