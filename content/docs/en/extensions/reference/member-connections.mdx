title: Member connections

A member connection lets each member of the organization connect their own account at the outside service, by OAuth. The package's actions then call the service with that member's token, for that member only, typically from a [schedule](/docs/en/extensions/reference/schedules) that reads each member's new data and [raises events](/docs/en/extensions/reference/raising-events). The guide [Data from each member's account](/docs/en/extensions/member-accounts) builds one.

```yaml title="connection/member.yaml"
label: Sandbox account
description: Sends your sandbox activities to your company's rules.
oauth:
  authorize: https://auth.example.com/oauth2/authorize
  token: https://api.example.com/oauth2/token
  scopes: [activities.read]
  clientAuth: basic
  pkce: false
  client: { id: clientId, secret: clientSecret }
config:
  companyId: { type: company, label: Company receiving your data, required: true }
data:
  - Activities
afterConnect:
  action: register_member
  output:
    sandboxUserId: meta
    signingKey: secret
  failures:
    "403":
      name: consents_missing
      message: Accept every data consent in the sandbox, then connect again.
    "409": already_registered
beforeDisconnect:
  action: deregister_member
```

It belongs to the package's [connection](/docs/en/extensions/reference/connection-and-secrets): `connection.yaml` names it with `member: member.yaml`, the only accepted value, and the organization's administrator enters the OAuth client there. A package has at most one member connection.

## OAuth

Members connect with the OAuth authorization code flow; no other kind of member sign-in is supported.

| Rule | Detail |
| --- | --- |
| Both addresses are written out | No template, port or user name, and both hosts are in `permissions.network`, so the administrator sees them before installing. |
| The client is the organization's | `client` names two credential fields of one connection method. The administrator enters them on the connection form. |
| Register Opero at the provider | The OAuth client must accept the Opero installation's callback address for member connections. Ask the installation's administrator for it. |
| What is stored | The access token, the refresh token and the expiry, when the provider sends them, encrypted. Nothing can read them back. |
| No token refresh | Opero does not renew an access token. When the provider stops accepting it, the member connects again; see [A refused token](#a-refused-token). |

## The member's form

`config` is a [field list](/docs/en/extensions/reference/actions#field-lists) without secrets: the form each member fills in for their connection. Its values reach the actions as `config`.

One field may be of type `company`, at the top of the list. The member picks one of their own companies, and it becomes the company of that member's runs: the schedule's runs and the hooks run in it, data steps work in it, and the events they raise go to it. The `company` type is accepted only here.

## Connecting: afterConnect

When a member has agreed at the provider and Opero has their token, Opero runs the `afterConnect` action. Use it to register the member at the service and keep what later runs need, such as the service's id for that member.

```yaml title="actions/register-member/rule.yaml"
entryStepId: register
steps:
  - id: register
    type: CALL_WEBHOOK
    name: Register
    contextKey: registered
    config:
      method: POST
      url: https://api.example.com/v1/users
      headers: { Authorization: "Bearer {{ userConnection.accessToken }}" }
      body: { memberId: "{{ trigger.data.credentialId }}" }
  - id: keep
    type: SAVE_TO_CONTEXT
    name: Keep the ids
    contextKey: output
    config:
      value:
        sandboxUserId: "{{ registered.body.id }}"
        signingKey: "{{ registered.body.signingKey }}"
edges:
  - { fromStepId: register, toStepId: keep }
```

The action's input:

| Field | Value |
| --- | --- |
| `credentialId` | The id of the member's connection. |
| `token.scopes`, `token.expiresAt` | What the provider granted, and until when, when it says. |
| `token.extra` | Other plain values of the provider's token answer, such as its user id. Values whose name contains `token`, `secret`, `password` or `key` are left out. |
| `config` | The member's form. |

The access token is never part of the input: the rule sends it with `{{ userConnection.accessToken }}`.

`output` says how each output field of the action is stored with the connection. Output fields it does not name are not stored.

| `output` | Stored | Read as |
| --- | --- | --- |
| `<field>: secret` | Encrypted, never shown or read back. | `{{ userConnection.<field> }}` in later member actions. |
| `<field>: meta` | As public information about the connection, shown to the member. | `subject.meta` in each scheduled run, `meta` in `beforeDisconnect`. |

## Failures

When `afterConnect` fails, the connect fails and nothing is stored. `failures` maps the HTTP status of the failed request, written in quotes and `4xx` or `5xx`, to a name:

| Written | The failure's code | The member sees |
| --- | --- | --- |
| `"409": already_registered` | `x-<key>.member.already_registered` | Opero's general message that the connection failed. |
| `"403": { name: consents_missing, message: … }` | `x-<key>.member.consents_missing` | That message, translated. One name has one message. |
| A status `failures` does not list | Opero's general connect failure | The general message. The provider's answer is never shown. |

To treat a status as success instead, such as `409` for a member who is already registered, connect the webhook step's error port (`branchKey: error`), check `{{ error.httpStatus }}` there, and finish the action from that branch.

## Disconnecting: beforeDisconnect

`beforeDisconnect` runs before a member's connection is removed: when the member disconnects, when they leave the organization, and for every member when the extension is uninstalled. Use it to unregister the member at the service.

Its input is `{ meta, config }`, and `{{ userConnection.<field> }}` still gives the member's values. It is best-effort: when it fails, the connection is removed anyway. During an uninstall the organization's connection is already off, so use only the member's values there.

## The member's values in rules

A rule file writes the member's secrets as `{{ userConnection.<field> }}`, with every rule of [connection secrets](/docs/en/extensions/reference/connection-and-secrets#secrets):

| Field | Value |
| --- | --- |
| `accessToken` | The member's access token. |
| `refreshToken` | The refresh token, when the provider sent one. |
| A `secret` output of `afterConnect` | That stored value. |

An action whose rule uses `{{ userConnection.<field> }}` is a **member action**. It runs only for one member, with that member's values, from the `afterConnect` or `beforeDisconnect` hook or from a schedule `forEach: userConnection`. It is never a rule step, a block action, a record command or the verify action. In a test case, give the values under `userConnection`; see [Tests](/docs/en/extensions/reference/tests#member-actions).

## A refused token

When a request that carried the member's token is answered `401` in a scheduled run, the run ends as credential revoked (`EXTENSION_ACTION_CREDENTIAL_REVOKED`). Nothing more runs for that member, and they are asked to connect again; once they do, they run within a minute.

A `401` to a request that carried only the organization's connection is an ordinary failure: the administrator's connection needs attention. A `401` while a member connects is a connect failure.

## Upgrades

| Change in a new version | What happens | Code |
| --- | --- | --- |
| An OAuth scope is added | Every connected member is asked to connect again, and nothing runs for them until they do. A warning. | `member.reconsent_required` |
| The `authorize` or `token` host changes | The same. | `member.reconsent_required` |
| `afterConnect` stores a new output | The same. | `member.reconsent_required` |
| A scope is dropped, or a path or `clientAuth` changes | Members stay connected. | |

What the administrator and the members see is in [Upgrade and uninstall](/docs/en/extensions/upgrade-and-uninstall#what-a-new-version-can-change) and [What members do](/docs/en/extensions/member-accounts#what-members-do).

## Translations

The texts go under `member`: `label`, `description`, each `data` text by its position (`member.data."0"`), `failures.<name>` and `config.<field>`. See [Translations](/docs/en/extensions/reference/translations#translatable-keys).

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `member.invalid` | An unknown key, a missing `label`, `oauth` or `afterConnect`, an address not written out in full, a hook action exposed as a rule step, an `output` field the action does not return, two company fields, or one failure name with two messages. | Fix the key the message names. |
| `member.host_not_listed` | The `authorize` or `token` host is not in `permissions.network`. | Add both hosts with a reason. |
| `member.client_field_unknown` | `oauth.client` does not name two credential fields of one connection method. | Name the method's id and secret fields. |
| `member.action_unknown` | A hook names no action of the package. | Fix the name, or add the action. |
| `member.requires_connection` | `connection/member.yaml` in a package whose `extension.yaml` has no `connection`. | Add `connection: connection` and its `connection.yaml`. |
| `layout.unlisted_feature` | `connection/member.yaml` that `connection.yaml` does not name. | Add `member: member.yaml`. |
| `field.invalid` | A `company` field outside the member's form, or a field of the wrong shape. | Keep `company` fields in `config`. |
| `action.member_outside_member_run` | A member action exposed as a step, a block action or a record command, used as the verify action, or run by a schedule that is not over members. | Run it only from a hook or a `forEach: userConnection` schedule. |
| `rule.connection_unsupported` | `{{ userConnection.<field> }}` in a package without a member connection. | Add `connection/member.yaml`, or use `connection.*`. |
| `connection.placeholder_position`, `connection.placeholder_not_bare`, `connection.unknown_field` | A member value used outside the places a secret may stand, with a filter, or naming no member value. | See [Connection and secrets](/docs/en/extensions/reference/connection-and-secrets#problems). |
| `file.yaml_feature_not_allowed` | A status in `failures` written without quotes. | Write `"403":`. |
