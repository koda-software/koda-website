---
title: The listing
description: Give an extension an icon, a long description, screenshots and a changelog for the catalog, with the files in the listing folder.
---

The listing is what administrators read about an extension before and after they install it: an icon, a long description, captioned screenshots and a changelog. It lives in the package's `listing/` folder, so it is versioned with the code and translated like every other text. Nothing about it is typed into Opero.

**Details** on a package's card under **Available to install** opens the listing. An installed extension's **Overview** shows its description and screenshots, and the upgrade review shows the changelog.

![The listing of an available package: icon, name, long description, screenshots and changelog](/docs/_assets/extensions/listing/listing-sheet.webp)

Every part is optional. A package without `listing/` shows its `name` and `description` from `extension.yaml` only.

| Path | Holds | Limit |
| --- | --- | --- |
| `listing/icon.png` | The icon. Also `icon.jpg`, `icon.jpeg` or `icon.webp`; one per package. | Square, 128 to 1024 px a side, 256 KB |
| `listing/description.md` | The long description, in English. | 50 KB |
| `listing/description.<lang>.md` | Its translation into a language listed in `locales`. | 50 KB |
| `listing/changelog.md` | What changed in each version. Not translated. | 100 KB |
| `listing/screenshots/` | The screenshots `extension.yaml` lists, and any other image the description shows. | See [Screenshots](#screenshots) |

`opero-ext init` writes `listing/description.md`, `listing/changelog.md` and a placeholder `listing/icon.png`. Replace all three before you publish.

## The icon

`listing/icon.png`, `icon.jpg`, `icon.jpeg` or `icon.webp` is shown on the catalog card and the extension's page. Without one, Opero shows a tile with the first letter of the name.

## The long description

`listing/description.md` is Markdown, shown above the screenshots. The short `description` in `extension.yaml` stays the text on the catalog card.

```md title="listing/description.md"
# Orders

Keeps your shop's orders in Opero and updates their status as they ship.

## What it adds

- An **Orders** list with live status.
- A rule step that creates a shipment.

![The orders list](screenshots/orders.png)

See the [setup guide](https://example.com/orders-setup) or [what it adds](#what-it-adds).
```

A description may hold:

- **images from the package only**, by a path relative to `listing/`: `screenshots/orders.png` is `listing/screenshots/orders.png`;
- **links** to `http`, `https`, `mailto` or a `#section` of the description; they open in a new tab;
- **Markdown, not HTML.** Code blocks and inline code are not checked, so you can show HTML as an example.

### Translations

`listing/description.<lang>.md` translates the description, for example `listing/description.pl.md`. Its language must be in `locales`, and the English `description.md` must exist. A language without its own file shows the English description.

## Screenshots

Screenshots are the one part of the listing that `extension.yaml` lists, so that they keep their order and captions.

```yaml title="extension.yaml"
listing:
  screenshots:
    - file: listing/screenshots/orders.png
      caption: Orders with live status
    - file: listing/screenshots/settings.png
      caption: Choose which stores to sync
```

A package has up to 8 screenshots, shown in the order listed. Each one:

- has a short side of at least 320 px and a long side of at most 3840 px;
- is between 1:2 (tall) and 3:1 (wide);
- is at most 1.5 MB.

A caption translates in `locales/<lang>.yaml` under `listing.screenshots`, by the file's name without its extension:

```yaml title="locales/pl.yaml"
listing:
  screenshots:
    orders: { caption: Zamówienia z bieżącym statusem }
    settings: { caption: Wybierz sklepy do synchronizacji }
```

## The changelog

`listing/changelog.md` is Markdown with one section per version, newest first:

```md title="listing/changelog.md"
## 1.2.0

- Orders can be filtered by store.

## [1.1.0] - 2026-10-02

- A rule step that creates a shipment.

## 1.0.0

- First version.
```

A section starts at a `##` heading that begins with the version, written `## 1.2.0`, `## [1.2.0]` or `## v1.2.0`, with or without a date after it. It runs to the next heading of that level. Anything else in the file is ignored: a changelog without such headings shows nothing and is not refused.

Before an upgrade, the review shows the sections after the installed version, up to the version being installed. `opero-ext plan` and `opero-ext upgrade` print them under **New since the installed version**, and `--json` returns them as `changelog`.

## Image rules

These apply to the icon, the screenshots and every image a description shows.

| Rule | Limit |
| --- | --- |
| Format | PNG, JPEG or WebP, read from the file's bytes, which must match its extension. No SVG or GIF. |
| Images in all | 16, the icon included. |
| Size of an image other than the icon | 1.5 MB, and 3840 px on the long side. |
| Size of the zip | Every image counts toward the zip's 10 MB. |

`validate` and `pack` add a note for an image that uses more than half its limit: compress it before you publish.

## Files nothing uses

Every file under `listing/` must be the icon, a description, the changelog, a listed screenshot or an image a description shows. Anything else is refused with `listing.unused_file`.

<Callout>
`README.md` and a `CHANGELOG.md` at the top of the package are yours: Opero does not show them and `pack` leaves them out. When the package has a `README.md` but no `listing/description.md`, `validate` and `pack` add a note that the README is not shown.
</Callout>

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `listing.invalid` | Two icons in one package. | Keep one `listing/icon.*`. |
| `listing.missing_file` | A screenshot or description image that is not in the package, or a translated description without the English one. | Add the file or fix the path; write `description.md` first. |
| `listing.unused_file` | A file under `listing/` that nothing uses. | Delete it, list it as a screenshot, or show it in the description. |
| `listing.unknown_locale` | A `description.<lang>.md` whose language is not in `locales`. | Add the language to `locales`, or rename the file. |
| `listing.image_invalid` | An image that is not PNG, JPEG or WebP, whose bytes do not match its extension, or a description image outside `listing/`. | Convert or rename it; keep images under `listing/`. |
| `listing.image_too_large` | The icon over 256 KB, or another image over 1.5 MB. | Compress it. |
| `listing.image_dimensions` | An icon that is not square or not 128 to 1024 px, a screenshot outside its size or ratio, or an image over 3840 px on the long side. | Resize or crop it. |
| `listing.image_external` | A description image from another site. | Put the image under `listing/` and use a relative path. |
| `listing.too_many_images` | More than 16 images, the icon included. | Show fewer. |
| `listing.description_too_large` | A description over 50 KB. | Shorten it. |
| `listing.description_html` | Raw HTML in a description. | Use Markdown. |
| `listing.link_invalid` | A description link that is not `http`, `https`, `mailto` or `#section`. | Change or remove the link. |
| `listing.changelog_too_large` | A changelog over 100 KB. | Drop the oldest versions. |
| `manifest.invalid` | A screenshot entry with an unknown key, a path outside `listing/screenshots/`, no caption, or a ninth screenshot. | Fix the entry. |
| `name.duplicate` | Two screenshots with the same name, whatever their extensions. | Rename one: the name keys its caption's translation. |
