A package decides who in the organization may use its block actions, record commands and record links by asking for its own **company permissions**. Each one becomes an ordinary company permission, `company.x-<key>.<name>`, that the organization grants in its [roles](/docs/en/opero/11-konto-i-dostep/role-i-uprawnienia) like any other.

```yaml title="extension.yaml"
permissions:
  company:
    track:
      label: Track parcels
      description: Ask the carrier where a parcel is, from its page or its card.
      reason: Each question counts against the organization's carrier quota.
    openTracking:
      label: Open tracking pages
      description: Open a parcel's tracking page at the carrier.
      reason: The link sends the parcel number to the carrier's site.
```

Each permission is named by at least one `expose.blockAction`, `expose.recordCommand` or link `permission`; one nothing names is refused with `permissions.unused_company_permission`. A name that is not declared is refused where it is used, with `action.permission_undeclared`.

## In the organization

- **Roles.** While the extension runs, the role editor lists its permissions in a group named after the package, after Opero's own groups, with your label and description in the member's language.
- **Granted by the organization.** Installing adds a package permission to no role; the organization decides who gets each one. Only a role that grants every permission holds them from the start.
- **Not for API tokens.** API tokens never receive package permissions, and block actions, record commands and links are not offered to them.
- **One of four checks.** The permission is the last of the checks a member passes to use a block action, a record command or a link: see [Who may use them](/docs/en/extensions/reference/member-actions#who-may-use-them).

## Install, disable, upgrade, uninstall

| When | What happens to the permissions |
| --- | --- |
| Install | The plan lists each permission with its label, description and reason. A version that adds one has to be agreed to again. |
| Disable | Roles keep their grants; the group leaves the role editor until the extension runs again. |
| Upgrade | A permission the new version no longer declares is removed from every role. When a role grants it, the plan warns (`permission.grants_removed`) with how many roles. |
| Uninstall | Every grant of the extension's permissions is removed. The uninstall lists how many roles grant each one. |
