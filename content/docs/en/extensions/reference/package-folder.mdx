A package is a folder with `extension.yaml` at the top and one folder per feature. Only what the manifest lists is part of the package.

| Path | Holds |
| --- | --- |
| `extension.yaml` | The identity, requirements and permissions, and the lists of everything else. Required. See [extension.yaml](/docs/en/extensions/reference/manifest). |
| `actions/<folder>/` | `action.yaml`, the file `run` names (a rule file, a script, or a rule file and the scripts its steps name), the test file or folder, and any schema files. See [Actions](/docs/en/extensions/reference/actions). |
| `filters/<folder>/` | `filter.yaml` and its script. See [Filters](/docs/en/extensions/reference/filters). |
| `objects/<folder>/` | `object.yaml`: one object of the package. See [Objects](/docs/en/extensions/reference/objects). |
| `dictionaries/<folder>/` | `dictionary.yaml`: one dictionary. See [Dictionaries](/docs/en/extensions/reference/dictionaries). |
| `queries/<folder>/` | `query.yaml` and the `.sql` file it names. See [Queries](/docs/en/extensions/reference/queries). |
| `triggers/<folder>/` | `trigger.yaml`: one rule trigger of the package, and its data schema file when it uses one. See [Triggers](/docs/en/extensions/reference/triggers). |
| `schedules/<folder>/` | `schedule.yaml`: one schedule. See [Schedules](/docs/en/extensions/reference/schedules). |
| `blocks/<folder>/` | `block.yaml`, the HTML file, the CSS and script files it names, and its render tests. See [Blocks](/docs/en/extensions/reference/blocks). |
| `links/<folder>/` | `link.yaml`: one record link. See [Record links](/docs/en/extensions/reference/record-links). |
| `forms/<folder>/` | `form.yaml` and its layout file: one form on an object of the package. See [Forms, lists and pages](/docs/en/extensions/reference/screens#formyaml). |
| `lists/<folder>/` | `list.yaml`: one Custom List. See [Forms, lists and pages](/docs/en/extensions/reference/screens#listyaml). |
| `pages/<folder>/` | `page.yaml` and its layout file: one workspace page. See [Forms, lists and pages](/docs/en/extensions/reference/screens#pageyaml). |
| `settings.yaml` | The extension's settings, when `extension.yaml` says `settings: settings.yaml`. See [Settings](/docs/en/extensions/reference/settings). |
| `connection/` | `connection.yaml`, when `extension.yaml` says `connection: connection`, and `member.yaml`, when `connection.yaml` says `member: member.yaml`. See [Connection and secrets](/docs/en/extensions/reference/connection-and-secrets) and [Member connections](/docs/en/extensions/reference/member-connections). |
| `<module>/module.yaml` | A group of features in its own folder, for a large package. See [Modules](#modules). |
| `locales/<lang>.yaml` | One translation per language listed in `locales`. See [Translations](/docs/en/extensions/reference/translations). |
| Anything else | A README, a changelog, a licence, CI files, your editor settings: ignored and not packed. |

<Callout type="warn">
A descriptor file (`action.yaml`, `filter.yaml`, `object.yaml` and so on) that no list names is refused with `layout.unlisted_feature`. List its folder, or delete it. The same goes for a `settings.yaml` that `extension.yaml` does not name, and a `connection/member.yaml` that `connection.yaml` does not name.
</Callout>

## Naming

- Every file the package uses has a lower-case path: letters, digits, `.`, `_` and `-`.
- Descriptor names are fixed. Folder names are yours and never become identifiers, so you can rename a folder without breaking anything that uses the feature.

## YAML rules

YAML is read strictly:

- one document per file, UTF-8;
- no anchors, aliases, tags, merge keys or repeated keys.

JSON is valid YAML, so a rule exported from the rule builder can be pasted as it is.

## Modules

A large package can group features into module folders. Each module folder holds a `module.yaml`:

```yaml title="billing/module.yaml"
module: billing
name: Billing
description: Invoice and payment steps.
actions:
  - actions/create-invoice
  - actions/send-invoice
filters:
  - filters/invoice-number
```

| Key | Meaning |
| --- | --- |
| `module` | The module's key. |
| `name` | Its name. |
| `description` | Optional. |
| `actions`, `filters`, `objects`, `dictionaries`, `queries`, `triggers`, `schedules`, `blocks`, `links`, `forms`, `lists`, `pages` | Its own lists, relative to the module's folder. The objects of every module folder still go into the one module `x-<key>` of the extension. |

`extension.yaml` names the module folder under `include`. Modules go one level deep only.

```yaml title="extension.yaml"
include:
  - billing
```
