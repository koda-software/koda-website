title: The package folder
description: How an extension package folder is laid out, where each part goes, and the naming and YAML rules every file of the package follows.
---

A package is a folder with `extension.yaml` at the top and one folder per part. Only what `extension.yaml` lists belongs to the package. [Part 1 of the tutorial](/docs/en/extensions/tutorial/start-the-package) builds one from scratch.

The smallest package has a manifest and one action:

<Files>
  <Folder name="hello-ext" defaultOpen>
    <File name="extension.yaml" />
    <Folder name="actions" defaultOpen>
      <Folder name="hello" defaultOpen>
        <File name="action.yaml" />
        <File name="run.js" />
        <File name="tests.yaml" />
      </Folder>
    </Folder>
  </Folder>
</Files>

```yaml title="extension.yaml"
manifestVersion: 2
extension: hello-ext
version: 0.1.0
name: Hello
description: A starter extension with a greeting.
publisher: Your company
requires:
  modules: [rules]

actions:
  - actions/hello
```

## Where each part goes

Each part lives in its own folder under its kind's folder, for example `actions/greet/`. The descriptor file in it has a fixed name.

| Path | Descriptor and other files | Reference |
| --- | --- | --- |
| `extension.yaml` | The manifest: identity, requirements, permissions and the list of every part. Required. | [extension.yaml](/docs/en/extensions/reference/manifest) |
| `actions/<folder>/` | `action.yaml`, the rule file or script `run` names, the tests, schema files. | [Actions](/docs/en/extensions/reference/actions) |
| `filters/<folder>/` | `filter.yaml` and its script. | [Template filters](/docs/en/extensions/reference/filters) |
| `objects/<folder>/` | `object.yaml`. | [Objects](/docs/en/extensions/reference/objects) |
| `dictionaries/<folder>/` | `dictionary.yaml`. | [Dictionaries](/docs/en/extensions/reference/dictionaries) |
| `queries/<folder>/` | `query.yaml` and its `.sql` file. | [Queries](/docs/en/extensions/reference/queries) |
| `triggers/<folder>/` | `trigger.yaml`, and a data schema file when it uses one. | [Triggers](/docs/en/extensions/reference/triggers) |
| `schedules/<folder>/` | `schedule.yaml`. | [Schedules](/docs/en/extensions/reference/schedules) |
| `blocks/<folder>/` | `block.yaml`, its HTML, CSS and script files, and its render tests. | [Blocks](/docs/en/extensions/reference/blocks) |
| `links/<folder>/` | `link.yaml`. | [Record links](/docs/en/extensions/reference/record-links) |
| `forms/<folder>/` | `form.yaml` and its layout file. | [Forms, lists and pages](/docs/en/extensions/reference/screens#formyaml) |
| `lists/<folder>/` | `list.yaml`. | [Forms, lists and pages](/docs/en/extensions/reference/screens#listyaml) |
| `pages/<folder>/` | `page.yaml` and its layout file. | [Forms, lists and pages](/docs/en/extensions/reference/screens#pageyaml) |
| `settings.yaml` | The extension's settings, when `extension.yaml` says `settings: settings.yaml`. | [Settings](/docs/en/extensions/reference/settings) |
| `connection/` | `connection.yaml`, when `extension.yaml` says `connection: connection`, and `member.yaml`, when `connection.yaml` names it. | [Connection and secrets](/docs/en/extensions/reference/connection-and-secrets), [Member connections](/docs/en/extensions/reference/member-connections) |
| `<module>/` | `module.yaml` and its own part folders. | [Modules](#modules) |
| `locales/` | One `<lang>.yaml` per language in `locales`. | [Translations](/docs/en/extensions/reference/translations) |
| `listing/` | The icon, long description, screenshots and changelog. All optional. | [The listing](/docs/en/extensions/reference/listing) |

## Files Opero ignores

Anything else in the folder is yours: a `README.md`, a root `CHANGELOG.md`, a licence, CI files, editor settings and the generated `.opero/` folder. `opero-ext pack` leaves them out, and Opero never reads them.

<Callout type="warn">
A descriptor file that no list names is refused with `layout.unlisted_feature`, wherever it is, except under a folder whose name starts with a dot (such as `.github/`). The same goes for a `settings.yaml` that `extension.yaml` does not name, and a `connection/member.yaml` that `connection.yaml` does not name.
</Callout>

## Naming

Every path the package uses is lower case: letters, digits, `.`, `_` and `-`, each part starting with a letter or a digit.

- A list entry is `<kind folder>/<folder>`, such as `actions/greet`, never deeper.
- Folder names are yours. They never become identifiers: the name an action, filter or object gets comes from its descriptor. You can rename a folder without breaking what uses the part.
- A file a descriptor names (`run`, `script`, a schema file) is a path relative to the part's folder, and stays inside it.

## YAML rules

Every YAML file is read strictly, as YAML 1.2.

- One document per file, in UTF-8, not empty.
- No anchors, aliases, tags, merge keys or repeated keys.
- `yes`, `no`, `on` and `off` are texts. Write `true` and `false` for booleans.

JSON is valid YAML, so a rule exported from the rule builder can be pasted as it is.

## Modules

A large package can group parts into module folders. `extension.yaml` names each module folder under `include`, and the folder holds a `module.yaml` that lists its own parts:

```yaml title="extension.yaml"
include:
  - billing
```

```yaml title="billing/module.yaml"
module: billing
name: Billing
description: Invoice steps.
actions:
  - actions/create-invoice
```

- Modules go one level deep: a `module.yaml` cannot `include` another.
- A module folder's name is lower-case letters, digits and `-`, and cannot be the name of a part folder (`actions`, `objects`, …), `connection` or `locales`.
- The objects of every module still go into the extension's one module `x-<key>`.

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `manifest.missing` | No `extension.yaml` at the top of the folder or zip. | Pack the folder that holds it. |
| `layout.invalid_path` | A list entry that is not `<kind folder>/<folder>`, or a file name that leaves the part's folder or breaks the naming rule. | Use the form shown; keep files in the part's folder. |
| `layout.missing_descriptor` | A listed folder without its descriptor, or `settings: settings.yaml` without the file. | Add the file, or fix the entry. |
| `layout.unlisted_feature` | A descriptor, `settings.yaml` or `connection/member.yaml` that nothing names. | List or name it, or delete it. |
| `manifest.missing_file` | A descriptor names a file that is not in the package. | Add the file, or fix the name. |
| `include.invalid` | An `include` entry with a wrong name, a reserved name, or no `module.yaml`. | Fix the folder name, or add its `module.yaml`. |
| `include.nested` | A `module.yaml` with `include`. | Include every module from `extension.yaml`. |
| `name.duplicate` | Two parts of one kind with the same name, two modules with the same `module`, or two forms with the same name on one object. | Rename one. |
| `file.invalid_yaml` | The file is not YAML, is empty, is not UTF-8, or has the wrong shape at the top. | Fix the line given; quote a text that contains `: `. |
| `file.yaml_feature_not_allowed` | An anchor, alias, tag, merge key or a second document. | Write the values out. |
| `archive.invalid_path` | A file the package uses has upper-case letters, spaces or other characters outside the naming rule. | Rename it. |
| `archive.invalid` | The upload is not a zip that can be read. | Pack the folder with `opero-ext pack`. |
| `archive.unsafe_path` | A zip entry that leaves the folder, a link, or the same path twice. | Pack the folder with `opero-ext pack`. |
| `archive.too_large`, `archive.too_many_entries`, `archive.entry_too_large` | The zip, a file in it, or their number is over a [limit](/docs/en/extensions/reference/limits). | Remove files the package does not use, or make them smaller. |
