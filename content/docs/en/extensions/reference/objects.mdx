An object is a table of records the extension brings with it, such as orders or shipments. At install, Opero creates a real table for each object, in one module named after the extension, `x-<key>`; the package's rules reach the records through [data steps](/docs/en/extensions/reference/data-steps). The guide [A package with its own data](/docs/en/extensions/own-data) builds two.

```yaml title="objects/orders/object.yaml"
object: orders
name: Order
namePlural: Orders
icon: package
fields:
  - { key: number, name: Number, type: TEXT, isIndexed: true }
  - key: status
    name: Status
    type: SELECT
    options: { dictionary: status }
  - { key: ordered_on, name: Ordered on, type: DATE }
  - key: last_note
    name: Last note
    type: REFERENCE
    options: { toObject: order-notes }
```

Each object has its own folder in `objects/`, listed under `objects` in `extension.yaml`, and a package with objects lists `objects` in `requires.modules`.

`opero-ext validate` checks that the type is written in upper case. Whether the type exists, its options are right and its module is available is checked in the install review.

## References inside the package

A field points at a dictionary or another object of the same package by its name, never by an id. Opero writes the installed ids in their place.

| Option | On a field of type | Names |
| --- | --- | --- |
| `dictionary: <name>` | `SELECT`, `MULTI_SELECT` | A [dictionary](/docs/en/extensions/reference/dictionaries) of the package. |
| `toObject: <object>` | `REFERENCE`, `SUBORDINATE_OBJECT_REFERENCE` | An object of the package, by its `object` key. Two objects may point at each other, and an object at itself. |

A field may not write `dictionaryId`, `toObjectId`, `toObjectClientId`, `toModuleKey` or `toObjectKey`: a package cannot point at the organization's own dictionaries or objects.

## No form comes with an object

Installing an object creates its table and fields only, with no form, list, page or menu entry, so `createDefaultForm` is refused. Ship the screens as [forms, lists and pages](/docs/en/extensions/reference/screens).

## The module

All of a package's objects live in the module `x-<key>`. The organization cannot create a module whose key starts with `x-`, so the module can only be this extension's. The object's shape is managed by the extension, and its records stay the organization's; see [Managed assets](/docs/en/extensions/after-install#managed-assets).

## Upgrades

| Change in a new version | What happens | Code |
| --- | --- | --- |
| An object or a field is added | It is created. | |
| A field or an object is dropped | Its values or records are deleted, once the administrator confirms the loss. | |
| A field changes so that its stored values must be cleared | The same. | |
| The install takes over an object a previous uninstall kept | The object becomes the extension's again. A warning. | `object.adopts_existing` |

An uninstall keeps the objects and their records by default, as the organization's own. What the administrator sees is in [When an upgrade deletes data](/docs/en/extensions/upgrade-and-uninstall#when-an-upgrade-deletes-data) and [Keep or delete the data](/docs/en/extensions/upgrade-and-uninstall#keep-or-delete-the-data).

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `object.invalid` | An unknown key, a key or field of the wrong shape, `createDefaultForm`, an option that names an id or another module, `dictionary` on a field that is not a select, `toObject` on a field that is not a reference, or more than 50 objects. | Fix the key the message names. |
| `object.unknown_reference` | `dictionary` or `toObject` names nothing in the package. | Fix the name, or add the dictionary or object. |
| `name.duplicate` | Two objects with the same `object` key. | Rename one. |
| `requires.module_undeclared` | The package has objects but `requires.modules` lacks `objects`. | Add `objects`. |
| `object.save_validation` | In the install review: the object or a field would not save, for example an unknown field type or wrong options. Blocks the install. | Fix the field as the message says. |
