---
title: Template filters
description: Add a template filter that every template of the organization can use, with filter.yaml and a small function that formats or converts a value.
---

A template filter is a small function that formats or converts one value. After install, every template of the organization can use it. [Part 2 of the tutorial](/docs/en/extensions/tutorial/call-a-service) adds one.

```yaml title="filters/shout/filter.yaml"
filter: shout
description: Upper-cases a text and adds an exclamation mark.
script: filter.js
```

```js title="filters/shout/filter.js"
/** @type {import('../../.opero/types').Filter} */
const filter = (value) => String(value ?? '').toUpperCase() + '!';
export default filter;
```

```txt title="Template"
{{ "hi" | x_hello_ext_shout }}
```

```txt title="Result"
HI!
```

## The name in templates

A filter is installed as `x_<key>_<filter>`, with the key's hyphens as underscores: `shout` of `hello-ext` is `x_hello_ext_shout`. The [glossary](/docs/en/extensions/reference/glossary#names-after-install) lists the names of everything an extension installs.

## The function

The function receives the value piped into it, the filter's arguments as an array, and the template's context. It returns the filtered value at once.

```js title="filters/trackingurl/filter.js"
/** @type {import('../../.opero/types').Filter} */
const filter = (value, args) => {
  const carrier = String(args[0] ?? 'dhl');
  const number = encodeURIComponent(String(value ?? ''));
  return 'https://track.example.com/' + carrier + '/' + number;
};
export default filter;
```

Arguments follow a colon in the template, separated by commas:

```txt title="Template"
{{ shipment.number | x_shipping_ext_trackingurl: "ups" }}
```

<Callout type="warn" title="Filters answer at once">
A filter may not be `async` and may not wait on anything. An `async` default export is refused at upload, and a filter that calls an asynchronous helper is refused in the install review.
</Callout>

## When filters work

A filter calls nothing, so it keeps working while the extension is not running, for example while its connection is not set up. It stops when the extension is disabled.

The package's own rule files cannot use its filters: do the conversion in a script instead.

## A filter or a step?

| Use a filter when | Use a step when |
| --- | --- |
| You convert or format one value. | You call a service or combine several values. |
| The result is used inside templates. | The result feeds later steps of a rule. |
| No credential is needed. | The work needs the connection. |

## Upgrades

| Change in a new version | What happens | Code |
| --- | --- | --- |
| A filter that rules of the organization use is removed | The upgrade is blocked until those rules stop using it. | `filter.in_use` |
| A filter no rule uses is removed | A warning: templates are not checked, and one that still uses the filter fails on it. | `filter.in_use` |

What the administrator sees is in [Upgrade and uninstall](/docs/en/extensions/upgrade-and-uninstall#what-a-new-version-can-change).

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `filter.invalid` | An unknown key, or a name with `_`, upper-case letters or over 41 characters. | Use lower-case letters and digits. |
| `filter.script_invalid` | `script` does not name a `.js` or `.ts` file. | Name the filter's script module. |
| `script.invalid` | The script is not a module with one `export default`, or its default export is `async`. | See [Scripts](/docs/en/extensions/reference/scripts#problems). |
| `name.duplicate` | Two filters with the same name. | Rename one. |
| `rule.own_filter_unsupported` | A rule file of the package uses one of its own filters. | Do the conversion in a script. |
| `filter.not_sync` | In the install review: the filter calls an asynchronous helper. | Make it answer at once. |
| `filter.save_validation` | In the install review: the script does not validate, or another script of the organization has its name. | Fix the script, or rename the filter. |
