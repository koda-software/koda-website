title: Block actions and record commands
description: Let members run the package's actions themselves, from a button in a block or a command on a record, with expose.blockAction and expose.recordCommand.
---

A rule step is used by the people who build rules. An action can also be offered to the organization's members, who run it themselves, as the guide [A block, a button and a link](/docs/en/extensions/blocks-and-actions) does:

| Exposure | Members run it from | Runs for |
| --- | --- | --- |
| `expose.blockAction` | A button in one of the package's [blocks](/docs/en/extensions/reference/blocks#buttons-that-run-actions). | The record the page shows, or no record on a custom page. |
| `expose.recordCommand` | The actions of a record it targets: an object of the package or a built-in record such as a contractor. | That record. |

Either way the action runs as the member who pressed it. One action may be a block action, a record command and a rule step at once.

```yaml title="actions/track-parcel/action.yaml"
action: track_parcel
label: Track parcel
description: Asks the carrier where the parcel is and returns its status.

output:
  message: { type: text, label: Message }
  status: { type: text, label: Carrier status }
  scannedAt: { type: text, label: Last scan }

run: rule.yaml
tests: tests.yaml

expose:
  blockAction: { permission: track }
  recordCommand:
    permission: track
    targets: [{ object: parcels }]
    icon: truck
    confirm: { title: Track parcel, message: Ask the carrier where this parcel is? }
    result: { message: message, details: [status, scannedAt] }
```

An action offered to members needs a `description`, and each exposure names a [package permission](/docs/en/extensions/reference/package-permissions) members must hold.

The command's form is the action's input fields; an action without input runs as soon as the member confirms. A command shows only on the records it targets, and is not on the external API or MCP. Its key, `x-<key>.<action>`, can be hidden in a workflow stage like any record action.

## The record the action runs for

The action gets the record by reference, not its values:

| Write | To get |
| --- | --- |
| `{{ trigger.record.id }}` | The record's id. |
| `{{ trigger.record.type }}` | `custom_record` for a record of an object; `contractor`, `sales_invoice`, `cost_invoice`, `budget` or `helpdesk_ticket` for a built-in record. |
| `{{ trigger.record.moduleKey }}`, `{{ trigger.record.objectKey }}` | For a record of an object: `x-<key>` and the object's key. |

A script receives the same as `record` in its argument, or `null` when the action runs without a record. To read the record's values, fetch it with [`FETCH_RECORDS`](/docs/en/extensions/reference/data-steps#fetch-records).

```yaml title="actions/track-parcel/rule.yaml"
entryStepId: ask
steps:
  - id: ask
    type: CALL_WEBHOOK
    name: Ask the carrier
    contextKey: asked
    config:
      url: "https://api.example.com/v1/parcels?reference={{ trigger.record.id }}"
      method: GET
  - id: answer
    type: RUN_SCRIPT
    name: Answer
    contextKey: output
    config:
      code: { $file: answer.js }
edges:
  - { fromStepId: ask, toStepId: answer }
```

## What the member gets back

| Run from | On success |
| --- | --- |
| A block | A `message` text in the output is shown to the member. The block receives the whole output in the event `opero:action-done`, then refreshes. |
| A record command | The `result.message` field is shown as the message, with the `result.details` fields below it, each with its output label in the member's language. |

When the action fails, the member sees its message, which never quotes what the service answered. A run that takes longer than 15 seconds is reported as still running; it is not cancelled.

## Who may use them

Each block action, record command and [record link](/docs/en/extensions/reference/record-links) is checked in this order, each time it is shown and again when it is used:

1. **The extension is running**: enabled, its settings complete, its connection switched on.
2. **It is exposed to the member's company.** After install, every block action, command and link is exposed to all companies.
3. **The member is in its audience.** After install, that is every member.
4. **The member holds its package permission**, `company.x-<key>.<name>`, through one of their roles.

The organization can narrow the companies and the audience of each one separately, and an upgrade keeps those choices. A command or a link that fails the check is not shown at all, never shown disabled. A block receives `false` in `extension_actions` for a block action the viewer may not run.

## Tests

A test case of such an action gives the record under `record`: `type`, `id`, and for `custom_record` the package object as `object`. See [Tests](/docs/en/extensions/reference/tests#a-test-case).

```yaml title="actions/track-parcel/tests.yaml"
- name: the carrier's status comes back
  record: { type: custom_record, id: rec-1, object: parcels }
  http:
    - request:
        method: GET
        url: https://api.example.com/v1/parcels?reference=rec-1
      response:
        status: 200
        body: { status: in_transit, scannedAt: "2026-11-12T08:30:00Z" }
  returns:
    message: "The carrier says: in_transit."
    status: in_transit
    scannedAt: "2026-11-12T08:30:00Z"
```

## What these actions cannot do

| An action that | Cannot be a block action or a record command | Code |
| --- | --- | --- |
| Raises events with `EMIT_EVENT` | Events come only from schedules and member connection hooks. | `event.emitted_from_step` |
| Uses `{{ userConnection.<field> }}` | Member values exist only in member runs. | `action.member_outside_member_run` |
| A schedule runs | A schedule's action is not exposed. | `schedule.action_exposed` |

A command always runs while the member waits; nothing runs in the background.

## When a member's run is refused

The screens show these to the member; the codes matter when you read the API.

| Code | When |
| --- | --- |
| `EXTENSION_INACTIVE` (409) | A block action of an extension that is not running. |
| `EXTENSION_ACTION_FORBIDDEN` (403) | The member is outside the audience, or lacks the package permission. `meta.reason` says which. |
| `block_action_unavailable` (404) | The block action is not on the member's page as it renders for them, is not exposed to their company, or the installed version no longer has it. |
| `ENTITY_ACTION_NOT_FOUND` (404) | The record command is no longer the member's to run, for example because the extension was disabled. |
| `ENTITY_ACTION_DISABLED` (409) | An `editGated` command on a record that is read-only in its stage. |
| `EXTENSION_ACTION_INPUT_INVALID` (400) | The input does not match the action's input fields. |
| `EXTENSION_ACTION_RATE_LIMITED` (429) | The service answered `429`. Carries `retryAfterSeconds` when it sent one. |
| `EXTENSION_ACTION_FAILED`, `EXTENSION_ACTION_OUTPUT_INVALID` (422) | The action ran and failed, or returned an output that does not match its output fields. |
| `ENTITY_ACTION_TIMEOUT` (504) | No answer within 15 seconds. The run goes on. |

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `action.invalid` | An action exposed to members without a `description`, or an exposure key of the wrong shape. | Add a description; fix the key the message names. |
| `action.permission_undeclared` | `permission` names nothing in `permissions.company`. | Declare the permission, or fix the name. |
| `action.record_command_invalid` | A record command with no target or more than 20. | Name 1 to 20 targets. |
| `action.record_command_unknown_target` | An object target that is not an object of the package. | Fix the key, or add the object. |
| `action.record_command_unknown_field` | `result` names a field that is not an output field of the action. | Name an output field. |
| `event.emitted_from_step` | An action that raises events is exposed. | Raise events from a schedule's action. |
| `action.member_outside_member_run` | An action that uses a member's values is exposed. | Run it from a member connection hook or schedule. |
| `schedule.action_exposed` | A schedule's action is exposed. | Give the schedule its own action. |
