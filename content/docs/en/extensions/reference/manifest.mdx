`extension.yaml` is the manifest: the package's identity, what it requires, what it may access, and the list of every feature it installs.

```yaml title="extension.yaml"
manifestVersion: 2
extension: hello-ext
version: 0.1.0
name: Hello
description: A starter extension with a greeting, a call to httpbin.org and a filter.
publisher: Your company
requires:
  opero: ">=2026.1.0"
  modules: [rules]
permissions:
  network:
    - host: httpbin.org
      reason: Checks the token and sends greetings to the httpbin.org test service.

connection: connection
settings: settings.yaml

actions:
  - actions/hello
  - actions/verify
  - actions/greet
filters:
  - filters/shout

locales: [pl]
```

## Network permissions

Every host the package calls is listed with a reason. The administrator sees each host and its reason in the install plan, before anything is installed.

```yaml title="extension.yaml"
permissions:
  network:
    - host: api.example.com
      reason: Creates shipments and reads their tracking numbers.
    - host: auth.example.com
      reason: Exchanges the API key for a short-lived access token.
```

- A call to a host that is not listed is refused, both when the package is checked and when it runs.
- A host without a reason is refused with `permissions.reason_required`.
- A package with a connection lists at least one host.
- A package with a [member connection](/docs/en/extensions/reference/member-connections) lists the host members sign in at and the host Opero exchanges their sign-in at (`member.host_not_listed` otherwise).
- When an upgrade asks for new hosts, the plan marks them as new in that version.

## Data permissions

A package whose rules read or write data, run queries or send messages lists the [data scopes](/docs/en/extensions/reference/data-permissions) it uses, each with a reason:

```yaml title="extension.yaml"
permissions:
  data:
    - scope: records:read
      reason: Reads the open orders.
    - scope: records:write
      reason: Stores the status the carrier answers.
```

- A scope that is not one of the eight is refused with `permissions.invalid_scope`, one without a reason with `permissions.reason_required`, and one no rule uses with `permissions.unused_scope`.
- A package with data scopes can only be installed by an organization owner. Triggers, schedules and a member connection do not add this rule.

## Link hosts, page scripts and company permissions

Three more permissions concern what members use, not what the package's rules do:

```yaml title="extension.yaml"
permissions:
  links:
    - host: track.example.com
      reason: Opens a parcel's tracking page at the carrier.
  pageScript:
    reason: The parcel card keeps the carrier's last answer on screen while the page is open.
  company:
    track:
      label: Track parcels
      description: Ask the carrier where a parcel is, from its page or its card.
      reason: Each question counts against the organization's carrier quota.
```

| Key | Declares | Refused when unused |
| --- | --- | --- |
| `links` | The hosts the package's [record links](/docs/en/extensions/reference/record-links), and the URLs of its [forms, lists and pages](/docs/en/extensions/reference/screens#urls), open in members' browsers. Opero itself never calls them. | `permissions.unused_link_host` |
| `pageScript` | That a [block](/docs/en/extensions/reference/blocks#the-script) of the package runs a script in viewers' browsers. | `permissions.unused_page_script` |
| `company` | The [package permissions](/docs/en/extensions/reference/package-permissions) members need, by name. | `permissions.unused_company_permission` |

Each carries a reason that the install plan shows. A version that adds a link host, a company permission or the page script has to be agreed to again.

## Reserved lists

The list name `components` is reserved for a later version and refused today with `manifest.unsupported_section`.
