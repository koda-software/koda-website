---
title: extension.yaml
description: Reference for extension.yaml, the manifest of an extension package. Its identity, requirements, permissions and the lists of its parts.
---

`extension.yaml` is the manifest at the top of the package folder. It says who the extension is, what it needs, what it may reach, and which parts it installs. [Part 1 of the tutorial](/docs/en/extensions/tutorial/start-the-package) writes one.

```yaml title="extension.yaml"
manifestVersion: 2
extension: hello-ext
version: 0.1.1
name: Hello
description: A starter extension with a greeting, a call to httpbin.org and a filter.
publisher: Your company
requires:
  modules: [rules]
permissions:
  network:
    - host: httpbin.org
      reason: Checks the token and sends greetings to the httpbin.org test service.
connection: connection
settings: settings.yaml

actions:
  - actions/hello
  - actions/verify
  - actions/greet
filters:
  - filters/shout

locales: [pl]
```

Any other key is refused with `manifest.invalid`.

## Key and version

The key names the extension everywhere and never changes; the version names one upload.

- Opero adds the `x-` prefix itself, so a key may not start with it (`manifest.reserved_key`).
- Two installed extensions cannot have overlapping keys, where one is the other followed by `-` and more, such as `order` and `order-sync`. The install review refuses the second with `key.overlaps_installed`.
- A version, once uploaded, keeps its content. Upload a change under a new, higher version.

## Requirements

`requires` lists what the organization must have for the install review to go ahead.

- `requires.opero` is a minimum only, `">=<year>.<release>.<patch>"`. An older Opero refuses the install (`requires.release`).
- `requires.modules` must name `objects` when the package has objects, `queries` when it has queries, and `documents` when it uses the `documents:generate` data scope (`requires.module_undeclared`).

## Permissions

Each permission names what the package reaches and says why. The administrator reads every reason in the [install review](/docs/en/extensions/install#the-install-review) before agreeing. A missing reason is refused with `permissions.reason_required`.

```yaml title="extension.yaml"
permissions:
  network:
    - host: api.example.com
      reason: Creates shipments and reads their tracking numbers.
  data:
    - scope: records:write
      reason: Stores the status the carrier answers.
```

| Key | Type | Declares | Reference |
| --- | --- | --- | --- |
| `network` | `{ host, reason }[]` | Up to 50 exact host names the package's rules call. No wildcards, ports or paths. | [Network hosts](#network-hosts) |
| `data` | `{ scope, reason }[]` | The data scopes the package's rules use. | [Data permissions](/docs/en/extensions/reference/data-permissions) |
| `links` | `{ host, reason }[]` | Up to 20 hosts the package's record links, forms, lists and pages open in members' browsers. | [Record links](/docs/en/extensions/reference/record-links) |
| `pageScript` | `{ reason }` | That a block of the package runs a script in viewers' browsers. | [Blocks](/docs/en/extensions/reference/blocks#the-script) |
| `company` | map of `{ label, description?, reason }` | Up to 30 package permissions that members need for its block actions, record commands and links. | [Package permissions](/docs/en/extensions/reference/package-permissions) |

On an upgrade, the review marks each permission the installed version did not ask for as **New in this version**.

### Network hosts

The package may call only the hosts it lists, both when it is checked and when it runs.

- A package with a connection lists at least one host (`connection.hosts_required`).
- A package with a [member connection](/docs/en/extensions/reference/member-connections) also lists the host members sign in at and the host Opero exchanges their sign-in at.
- Each host is listed once.

### Link hosts, page scripts and company permissions

`links`, `pageScript` and `company` concern what members use, not what the package's rules do. Each one that nothing in the package uses is refused, so the review never asks for more than the package needs. The codes are on the pages in the table above.

## Part lists

Each list names part folders, written `<kind folder>/<folder>`, and each entry once.

| List | Folder form | Up to |
| --- | --- | --- |
| `actions` | `actions/<folder>` | 200 |
| `filters` | `filters/<folder>` | 200 |
| `objects` | `objects/<folder>` | 50 |
| `dictionaries` | `dictionaries/<folder>` | 50 |
| `queries` | `queries/<folder>` | 100 |
| `triggers` | `triggers/<folder>` | 50 |
| `schedules` | `schedules/<folder>` | 10 |
| `blocks` | `blocks/<folder>` | 50 |
| `links` | `links/<folder>` | 20 |
| `forms` | `forms/<folder>` | 100 |
| `lists` | `lists/<folder>` | 50 |
| `pages` | `pages/<folder>` | 50 |

A limit counts the whole package, the [modules](/docs/en/extensions/reference/package-folder#modules) included, except for `actions` and `filters`, whose limit is per list. The list name `components` is reserved for a later version.

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `manifest.invalid` | An unknown key, a value of the wrong form, a list entry written twice, or `en` in `locales`. | Check the key against the table above. |
| `manifest.unsupported_version` | `manifestVersion` is not 2, or the package is in the old `manifest.json` format. | Write an `extension.yaml` with `manifestVersion: 2`. |
| `manifest.unsupported_section` | The reserved list `components`. | Remove it. |
| `manifest.reserved_key` | `extension` starts with `x-`. | Leave the prefix out; Opero adds it. |
| `requires.invalid_release` | `requires.opero` is not a minimum such as `">=2026.22.0"`. | Write it in that form, quoted. |
| `requires.module_undeclared` | Objects, queries or the `documents:generate` scope without `objects`, `queries` or `documents` in `requires.modules`. | Add the module. |
| `permissions.reason_required` | A permission without a reason, or written as a bare host or scope. | Write `{ host, reason }`, `{ scope, reason }` or `{ reason }`. |
| `permissions.unused_scope`, `permissions.unused_link_host`, `permissions.unused_page_script`, `permissions.unused_company_permission` | A data scope, link host, `pageScript` or package permission that no part of the package uses. The administrator consents only to what the package uses. | Remove it, or add the part that uses it. |
| `manifest.unsupported_by_server` | At upload: this Opero does not install a part, or serve a data scope, that the package uses yet. | Leave the part out, or wait for an Opero that supports it. |
| `requires.release` | In the install review: this Opero is older than `requires.opero`. | Update Opero, or lower the requirement if the package really works on older releases. |
| `requires.release_unknown` | In the install review: the installation does not know its release, so `requires.opero` was not checked. Does not block. | None. |
| `requires.module` | In the install review: a module in `requires.modules` is not available in the organization. | The administrator turns the module on, or the licence adds it. |
| `key.overlaps_installed` | In the install review: an installed extension's key overlaps this one. | Choose a key that does not overlap. |
| `version.not_newer` | In the install review: an upgrade to the same or an older version. | Raise `version`. |
| `EXTENSION_VERSION_EXISTS` | At upload: this version was uploaded before with other content. | Raise `version`. |
