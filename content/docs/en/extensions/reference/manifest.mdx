`extension.yaml` is the manifest: the package's identity, what it requires, what it may access, and the list of every feature it installs.

```yaml title="extension.yaml"
manifestVersion: 2
extension: hello-ext
version: 0.1.0
name: Hello
description: A starter extension with a greeting, a call to httpbin.org and a filter.
publisher: Your company
requires:
  opero: ">=2026.1.0"
  modules: [rules]
permissions:
  network:
    - host: httpbin.org
      reason: Checks the token and sends greetings to the httpbin.org test service.

connection: connection
settings: settings.yaml

actions:
  - actions/hello
  - actions/verify
  - actions/greet
filters:
  - filters/shout

locales: [pl]
```

## Network permissions

Every host the package calls is listed with a reason. The administrator sees each host and its reason in the install plan, before anything is installed.

```yaml title="extension.yaml"
permissions:
  network:
    - host: api.example.com
      reason: Creates shipments and reads their tracking numbers.
    - host: auth.example.com
      reason: Exchanges the API key for a short-lived access token.
```

- A call to a host that is not listed is refused, both when the package is checked and when it runs.
- A host without a reason is refused with `permissions.reason_required`.
- A package with a connection lists at least one host.
- When an upgrade asks for new hosts, the plan marks them as new in that version.

## Reserved lists

The list names `objects`, `dictionaries`, `queries`, `blocks`, `components`, `triggers` and `schedules` are reserved for later versions and refused today with `manifest.unsupported_section`.
