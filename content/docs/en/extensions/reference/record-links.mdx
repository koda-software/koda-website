---
title: Record links
description: Add a record action that opens your service's page for the record, an https address built from the record's id and fields, with link.yaml.
---

A record link opens a page of the outside service for the record a member is looking at, for example a parcel's tracking page at the carrier. It appears among the record's actions and runs nothing on Opero's server: the member's browser opens an https address built from the record's id and the fields the link declares. The guide [A block, a button and a link](/docs/en/extensions/blocks-and-actions) adds one.

```yaml title="links/open-tracking/link.yaml"
link: open_tracking
label: Open tracking page
description: Opens the parcel's page at the carrier.
permission: openTracking
targets: [{ object: parcels }]
fields:
  number: { label: Parcel number }
url: "https://track.example.com/parcels/{fields.number}?ref={record.id}"
```

List the folder under `links` in `extension.yaml` or an included module's `module.yaml`. `opero-ext add link <name>` writes one to point at your own host and permission. A package has at most 20 links.

## The address

The address starts with `https://`, and its host is written out, with no placeholder, user name or password. `{record.id}` is the record's id, and `{fields.<field>}` the value of a field the link declares; both may stand in the path or the query. Each value is encoded where it stands, as one path segment or a query value, so `A/1 B` in the path becomes `A%2F1%20B`.

The host is listed in `permissions.links` of `extension.yaml`, with a reason. A link host is not a host the package calls, so it does not go in `permissions.network`.

```yaml title="extension.yaml"
permissions:
  links:
    - host: track.example.com
      reason: Opens a parcel's tracking page at the carrier.
```

A package lists up to 20 link hosts, each opened by a link or a [screen](/docs/en/extensions/reference/screens#urls).

## Links on the package's objects

With `{ object: <key> }` targets, each declared field is a field of every target object. The link appears on a record of those objects only when all of these hold; otherwise it is absent, so a member never gets an address with a value missing:

| Condition | Detail |
| --- | --- |
| The member passes the check | The extension runs, the link is exposed to the company, the member is in its audience and holds its permission. See [Who may use them](/docs/en/extensions/reference/member-actions#who-may-use-them). |
| The fields are on the member's form | Every field the link declares is on the form the member is shown. |
| The fields have values | The member can read the record, and every declared field has a text, a number or a yes/no. An empty field or a list hides the link. |

## Links on built-in records

A link may instead target one built-in type, and then takes its fields from that type's fixed set:

```yaml title="links/open-registry/link.yaml"
link: open_registry
label: Open in the registry
permission: checkCompanies
targets: [{ entity: contractor }]
fields:
  vatId: { label: VAT ID }
url: "https://registry.example.com/companies/{fields.vatId}"
```

| Type | Fields |
| --- | --- |
| `contractor` | `name`, `shortName`, `vatId`, `regon`, `krs`, `country`, `externalId.<system>` (the contractor's id in that outside system) |
| `sales_invoice` | `number`, `issueDate`, `saleDate`, `ksefNumber`, `currencyCode`, `grossAmount`, `buyerVatId` |
| `cost_invoice` | `supplierInvoiceNumber`, `issueDate`, `ksefNumber`, `currencyCode`, `grossAmount`, `supplierVatId` |
| `budget` | `number`, `name`, `periodStart`, `periodEnd`, `currencyCode` |
| `helpdesk_ticket` | `reference`, `number`, `typeKey` |

Dates are written `YYYY-MM-DD` and amounts as plain decimals, such as `1230.5`. Fields may be added to these sets later; none will be removed. Personal data such as PESEL, email addresses and phone numbers is left out on purpose.

On a built-in record the link appears when the member passes the same check, may read that record (its read permission; for a ticket, access to its desk) and every field has a value. The fields need not be on the page. For consent, the install review shows Opero's own labels for these fields; the labels you write are still required.

## Upgrades

| Change in a new version | What happens | Code |
| --- | --- | --- |
| A link host is added, or a link's address or fields change | It is shown as new in the review, for the administrator to agree to. | |

Each link is exposed and given an audience on its own, separately from the package's block actions and record commands. What the administrator sees is in [What members can use](/docs/en/extensions/after-install#what-members-can-use).

## Translations

The texts go under `links.<link>`: `label`, `description` and `fields.<field>.label`. See [Translations](/docs/en/extensions/reference/translations#translatable-keys).

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `link.invalid` | An unknown key, a key of the wrong shape, or more than 20 links. | Fix the key the message names. |
| `link.not_https` | The address does not start with `https://`. | Use an https address. |
| `link.template_invalid` | A placeholder in the host, a user name or password, or a placeholder of another form. | Write the host out; use only `{record.id}` and `{fields.<field>}`. |
| `link.host_not_declared` | The host is not in `permissions.links`. | Add it with a reason. |
| `link.field_undeclared` | `{fields.<field>}` names a field the link does not declare. | Add it under `fields`. |
| `link.unknown_target` | An object target that is not an object of the package. | Fix the key, or add the object. |
| `link.field_not_on_object` | A declared field is missing from one of the target objects. | Add the field to every target, or drop the target. |
| `link.mixed_targets` | Object targets and a built-in type together, or more than one built-in type. | Split it into two links. |
| `link.field_unknown` | At upload: a field outside the built-in type's set, or `externalId` without its `.<system>`. | Use a field from the table. |
| `action.permission_undeclared` | `permission` names nothing in `permissions.company`. | Declare the permission. |
| `permissions.unused_link_host` | A link host no link or screen opens. | Remove it. |
