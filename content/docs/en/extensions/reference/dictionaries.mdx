title: Dictionaries

A dictionary is a fixed list of values, such as statuses or priorities, that select fields offer. A package uses its own dictionaries in the fields of its [objects](/docs/en/extensions/reference/objects), as the guide [A package with its own data](/docs/en/extensions/own-data) does.

```yaml title="dictionaries/status/dictionary.yaml"
dictionary: status
name: Order status
description: Where an order is.
entries:
  - { key: open, label: Open }
  - { key: noted, label: Noted, color: "#2563EB" }
  - { key: closed, label: Closed, isActive: false }
```

Each dictionary has its own folder in `dictionaries/`, listed under `dictionaries` in `extension.yaml`.

## The installed key

A dictionary is installed as an organization dictionary with the key `x-<key>-<name>`: `status` of the extension `shop-ext` is `x-shop-ext-status`. The organization cannot create a dictionary whose key starts with `x-`.

The package's own fields name the dictionary by its name, `options: { dictionary: status }`, not by the installed key. A select field stores the entry's `key`, so a [query](/docs/en/extensions/reference/queries) compares with it: `WHERE f_status = 'open'`.

## Translations

Only the entry labels are translatable, under `dictionaries.<name>.entries.<key>.label`. The dictionary's `name` and `description` stay in English. See [Translations](/docs/en/extensions/reference/translations#translatable-keys).

## Upgrades

| Change in a new version | What happens | Code |
| --- | --- | --- |
| An entry keeps its key | It keeps its identity, and records keep their values. | |
| An entry is left out | It is removed. While custom fields of the organization name the dictionary, the install review blocks. | `dictionary.save_validation` |
| A dictionary is dropped | It is deleted, or kept as the organization's own when something still uses it. A warning. | `dictionary.released` |
| The install takes over a dictionary a previous uninstall kept | It becomes the extension's again. A warning. | `dictionary.adopts_existing` |

An uninstall keeps the dictionaries by default, as the organization's own. What the administrator sees is in [Upgrade and uninstall](/docs/en/extensions/upgrade-and-uninstall#what-a-new-version-can-change).

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `dictionary.invalid` | An unknown key, a name of the wrong form, an entry without `key` or `label`, two entries with the same key, a colour not written `#RRGGBB`, more than 1,000 entries, or more than 50 dictionaries. | Fix the key the message names. |
| `name.duplicate` | Two dictionaries with the same name. | Rename one. |
| `object.unknown_reference` | A field names a dictionary the package does not have. | Fix the name, or add the dictionary. |
| `dictionary.save_validation` | In the install review: the dictionary would not save, for example because entries would be removed while custom fields of the organization name it. Blocks the install. | Keep the entries, or ask the organization to change those fields. |
