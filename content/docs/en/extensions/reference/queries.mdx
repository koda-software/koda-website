title: Queries
description: Bring saved SQL queries over the package's own tables with query.yaml and a .sql file, and run them from SQL lists, reports, blocks and rules.
---

A query is a saved SQL query that the extension brings with it, reading or changing the records of the package's own [objects](/docs/en/extensions/reference/objects). Once installed it is a saved query of the organization: SQL lists, reports and blocks can use it, and the package's rules run it with the [`RUN_QUERY`](/docs/en/extensions/reference/data-steps#run-a-query) step.

```yaml title="queries/orders-by-day/query.yaml"
query: orders_by_day
name: Orders by day
kind: FETCH
sql: query.sql
```

```sql title="queries/orders-by-day/query.sql"
SELECT f_ordered_on AS day, count(*) AS orders
FROM {{object.orders}}
GROUP BY f_ordered_on
```

Each query has its own folder in `queries/` with its `query.yaml` and its SQL file, listed under `queries` in `extension.yaml`. A package with queries lists `queries` in `requires.modules`.

## The SQL file

The file holds one SQL statement of up to 10,000 characters, in UTF-8.

| Write | For |
| --- | --- |
| `{{object.<key>}}` | The table of one of the package's objects, by its `object` key. Opero writes the real table name in its place at install. Spaces inside the braces are allowed. |
| `f_<field key>` | The column of a field. A select field holds the entry's key. |
| `:name` | A parameter, declared under `parameters`. |

A query cannot name the tables of the organization's own objects. The SQL itself is checked in the install review, the same way as a saved query an administrator writes; a query over a table the same install creates gets the full check when it is installed. It runs on the limited database roles saved queries use, in the company it runs for.

## Parameters

```yaml title="queries/close-old-orders/query.yaml"
query: close_old_orders
name: Close old orders
kind: MUTATION
mutationOperation: UPDATE
sql: query.sql
parameters:
  - { name: before, type: date, required: true, description: Orders placed before this day are closed. }
```

```sql title="queries/close-old-orders/query.sql"
UPDATE {{object.orders}}
SET f_status = 'closed'
WHERE f_ordered_on < :before
```

## The installed key

A query is installed with the key `x_<key with _>_<name>`: `orders_by_day` of the extension `orders-ext` is `x_orders_ext_orders_by_day`. Rules and tests name it by that key. The organization cannot create or rename a saved query to a key that starts with `x_`.

A package with a MUTATION query is installed only by someone who holds `org.savedQueries.executeMutation`.

## Upgrades

| Change in a new version | What happens | Code |
| --- | --- | --- |
| A query's SQL changes | The install review shows the new SQL. | |
| A query that an active SQL list, report or block uses is dropped | The upgrade is blocked until those stop using it. | `query.in_use` |
| The install takes over a query a previous uninstall kept | It becomes the extension's again. A warning. | `query.adopts_existing` |

An uninstall deletes the queries nothing uses and keeps the others as the organization's own. What the administrator sees is in [Upgrade and uninstall](/docs/en/extensions/upgrade-and-uninstall#what-a-new-version-can-change).

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `query.invalid` | An unknown key, a missing `kind`, `mutationOperation` on a FETCH query, two parameters with the same name, an SQL file that is not `.sql`, not UTF-8, empty or over 10,000 characters, or more than 100 queries. | Fix the key or the file the message names. |
| `query.unknown_object` | `{{object.<key>}}` names no object of the package. The message gives the line in the SQL file. | Fix the key, or add the object. |
| `manifest.missing_file` | The SQL file `sql` names is not there. | Add the file, or fix the name. |
| `name.duplicate` | Two queries with the same name. | Rename one. |
| `requires.module_undeclared` | The package has queries but `requires.modules` lacks `queries`. | Add `queries`. |
| `query.save_validation` | In the install review: the SQL would not save, or `kind` is not what the SQL does. Blocks the install. | Fix the SQL or the `kind`. |
