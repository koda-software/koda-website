---
title: Actions and field lists
description: Reference for action.yaml, the folder that holds one action of an extension, and for the field lists that describe its input and output.
---

An action is one piece of logic of the package: a folder with an `action.yaml`, its logic (a [rule file](/docs/en/extensions/reference/rule-files) or a [script](/docs/en/extensions/reference/scripts)) and its [tests](/docs/en/extensions/reference/tests). Published as a rule step, it is what the organization's rule authors use. [Part 2 of the tutorial](/docs/en/extensions/tutorial/call-a-service) builds three.

```yaml title="actions/greet/action.yaml"
action: greet
label: Greet
description: Sends a greeting for a name to httpbin.org and returns its answer.

input:
  name: { type: text, label: Name, required: true }
output:
  status: { type: integer, label: HTTP status }
  body: { type: object, label: Answer, fields: {} }

run: rule.yaml
tests: tests.yaml

expose:
  ruleStep: { category: integrations }
```

<Callout type="warn" title="Extra outcome ports">
`expose.ruleStep.branches` adds ports to the step, but today only the default and error ports are ever taken.

## What runs an action

An action runs only when something runs it. Without `expose`, it is installed but rule authors do not see it.

| Run by | Declared in | Reference |
| --- | --- | --- |
| A rule of the organization, as a step | `expose.ruleStep` | This page |
| A button in a block, or a record's actions, as the member | `expose.blockAction`, `expose.recordCommand` | [Block actions and record commands](/docs/en/extensions/reference/member-actions) |
| **Test connection** on the connection | `verify` in `connection.yaml` | [Connection and secrets](/docs/en/extensions/reference/connection-and-secrets) |
| A schedule | `action` in `schedule.yaml` | [Schedules](/docs/en/extensions/reference/schedules) |
| A member connection hook | `afterConnect`, `beforeDisconnect` in `member.yaml` | [Member connections](/docs/en/extensions/reference/member-connections) |
| Another action of the package | a step `x-<key>.<action>` in its rule file | [Rule files](/docs/en/extensions/reference/rule-files#steps-a-rule-file-may-use) |

The rule behind an action is installed as `<package name>: <label>` and runs only this way. Running, testing or replaying it by hand, or calling it with **Call Rule**, is refused with `EXTENSION_MANAGED_RULE_RUN`. To try an action, use its step in a rule of the organization, or run its tests.

### Actions that are not steps

Some actions run only from inside the package, so they cannot be exposed.

| Action | May not be | Code |
| --- | --- | --- |
| One a schedule or a member connection hook runs | A rule step, block action or record command | `schedule.action_exposed`, `member.invalid` |
| One that raises events with [`EMIT_EVENT`](/docs/en/extensions/reference/raising-events) | Exposed in any way, or the verify action | `event.emitted_from_step` |
| A member action, one whose rule uses `{{ userConnection.<field> }}` | Exposed in any way, the verify action, or run by a schedule that is not over members | `action.member_outside_member_run` |
| The verify action | One that uses a data step | `action.verify_uses_data` |

<Callout title="Two meanings of “member”">
A *member action* on this page uses a member's own connection. The actions members run themselves from blocks and records are [block actions and record commands](/docs/en/extensions/reference/member-actions).
</Callout>

## Field lists

A field list maps field keys to definitions. An action's input and output, a connection's credentials, the extension's [settings](/docs/en/extensions/reference/settings), a [trigger](/docs/en/extensions/reference/triggers)'s data and filters, and a [member connection](/docs/en/extensions/reference/member-connections)'s form are all field lists.

```yaml title="actions/create-shipment/action.yaml"
input:
  order_id: { type: text, label: Order number, required: true, help: As shown on the order. }
  priority:
    type: select
    label: Priority
    options: [low, normal, { value: high, label: High priority }]
    default: normal
  lines:
    type: list
    label: Lines
    items:
      type: object
      fields:
        sku: { type: text, label: SKU }
        quantity: { type: integer, label: Quantity }
```

A field key is letters, digits and `_`, not starting with a digit, up to 63 characters.

A list nests up to five levels and holds up to 100 fields at each level. An input is closed at every level: a nested field the list does not name is refused too.

### Field types

| Type | Value |
| --- | --- |
| `text` | A text. |
| `number` | A number. |
| `integer` | A whole number. |
| `boolean` | `true` or `false`. |
| `date` | A date, such as `2026-11-12`. |
| `datetime` | An ISO 8601 date and time. |
| `select` | One of `options`. |
| `list` | A list of `items`. |
| `object` | An object with `fields`. |
| `company` | One of the member's companies. Only at the top of a [member connection](/docs/en/extensions/reference/member-connections#the-members-form)'s `config`, at most once. |

<Callout type="warn" title="Number and boolean inputs take fixed values">
The values a rule gives a step are checked against its input fields when the rule is saved, so a `number` or `boolean` input accepts only a fixed value, not a template such as `{{ record.price }}`. Declare such inputs as `text` and convert them in a script. [A step that only calculates](/docs/en/extensions/calculating-step) shows how.
</Callout>

### Schema files

A JSON Schema file in the action's folder can stand in for a field list when you need more than field lists offer:

```yaml title="actions/create-shipment/action.yaml"
input: input.schema.json
```

The file is JSON or YAML, an object schema, and written in English only: its texts are not translated, and its fields are not typed in scripts.

## When a step fails

A failed step carries one of these codes on its error port. Connect the error port to handle them in the rule.

| Code on the step | Cause | Carries |
| --- | --- | --- |
| `EXTENSION_ACTION_FAILED` | The action failed, usually because the service answered with an error. | `httpStatus`, when a call failed |
| `EXTENSION_ACTION_RATE_LIMITED` | The service answered `429`. | `httpStatus`, and `retryAfterSeconds` when the service sent it |
| `EXTENSION_ACTION_INPUT_INVALID` | The step's input did not match the input fields. | |
| `EXTENSION_ACTION_OUTPUT_INVALID` | The result did not match the output fields. | |

When a data step of the extension is refused while it runs, the extension's own rule shows `EXTENSION_SCOPE_DENIED` on its run, and your rule's step fails with `EXTENSION_ACTION_FAILED`. The message never quotes what the service sent back, because an error body could repeat a secret.

<Callout type="idea" title="Retry on rate limits">
`EXTENSION_ACTION_RATE_LIMITED` means the service is busy, not that the request was wrong. Handle it apart from other failures, and use `retryAfterSeconds` to decide when to try again.
</Callout>

## Problems

| Code | Cause | Fix |
| --- | --- | --- |
| `action.invalid` | An unknown key, a bad name or label, or an exposed action without a `description`. | Check the key against the table above. |
| `action.run_invalid` | `run` names something that is neither `.yaml`, `.js` nor `.ts`. | Name a rule file or a script. |
| `action.missing_test` | An action without a test case, or a `tests` folder with no `.yaml` file. | Write a case. |
| `action.cycle` | Actions call each other's steps in a circle. | Break the circle. |
| `action.schema_invalid` | A schema file that is not an object schema, does not compile, or uses text keys such as `x-titleKey`. | Fix the schema, or use a field list. |
| `action.verify_uses_data` | The verify action uses a data step. | Keep the verify action to calls and logic. |
| `action.member_outside_member_run` | A member action is exposed, is the verify action, or is run by a schedule that is not over members. | Run it from a member connection hook or a schedule over members. |
| `field.invalid` | A field list with an unknown type or key, a field key of the wrong form, a container without `options`, `items` or `fields`, an invalid default, or a key used where its list does not allow it. | Check the field against the table above. |
| `step.invalid` | A branch named `error`, written twice, or not a lower-case name. | Use unique branch names other than `error`. |
| `step.unknown_category` | At upload: `category` is not one of the six. | Use `data`, `logic`, `notifications`, `integrations`, `files` or `flow`. |
| `name.duplicate` | Two actions with the same name. | Rename one. |
| `EXTENSION_MANAGED_RULE_RUN` | Someone ran, tested or replayed the extension's rule directly, or called it with **Call Rule**. | Use the step in a rule. |

The codes about block actions and record commands are under [Block actions and record commands](/docs/en/extensions/reference/member-actions), and the ones about the rule file under [Rule files](/docs/en/extensions/reference/rule-files#problems).
