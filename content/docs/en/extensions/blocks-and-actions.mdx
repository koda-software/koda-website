---
title: "Recipe: a block, a button and a link"
description: "Build an Opero extension that members use on record pages: a parcel object, a block with a scripted card and a badge, an action members run from a button and as a record command, a link to the carrier's tracking page, and the package permissions that decide who may use them."
---

This recipe builds a package for **parcels** that members use on the parcel's own page. It brings:

- an object **Parcel**;
- a block **Parcel card** that shows the parcel with a **Status badge**, another block of the package, and a **Track now** button;
- an action **Track parcel** (`x-parcels.track_parcel`) that asks the carrier where the parcel is, run by that button and offered as a command on every parcel;
- a link **Open tracking page** to the parcel's page at the carrier;
- two package permissions, **Track parcels** and **Open tracking pages**, that the organization grants in its roles.

The carrier in this recipe knows each parcel by its Opero record id, which it was given when the parcel was registered.

<Steps>
<Step>
### Write the manifest

```yaml title="extension.yaml"
manifestVersion: 2
extension: parcels
version: 0.1.0
name: Parcels
description: Keeps parcels, shows them on record pages and asks the carrier where they are.
publisher: Your company
requires:
  modules: [rules, objects]
permissions:
  network:
    - host: api.example.com
      reason: Asks the carrier where a parcel is.
  links:
    - host: track.example.com
      reason: Opens a parcel's tracking page at the carrier.
  pageScript:
    reason: The parcel card keeps the carrier's last answer on screen while the page is open.
  company:
    track:
      label: Track parcels
      description: Ask the carrier where a parcel is, from its page or its card.
      reason: Each question counts against the organization's carrier quota.
    openTracking:
      label: Open tracking pages
      description: Open a parcel's tracking page at the carrier.
      reason: The link sends the parcel number to the carrier's site.

objects:
  - objects/parcels
actions:
  - actions/track-parcel
blocks:
  - blocks/parcel-card
  - blocks/status-badge
links:
  - links/open-tracking

locales: [pl]
```

Three kinds of permission sit side by side: `network` is the host the package's rules call, `links` the host members' browsers open, and `company` the [package permissions](/docs/en/extensions/reference/package-permissions) members need. `pageScript` is there because the card has a script.
</Step>

<Step>
### Add the object

```yaml title="objects/parcels/object.yaml"
object: parcels
name: Parcel
namePlural: Parcels
icon: package
fields:
  - { key: number, name: Number, type: TEXT }
  - { key: status, name: Status, type: TEXT }
```
</Step>

<Step>
### Describe the action

```yaml title="actions/track-parcel/action.yaml"
action: track_parcel
label: Track parcel
description: Asks the carrier where the parcel is and returns its status.

output:
  message: { type: text, label: Message }
  status: { type: text, label: Carrier status }
  scannedAt: { type: text, label: Last scan }

run: rule.yaml
tests: tests.yaml

expose:
  blockAction: { permission: track }
  recordCommand:
    permission: track
    targets: [{ object: parcels }]
    icon: truck
    confirm: { title: Track parcel, message: Ask the carrier where this parcel is? }
    result: { message: message, details: [status, scannedAt] }
```

The action has no input, so the command runs as soon as the member confirms. Its result shows `message`, then the carrier's status and the last scan, each labelled with its output label. See [Block actions and record commands](/docs/en/extensions/reference/member-actions).
</Step>

<Step>
### Write the rule

```yaml title="actions/track-parcel/rule.yaml"
entryStepId: ask
steps:
  - id: ask
    type: CALL_WEBHOOK
    name: Ask the carrier
    contextKey: asked
    config:
      url: "https://api.example.com/v1/parcels?reference={{ trigger.record.id }}"
      method: GET
  - id: answer
    type: RUN_SCRIPT
    name: Answer
    contextKey: output
    config:
      code: { $file: answer.js }
edges:
  - { fromStepId: ask, toStepId: answer }
```

```js title="actions/track-parcel/answer.js"
/** @type {import('../../.opero/types').StepScript<'track_parcel'>} */
export default function answer({ context }) {
  const { status, scannedAt } = context.asked.body;
  return {
    message: `The carrier says: ${status}.`,
    status: String(status),
    scannedAt: String(scannedAt),
  };
}
```

`trigger.record.id` is the record the member runs the action for, whether they pressed the card's button or the command.
</Step>

<Step>
### Test the action

```yaml title="actions/track-parcel/tests.yaml"
- name: the carrier's status comes back
  record: { type: custom_record, id: rec-1, object: parcels }
  http:
    - request:
        method: GET
        url: https://api.example.com/v1/parcels?reference=rec-1
      response:
        status: 200
        body: { status: in_transit, scannedAt: "2026-11-12T08:30:00Z" }
  returns:
    message: "The carrier says: in_transit."
    status: in_transit
    scannedAt: "2026-11-12T08:30:00Z"
- name: a parcel the carrier does not know fails
  record: { type: custom_record, id: rec-2, object: parcels }
  http:
    - request:
        method: GET
        url: https://api.example.com/v1/parcels?reference=rec-2
      response: { status: 404, body: { error: not_found } }
  fails: { status: 404 }
```

`record` is the record the case runs for.
</Step>

<Step>
### Add the card

```yaml title="blocks/parcel-card/block.yaml"
block: parcel_card
label: Parcel card
description: The parcel's number and status, with a button that asks the carrier where it is.
html: block.html
css: block.css
script: block.js
tests: tests.yaml
```

```html title="blocks/parcel-card/block.html"
<section class="parcel">
  <h3 class="parcel__number">Parcel {{ record.number }}</h3>
  {% render 'x_parcels_status_badge', status: record.status %}
  {% if extension_actions['x-parcels.track_parcel'] %}
    <button type="button" data-opero-action="run-action"
            data-action="x-parcels.track_parcel">Track now</button>
  {% endif %}
  <p class="parcel__answer" data-answer></p>
</section>
```

```css title="blocks/parcel-card/block.css"
.parcel { display: grid; gap: 8px; padding: 16px; border-radius: 8px; background: var(--muted); }
.parcel__number { margin: 0; }
.parcel__answer:empty { display: none; }
```

```js title="blocks/parcel-card/block.js"
/** @type {import('../../.opero/types').Block} */
export default function parcelCard(ctx) {
  const answer = ctx.dom.querySelector('[data-answer]');
  const last = ctx.state.get('answer');
  if (answer && typeof last === 'string') answer.textContent = last;
  ctx.dom.root.addEventListener('opero:action-done', (event) => {
    const message = event.detail?.output?.message;
    if (typeof message !== 'string' || !answer) return;
    ctx.state.set('answer', message);
    answer.textContent = message;
  });
}
```

```yaml title="blocks/parcel-card/tests.yaml"
- name: shows the button to a member who may track
  record: { type: custom_record, id: rec-1, object: parcels }
  extensionActions: { x-parcels.track_parcel: true }
  contains: ['data-action="x-parcels.track_parcel"', "Track now"]
- name: hides the button from everyone else
  record: { type: custom_record, id: rec-1, object: parcels }
  extensionActions: { x-parcels.track_parcel: false }
  notContains: ["Track now"]
```

Placed on a parcel's page, the card reads the parcel as `record` and renders the badge by its installed key, `x_parcels_status_badge`. The button appears only for members who may run the action. When the action finishes, the script writes its message under the button and keeps it there across the block's refreshes. See [Blocks](/docs/en/extensions/reference/blocks).
</Step>

<Step>
### Add the link

`opero-ext add link open_tracking` writes the folder; point it at the carrier:

```yaml title="links/open-tracking/link.yaml"
link: open_tracking
label: Open tracking page
description: Opens the parcel's page at the carrier.
permission: openTracking
targets: [{ object: parcels }]
fields:
  number: { label: Parcel number }
url: "https://track.example.com/parcels/{fields.number}?ref={record.id}"
```

The link appears on a parcel only for a member whose form shows the **Number** field and only when the parcel has a number. See [Record links](/docs/en/extensions/reference/record-links).
</Step>

## After install

An administrator installs the package as in the [tutorial](/docs/en/extensions/tutorial/install-and-use), with the permissions to create Custom Blocks and change custom HTML. Before confirming, the install plan shows the two blocks with the card's script, the action members run with the permission it needs, the link with its host `track.example.com` and its field **Parcel number**, and the two package permissions with their reasons.

Then:

- the organization grants **Track parcels** and **Open tracking pages** to the roles that should have them; until then only members whose role grants every permission see the command, the button and the link;
- it places **Parcel card** (`x_parcels_parcel_card`) on the parcels' record page, as it places its own blocks;
- a member with **Track parcels** presses **Track now** on the card, or runs **Track parcel** from the parcel's actions, and sees the carrier's answer; a member with **Open tracking pages** opens the parcel at the carrier.

Every one of these is exposed to all companies and all members after install; the organization can narrow each one to some companies or to an audience. If the extension is disabled, the card shows a notice instead of the parcel, and the command and the link disappear. If it is uninstalled, the card stays archived where it was placed and shows that the extension was removed; installing it again brings it back.
