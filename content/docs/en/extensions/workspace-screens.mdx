title: Forms, lists and pages
description: "Build an Opero extension that brings the screens members work with: forms on its own objects, Custom Lists and a workspace page."
---

An object is only useful when members can open, list and create its records. This guide builds **Shop**, a package that keeps orders and their lines and brings the screens for them: an **Order** form that shows the order's lines, a list of **Open orders**, and an **Orders** workspace page that puts a counter, the list, a block and the form together.

![The Shop workspace page: the open orders counter, the list, a summary block and the new order form](/docs/_assets/extensions/workspace-screens/shop-page.webp)

Screens refer to each other with references such as `{ $ref: "list:open-orders" }`, never by id, because ids differ in every organization. Opero replaces each reference with the installed id. See [References](/docs/en/extensions/reference/screens#references).

<Steps>
<Step>
### Write the manifest

```yaml title="extension.yaml"
manifestVersion: 2
extension: shop
version: 1.0.0
name: Shop
description: Keeps orders with their lines, and the screens to work with them.
publisher: Your company
requires:
  modules: [objects, queries]
permissions:
  links:
    - host: shop.example.test
      reason: Opens an order in the shop.

objects:
  - objects/orders
  - objects/order-lines
queries:
  - queries/open-count
blocks:
  - blocks/order-summary
forms:
  - forms/order
  - forms/line
lists:
  - lists/open-orders
  - lists/order-lines
pages:
  - pages/orders

locales: [pl]
```

The list opens orders in the shop, so its host is in `permissions.links`. `opero-ext add form`, `add list` and `add page` write a starting folder and list it here.
</Step>

<Step>
### Add the objects

```yaml title="objects/orders/object.yaml"
object: orders
name: Order
namePlural: Orders
icon: package
fields:
  - { key: title, name: Title, type: TEXT }
  - { key: status, name: Status, type: TEXT }
  - { key: external_id, name: Shop id, type: TEXT }
```

```yaml title="objects/order-lines/object.yaml"
object: order-lines
name: Order line
namePlural: Order lines
fields:
  - { key: product, name: Product, type: TEXT }
  - { key: quantity, name: Quantity, type: NUMBER }
  - key: order
    name: Order
    type: REFERENCE
    options: { toObject: orders }
```

Each line points at its order. See [Objects](/docs/en/extensions/reference/objects).
</Step>

<Step>
### Add the counter's query and the block

The page counts open orders with a query, and both the page and the form show a small block.

```yaml title="queries/open-count/query.yaml"
query: open_count
name: Open orders
kind: FETCH
sql: query.sql
```

```sql title="queries/open-count/query.sql"
SELECT count(*) AS value
FROM {{object.orders}}
WHERE f_status <> 'closed'
```

```yaml title="blocks/order-summary/block.yaml"
block: order_summary
label: Order summary
html: block.html
inputs:
  title: { type: text, label: Title, default: Order }
tests: tests.yaml
```

```html title="blocks/order-summary/block.html"
<section class="summary">
  <h3>{{ inputs.title }}</h3>
</section>
```

```yaml title="blocks/order-summary/tests.yaml"
- name: shows its title
  inputs: { title: Order A-1 }
  contains: ["Order A-1"]
```
</Step>

<Step>
### Add the order form

`form.yaml` describes the form; `layout.yaml` is its [View Layout](/docs/en/extensions/reference/screens#formyaml). `default` makes it the form an order opens in, when the object has none yet.

```yaml title="forms/order/form.yaml"
form: order
object: orders
name: Order
types: [view, edit, create]
default: [view, edit, create]
config:
  title: New order
  successMessage: Saved
layout: layout.yaml
```

```yaml title="forms/order/layout.yaml"
schemaVersion: 2
regions:
  main:
    - id: details
      kind: card
      children:
        - { id: f_title, kind: field, field: { source: dynamic, key: title } }
        - { id: f_status, kind: field, field: { source: dynamic, key: status } }
    - id: summary
      kind: component
      component: custom_block
      config:
        customBlockId: { $ref: "block:order_summary" }
        inputs: { title: "Order {{ record.title }}" }
    - id: lines
      kind: component
      component: layout.customList
      config:
        customListId: { $ref: "list:order-lines" }
        params: { order: "{{ record.id }}" }
```

The last component embeds the lines list and passes it the order's id as the parameter `order`.
</Step>

<Step>
### Add the line form

```yaml title="forms/line/form.yaml"
form: line
object: order-lines
name: Order line
types: [create, edit]
layout: layout.yaml
```

```yaml title="forms/line/layout.yaml"
schemaVersion: 2
regions:
  main:
    - id: line
      kind: card
      children:
        - { id: f_order, kind: field, field: { source: dynamic, key: order } }
        - { id: f_product, kind: field, field: { source: dynamic, key: product } }
        - { id: f_quantity, kind: field, field: { source: dynamic, key: quantity } }
```
</Step>

<Step>
### Add the lists

```yaml title="lists/open-orders/list.yaml"
list: open-orders
name: Open orders
description: Orders that are not closed yet.
source: { object: orders }
config:
  columns: [{ field: title }, { field: status }]
  baseFilter:
    op: AND
    items: [{ field: status, operator: neq, value: closed }]
  modes: [table]
  views: [{ id: default, name: Default, default: true, config: { schemaVersion: 2 } }]
  builtInActions: [create, open]
  create: { formId: { $ref: "form:orders.order" } }
actions:
  - key: open_in_shop
    type: OPEN_LINK
    label: Open in shop
    config: { url: "https://shop.example.test/orders/{{ row.external_id }}" }
```

```yaml title="lists/order-lines/list.yaml"
list: order-lines
name: Order lines
source: { object: order-lines }
config:
  columns: [{ field: product }, { field: quantity }]
  parameters: [{ key: order, label: Order, required: true }]
  baseFilter:
    op: AND
    items: [{ field: order, operator: eq, value: "{{ params.order }}" }]
  modes: [table]
  views: [{ id: default, name: Default, default: true, config: { schemaVersion: 2 } }]
  builtInActions: [create, edit]
  create: { formId: { $ref: "form:order-lines.line" } }
```

A form is named as `<object>.<form>`. The lines list takes the parameter `order` and shows only that order's lines. A list can also read a built-in source, such as contractors, with `source: { builtIn: contractors }`. See [list.yaml](/docs/en/extensions/reference/screens#listyaml).
</Step>

<Step>
### Add the page

```yaml title="pages/orders/page.yaml"
page: orders
title: Orders
description: Open orders and how many there are.
surface: workspace
layout: layout.yaml
```

```yaml title="pages/orders/layout.yaml"
schemaVersion: 2
regions:
  main:
    - id: open
      kind: component
      component: page.counter
      config:
        savedQueryId: { $ref: "query:open_count" }
        valueTemplate: "{{ value }}"
    - id: list
      kind: component
      component: layout.customList
      config:
        customListId: { $ref: "list:open-orders" }
    - id: summary
      kind: component
      component: custom_block
      config:
        customBlockId: { $ref: "block:order_summary" }
        inputs: { title: Today }
    - id: new_order
      kind: component
      component: page.form
      config:
        formId: { $ref: "form:orders.order" }
        capability: CREATE
    - id: shop
      kind: component
      component: layout.button
      config:
        label: Open the shop
        action: open_url
        url: "https://shop.example.test/admin"
```

The page is installed with the slug `x-shop-orders`. See [page.yaml](/docs/en/extensions/reference/screens#pageyaml).
</Step>

<Step>
### Translate it

```yaml title="locales/pl.yaml"
extension:
  name: Sklep
  description: Zamówienia z pozycjami i ekrany do pracy z nimi.
permissions:
  links:
    shop.example.test:
      reason: Otwiera zamówienie w sklepie.
blocks:
  order_summary:
    label: Podsumowanie zamówienia
forms:
  orders:
    order:
      config:
        title: Nowe zamówienie
        successMessage: Zapisano
pages:
  orders:
    title: Zamówienia
    description: Otwarte zamówienia i ich liczba.
```

Form names, list names, column labels and action labels are English only. See [Translations](/docs/en/extensions/reference/screens#translations).
</Step>

### Validate, test and pack


</Step>
</Steps>

## After install

[Install the zip](/docs/en/extensions/install) as usual. The review lists the screens under **Screens members will see**. Unlike the other parts of an extension, they reach members at once:

| Screen | Who sees it after install | What you do |
| --- | --- | --- |
| The page | Every member of every company. | Add it to a company's menu; a package places no menu item. Narrow its companies and audience if needed. |
| The forms | Every company where the module `x-shop` is exposed, which is all of them until you narrow it. | Set who may use each form, as for your own forms. |
| The lists | Members see a list where a page or form embeds it. | Nothing. |

An order now opens in the packaged form, with its lines below:

![An order opened in the form the package brings, with the summary block and the order's lines](/docs/_assets/extensions/workspace-screens/shop-form.webp)

The forms, lists and page are read-only and change only with an upgrade. See [What the organization does next](/docs/en/extensions/after-install#what-the-organization-does-next).
