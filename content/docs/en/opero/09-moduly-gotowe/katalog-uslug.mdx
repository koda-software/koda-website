## What the catalog is for

The service catalog is a **list of repeatable items** that go onto documents: services, work, costs. Instead of typing "Service inspection, hour, 250 PLN" on every invoice, you choose a ready item, and the name, unit, and price drop in by themselves.

The gain is twofold: you issue a document **faster** and name the same thing **more consistently**. The same service is not called "inspection" once, "periodic service" another time, "INSP." a third.

## Contents of a catalog item

- **A name**, that is, what the client will see on the document.
- **A unit**: hour, piece, month, set.
- **A price** the system will suggest when inserting the item.

> **Example.** You issue an invoice for service. Instead of typing the description by hand, you choose "Periodic inspection" from the catalog, the unit hour, the price suggested. You enter only the number of hours, and the system computes the rest.

## The catalog price is a suggestion

The catalog price is a **starting point**, not a fixed price list. If you agreed a different rate in a specific matter, you correct it on the document. The catalog is to save typing, not to block negotiation.

Note the reverse of this rule: **changing a price in the catalog does not change already issued documents.** An invoice keeps the values from the moment of issue.

## Gaps in the catalog

If you often type the same item by hand because it is not in the catalog, report it to the administrator. Adding an item takes a moment, saves everyone the repetitive work, and keeps uniform naming on documents going out to clients.
