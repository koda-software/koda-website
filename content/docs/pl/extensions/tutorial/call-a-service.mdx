---
title: "Część 2: Wywołaj usługę"
description: "Dodaj do rozszerzenia Hello połączenie z tokenem, ustawienie języka, sprawdzenie połączenia, krok wywołujący httpbin.org, filtr i polskie tłumaczenie."
---

W tej części paczka uczy się wywoływać httpbin.org z sekretnym tokenem. Na końcu ma połączenie, ustawienie, sprawdzenie tokenu, krok `greet`, filtr `shout` i polskie tłumaczenie.

<Steps>
<Step>
### Dodaj dwie akcje i filtr [#add-two-actions-and-a-filter]

Uruchom te polecenia w folderze paczki. Każde zapisuje działający przykład i dopisuje jego wiersz do `extension.yaml`; `--rule` tworzy akcję z pliku reguły.

```bash title="Terminal"
cd hello-ext
opero-ext add action verify --rule
opero-ext add action greet --rule
opero-ext add filter shout
```

```txt title="Wynik pierwszego polecenia"
  actions/verify/action.yaml
  actions/verify/tests.yaml
  actions/verify/rule.yaml
  actions/verify/step.js
  extension.yaml
Wrote 5 files in …/hello-ext.
```

W kolejnych krokach zastąpisz te przykłady. Usuń `actions/verify/step.js` i `actions/greet/step.js`, bo reguły poniżej ich nie używają.
</Step>

<Step>
### Opisz połączenie [#describe-the-connection]

Połączenie to formularz, w którym administrator wpisuje dane uwierzytelniające usługi. Utwórz `connection/connection.yaml`:

```yaml title="connection/connection.yaml"
methods:
  - method: token
    kind: api_token
    label: API token
    fields:
      token: { type: text, label: API token, required: true, hint: true }
verify: verify
```

Każde pole metody jest sekretem; `hint: true` pozwala Opero pokazać ostatnie cztery znaki zapisanego tokenu. `verify` wskazuje akcję, którą uruchamia **Sprawdź połączenie**. Zobacz [Połączenie i sekrety](/docs/pl/extensions/reference/connection-and-secrets).
</Step>

<Step>
### Dodaj ustawienie [#add-a-setting]

Język powitania nie jest sekretem, więc jest ustawieniem, a nie częścią połączenia. Utwórz `settings.yaml`:

```yaml title="settings.yaml"
groups:
  - group: general
    label: General
    description: How the greetings are sent.
    fields:
      language: { type: select, label: Language, options: [en, pl], default: en }
```

Każda grupa to sekcja formularza ustawień. Dzięki `default: en` rozszerzenie działa, zanim ktokolwiek otworzy formularz; zobacz [Ustawienia](/docs/pl/extensions/reference/settings).
</Step>

<Step>
### Napisz sprawdzenie [#write-the-check]

Sprawdzenie to akcja, której nic nie publikuje jako kroku. Nie przyjmuje wejścia i zwraca to, co odpowie usługa.

```yaml title="actions/verify/action.yaml"
# The connection check: connection.yaml names it. It exposes nothing.
action: verify
label: Verify
description: Checks the connection's token with httpbin.org.

run: rule.yaml
tests: tests.yaml
```

Jej logika to [plik reguły](/docs/pl/extensions/reference/rule-files): kroki i krawędzie, które zapisuje edytor reguł, z identyfikatorami kroków wybranymi przez ciebie.

```yaml title="actions/verify/rule.yaml"
# The rule-save graph; the reader supplies its name and MANUAL trigger.
entryStepId: call
steps:
  - id: call
    type: CALL_WEBHOOK
    name: Check token
    contextKey: output
    config:
      url: https://httpbin.org/bearer
      method: GET
      headers: { Authorization: "Bearer {{ connection.token }}" } # [!code highlight]
edges: []
```

`{{ connection.token }}` to sekret: Opero wstawia prawdziwą wartość dopiero podczas wysyłania żądania. To, co reguła zostawi pod `output`, jest wynikiem akcji, a status błędu kończy sprawdzenie niepowodzeniem.
</Step>

<Step>
### Przetestuj sprawdzenie [#test-the-check]

Przypadek testowy wymienia żądania, które wysyła akcja, odpowiedź na każde z nich i to, jak przypadek się kończy. Opero uruchamia wszystkie przypadki przy przesłaniu, nie wysyłając niczego.

```yaml title="actions/verify/tests.yaml"
- name: a valid token is accepted
  connection: { token: test-token }
  http:
    - request:
        method: GET
        url: https://httpbin.org/bearer
        headers: { authorization: Bearer test-token }
      response: { status: 200, body: { authenticated: true, token: test-token } }
  succeeds: true

- name: a refused token fails
  connection: { token: wrong-token }
  http:
    - request: { method: GET, url: https://httpbin.org/bearer }
      response: { status: 401 }
  fails: { status: 401 }
```

`connection` podaje wartości danych uwierzytelniających przypadku. Porównywane są tylko nagłówki, które wymienisz, pisane małymi literami; zobacz [Testy](/docs/pl/extensions/reference/tests).
</Step>

<Step>
### Napisz krok greet [#write-the-greet-step]

Tego kroku będą używać autorzy reguł. Przyjmuje imię i wysyła powitanie.

```yaml title="actions/greet/action.yaml"
action: greet
label: Greet
description: Sends a greeting for a name to httpbin.org and returns its answer.

input:
  name: { type: text, label: Name, required: true }
output:
  status: { type: integer, label: HTTP status }
  body: { type: object, label: Answer, fields: {} }

run: rule.yaml
tests: tests.yaml

expose:
  ruleStep: { category: integrations }
```

```yaml title="actions/greet/rule.yaml"
# The rule-save graph; the reader supplies its name and MANUAL trigger.
entryStepId: call
steps:
  - id: call
    type: CALL_WEBHOOK
    name: Greet
    contextKey: output
    config:
      url: "https://httpbin.org/anything?lang={{ trigger.settings.language }}"
      method: POST
      headers: { Authorization: "Bearer {{ connection.token }}" }
      body: { greeting: "Hello, {{ trigger.data.name }}!" }
edges: []
```

| Napisz | Aby dostać |
| --- | --- |
| `{{ trigger.data.name }}` | Pole wejścia akcji. |
| `{{ trigger.settings.language }}` | Ustawienie, z zastosowaną wartością domyślną. |
| `{{ connection.token }}` | Pole sekretne. Tylko w wartości nagłówka albo w wartości parametru zapytania w URL kroku **Wywołaj webhook**. |
</Step>

<Step>
### Przetestuj krok greet [#test-the-greet-step]

Pierwszy przypadek dowodzi, że żądanie niesie ustawienie, token i imię. Drugi dowodzi, że `429` jest zgłaszane jako przekroczenie limitu, więc wywołująca reguła może poczekać i ponowić próbę.

```yaml title="actions/greet/tests.yaml"
- name: the greeting is sent
  input: { name: Ada }
  settings: { language: pl }
  connection: { token: test-token }
  http:
    - request:
        method: POST
        url: https://httpbin.org/anything?lang=pl
        headers: { authorization: Bearer test-token }
        body: { greeting: "Hello, Ada!" }
      response:
        status: 200
        headers: { content-type: application/json }
        body: { json: { greeting: "Hello, Ada!" } }
  returns:
    status: 200
    headers: { content-type: application/json }
    body: { json: { greeting: "Hello, Ada!" } }

- name: a 429 is reported as rate limited
  input: { name: Ada }
  connection: { token: test-token }
  http:
    - request: { method: POST, url: https://httpbin.org/anything?lang=en }
      response: { status: 429, headers: { retry-after: "30" } }
  rateLimited: { status: 429 }
```

Drugi przypadek nie podaje `settings`, więc językiem jest wartość domyślna, `en`.
</Step>

<Step>
### Napisz filtr [#write-the-filter]

Funkcja filtra dostaje wartość przekazaną do filtra i od razu zwraca wynik; nie może być `async`.

```yaml title="filters/shout/filter.yaml"
filter: shout
description: Upper-cases a text and adds an exclamation mark.
script: filter.js
```

```js title="filters/shout/filter.js"
/** @type {import('../../.opero/types').Filter} */
const filter = (value) => String(value ?? '').toUpperCase() + '!';
export default filter;
```

Po instalacji każdy szablon może zawierać `{{ "hi" | x_hello_ext_shout }}` i dostać `HI!`. Zobacz [Filtry szablonów](/docs/pl/extensions/reference/filters).
</Step>

<Step>
### Przetłumacz [#translate]

Wersję angielską zapisujesz w deskryptorach, a każdy inny język to jeden plik. Pomiń to, czego nie tłumaczysz, a zostanie wyświetlone po angielsku.

```yaml title="locales/pl.yaml"
extension:
  name: Hello
  description: Rozszerzenie startowe z powitaniem, wywołaniem httpbin.org i filtrem.
permissions:
  network:
    httpbin.org: { reason: Sprawdza token i wysyła powitania do testowej usługi httpbin.org. }
connection:
  methods:
    token:
      label: Token API
      fields: { token: { label: Token API } }
settings:
  groups:
    general:
      label: Ogólne
      description: Jak wysyłane są powitania.
  fields:
    language: { label: Język }
actions:
  hello:
    label: Powitanie
    description: Tworzy powitanie dla imienia.
    input: { name: { label: Imię } }
    output: { greeting: { label: Powitanie } }
  greet:
    label: Pozdrów
    description: Wysyła powitanie dla imienia do httpbin.org i zwraca jego odpowiedź.
    input: { name: { label: Imię } }
filters:
  shout: { description: Zamienia tekst na wielkie litery i dodaje wykrzyknik. }
```

Klucz, który nie wskazuje niczego w paczce, jest odrzucany, więc literówka się nie ukryje. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/translations).
</Step>

<Step>
### Wpisz nowe części do extension.yaml [#list-the-new-parts-in-extensionyaml]

Polecenia `add` wpisały już akcje i filtr. Dodaj host, który wywołuje paczka, z powodem, a także połączenie, ustawienia i język:

```yaml title="extension.yaml"
# The package's contents: every feature it installs is listed here.
manifestVersion: 2
extension: hello-ext
version: 0.1.0
name: Hello
description: A starter extension with a greeting, a call to httpbin.org and a filter.
publisher: Your company
requires:
  modules: [rules]
permissions: # [!code ++]
  network: # [!code ++]
    - host: httpbin.org # [!code ++]
      reason: Checks the token and sends greetings to the httpbin.org test service. # [!code ++]
connection: connection # [!code ++]
settings: settings.yaml # [!code ++]

actions:
  - actions/hello
  - actions/verify
  - actions/greet
filters:
  - filters/shout

locales: [pl] # [!code ++]

# What the catalog shows is under listing/: icon.png, description.md and
# changelog.md. Screenshots are listed here, in order, with their captions:
# listing:
#   screenshots:
#     - file: listing/screenshots/main.png
#       caption: The main screen
```

Przed instalacją administrator widzi każdy host wraz z powodem. Wywołanie innego hosta jest odrzucane, podobnie jak uprawnienie bez powodu.
</Step>
</Steps>
