---
title: "Część 1: Utwórz paczkę"
description: "Utwórz szkielet rozszerzenia Hello poleceniem opero-ext init, poznaj manifest, pierwszą akcję, jej skrypt i test, a potem zwaliduj paczkę."
---

W tej części tworzysz szkielet paczki `hello-ext` i czytasz, co zapisało narzędzie. Na końcu masz poprawną paczkę z jednym krokiem, który tworzy powitanie.

Samouczek buduje `hello-ext` dla [httpbin.org](https://httpbin.org), publicznej usługi, która odsyła otrzymane żądania. Każdy pokazany plik jest kompletny, w takiej postaci, w jakiej trafia do gotowej paczki.

| Część | Co robisz |
| --- | --- |
| 1. Utwórz paczkę | Tworzysz szkielet poleceniem `init` i czytasz, co powstało. |
| 2. [Wywołaj usługę](/docs/pl/extensions/tutorial/call-a-service) | Dodajesz połączenie, ustawienie, krok wywołujący httpbin.org, filtr i tłumaczenie. |
| 3. [Sprawdź i spakuj](/docs/pl/extensions/tutorial/check-and-pack) | Walidujesz paczkę, pakujesz plik zip i uruchamiasz testy w Opero. |
| 4. [Zainstaluj i używaj](/docs/pl/extensions/tutorial/install-and-use) | Przesyłasz, instalujesz, łączysz, używasz kroku w regule i wydajesz nową wersję. |

<Steps>
<Step>
### Utwórz folder [#create-the-folder]

Niech narzędzie wiersza poleceń zapisze działającą paczkę. Nazwa folderu staje się kluczem rozszerzenia; inny wybierzesz opcją `--key`.

```bash title="Terminal"
opero-ext init hello-ext --name Hello
```

```txt title="Wynik"
  extension.yaml
  actions/hello/action.yaml
  actions/hello/tests.yaml
  actions/hello/run.js
  listing/description.md
  listing/changelog.md
  listing/icon.png
  README.md
  .gitignore
  jsconfig.json
  .vscode/settings.json
Wrote 11 files in …/hello-ext.
```

Do pliku zip trafia tylko to, do czego prowadzi `extension.yaml`, oraz folder `listing/`, który pokazuje katalog. `README.md`, `.gitignore`, `jsconfig.json` i `.vscode/` są dla ciebie i twojego edytora.
</Step>

<Step>
### Opisz paczkę [#describe-the-package]

`extension.yaml`, czyli manifest, zawiera tożsamość paczki i wymienia każdą część, którą instaluje. Zastąp opis zastępczy:

```yaml title="extension.yaml"
# The package's contents: every feature it installs is listed here.
manifestVersion: 2
extension: hello-ext
version: 0.1.0
name: Hello
description: A starter extension with a greeting, a call to httpbin.org and a filter. # [!code highlight]
publisher: Your company
requires:
  modules: [rules]

actions:
  - actions/hello

# What the catalog shows is under listing/: icon.png, description.md and
# changelog.md. Screenshots are listed here, in order, with their captions:
# listing:
#   screenshots:
#     - file: listing/screenshots/main.png
#       caption: The main screen
```

| Klucz | Co to jest |
| --- | --- |
| `extension` | Klucz, od którego pochodzą nazwy wszystkiego, co dodaje rozszerzenie. Organizacja nie może zainstalować dwóch rozszerzeń, których klucze na siebie zachodzą, na przykład `order` i `order-sync`. |
| `version` | Trzy liczby. Każde przesłanie wymaga nowej. |
| `name`, `description` | To, co pokazuje lista rozszerzeń, po angielsku. Część 2 je tłumaczy. |
| `actions` | Foldery akcji. Folder, którego tu nie ma, nie należy do paczki. |

Wszystkie klucze opisuje strona [extension.yaml](/docs/pl/extensions/reference/manifest), a pliki katalogu strona [Wizytówka w katalogu](/docs/pl/extensions/reference/listing).
</Step>

<Step>
### Opisz akcję [#describe-the-action]

Akcja to jedna operacja, tutaj udostępniona jako krok reguły. Zastąp opis zastępczy w `action.yaml`:

```yaml title="actions/hello/action.yaml"
action: hello
label: Hello
description: Builds a greeting for a name. # [!code highlight]

input:
  name: { type: text, label: Name, required: true }
output:
  greeting: { type: text, label: Greeting }

run: run.js
tests: tests.yaml

expose:
  ruleStep: { category: data }
```

| Klucz | Co to jest |
| --- | --- |
| `action` | Nazwa akcji. Nazwa folderu nie ma znaczenia. |
| `input`, `output` | [Listy pól](/docs/pl/extensions/reference/actions#field-lists). Wejście staje się formularzem kroku w edytorze reguł. |
| `run` | Logika: skrypt albo plik reguły, jak w części 2. |
| `expose.ruleStep` | Publikuje akcję jako krok `x-hello-ext.hello` w kategorii `data`. |

Wszystkie klucze opisuje strona [Akcje i listy pól](/docs/pl/extensions/reference/actions).
</Step>

<Step>
### Przeczytaj skrypt [#read-the-script]

Skrypt eksportuje jedną funkcję. Dostaje ona wejście i zwraca wyjście akcji.

<Tabs items={['JavaScript', 'TypeScript']}>
<Tab value="JavaScript">

```js title="actions/hello/run.js"
/** @type {import('../../.opero/types').Action<'hello'>} */
const run = ({ input }) => {
  return { greeting: 'Hello, ' + input.name + '!' };
};
export default run;
```

Komentarz w pierwszym wierszu nadaje funkcji typ wyprowadzony z `action.yaml`, więc edytor podpowiada `input.name`.

</Tab>
<Tab value="TypeScript">

```ts title="actions/hello/run.ts"
import type { Action } from '../../.opero/types';

const run: Action<'hello'> = ({ input }) => {
  return { greeting: 'Hello, ' + input.name + '!' };
};
export default run;
```

Utwórz szkielet z opcją `--typescript`, a dostaniesz `run.ts`. Narzędzie usuwa typy przy pakowaniu, więc w pliku zip jest `run.js`.

</Tab>
</Tabs>

Argument zawiera też `settings`, `company`, `user` i `context`; zobacz [Skrypty](/docs/pl/extensions/reference/scripts).
</Step>

<Step>
### Przeczytaj test [#read-the-test]

Przypadek testowy podaje wejście i dokładne oczekiwane wyjście. Opero uruchamia go przy każdym przesłaniu.

```yaml title="actions/hello/tests.yaml"
- name: a name gets a greeting
  input:
    name: Ada
  returns:
    greeting: Hello, Ada!
```
</Step>

<Step>
### Zwaliduj [#validate]

Sprawdzenie działa bez sieci i trwa chwilę, więc uruchamiaj je po każdej zmianie. Zapisuje też `.opero/`, czyli typy i schematy, z których korzysta edytor.

```bash title="Terminal"
opero-ext validate hello-ext
```

```txt title="Wynik"
hello-ext 0.1.0 is valid.
```
</Step>
</Steps>
