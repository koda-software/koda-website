---
title: "Część 3: Sprawdź i spakuj"
description: "Zwaliduj rozszerzenie Hello, przeczytaj raport problemów, spakuj plik zip i uruchom testy na serwerze Opero, zanim go prześlesz."
---

W tej części sprawdzasz gotowy folder i go pakujesz. Na końcu masz `hello-ext-0.1.0.zip` i wiesz, że jego testy przechodzą w Opero.

<Steps>
<Step>
### Zwaliduj folder [#validate-the-folder]

Uruchom sprawdzenie w folderze paczki.

```bash title="Terminal"
opero-ext validate .
```

```txt title="Wynik"
hello-ext 0.1.0 is valid.
```
</Step>

<Step>
### Przeczytaj raport problemów [#read-a-problem-report]

Gdy coś jest nie tak, każdy problem w każdym pliku jest wymieniony z kodem, plikiem, wierszem i miejscem. Tak wygląda raport dla literówki w `label` akcji hello i hosta `api.httpbin.org` w regule greet:

```txt title="Wynik"
  action.invalid  actions/hello/action.yaml:1
    actions/hello/action.yaml must have required property 'label'
  action.invalid  actions/hello/action.yaml:2 #/lable
    "lable" is not a key actions/hello/action.yaml knows.
  rule.host_not_declared  actions/greet/rule.yaml:9 #/steps/0/config/url
    Host "api.httpbin.org" is not listed in permissions.network.

3 problems found.
The package is not valid.
```

[Kody błędów](/docs/pl/extensions/error-codes) wyjaśniają każdy kod i sposób naprawy.
</Step>

<Step>
### Spakuj [#pack-it]

`pack` sprawdza folder jeszcze raz i zapisuje obok niego plik zip. Ten sam folder zawsze daje ten sam plik, bajt w bajt; nazwę pliku wybierzesz opcją `--out`.

```bash title="Terminal"
opero-ext pack .
```

```txt title="Wynik"
Wrote …/hello-ext-0.1.0.zip (5710 bytes; listing images 1325 bytes)
```

Plik zip zawiera piętnaście plików, do których prowadzi `extension.yaml`, i trzy pliki [wizytówki](/docs/pl/extensions/reference/listing), nic więcej. `listing images` to rozmiar ikony i ewentualnych zrzutów ekranu.
</Step>

<Step>
### Uruchom testy w Opero [#run-the-tests-on-opero]

Ten krok jest opcjonalny: przesłanie uruchamia te same testy. Zaloguj się raz, a potem uruchom wszystkie przypadki na serwerze, niczego nie zapisując.

```bash title="Terminal"
opero-ext login --server https://opero.example.com/mcp
opero-ext test . --server https://opero.example.com/mcp
```

```txt title="Wynik"
Result  Part    Test                          Name
PASS    hello   actions/hello/tests.yaml#/0   a name gets a greeting
PASS    verify  actions/verify/tests.yaml#/0  a valid token is accepted
PASS    verify  actions/verify/tests.yaml#/1  a refused token fails
PASS    greet   actions/greet/tests.yaml#/0   the greeting is sent
PASS    greet   actions/greet/tests.yaml#/1   a 429 is reported as rate limited

5 of 5 tests passed.
```

Dodaj `--org <organizationId>`, jeśli należysz do więcej niż jednej organizacji. `test` wymaga modułu **Tworzenie rozszerzeń** i bez niego kończy się kodem 4.
</Step>
</Steps>

<Callout type="idea" title="Najszybsza pętla">
Uruchamiaj `validate` po każdej zmianie, `test`, gdy pliki są poprawne, i przesyłaj paczkę, gdy testy przechodzą.
</Callout>
