Ustawienia to wartości, które administrator wybiera dla zainstalowanego rozszerzenia, na przykład region, język albo liczbę rekordów wysyłanych w jednym wywołaniu. Nie są sekretne: sekret należy do [połączenia](/docs/pl/extensions/reference/connection-and-secrets). Paczka może mieć ustawienia z połączeniem albo bez niego.

```yaml title="settings.yaml"
groups:
  - group: general
    label: General
    fields:
      region: { type: select, label: Region, options: [eu, us], default: eu }
      sandbox: { type: boolean, label: Use the sandbox }
  - group: sync
    label: Synchronisation
    description: How much is sent in one call.
    fields:
      batchSize: { type: integer, label: Batch size, help: Parcels per call., default: 50 }
      owner: { type: text, label: Owner e-mail, required: true }
```

Plik leży na najwyższym poziomie paczki, obok `extension.yaml`, który go wskazuje:

```yaml title="extension.yaml"
settings: settings.yaml
```

`settings.yaml` to jedyna dopuszczalna wartość. Plik `settings.yaml`, którego nie wskazuje `extension.yaml`, jest odrzucany z kodem `layout.unlisted_feature`.

## settings.yaml [#settingsyaml]

Plik ma jeden klucz, `groups`: listę od 1 do 20 grup. Każda grupa to jedna sekcja formularza ustawień.

<TypeTable
  type={{
    group: {
      type: 'string',
      description: 'Klucz grupy: małe litery, cyfry i _, zaczyna się od litery, do 41 znaków. Unikalny w pliku.',
      required: true,
    },
    label: {
      type: 'string',
      description: 'Tytuł sekcji, do 200 znaków. Do przetłumaczenia.',
      required: true,
    },
    description: {
      type: 'string',
      description: 'Widoczny pod tytułem, do 1000 znaków. Do przetłumaczenia.',
    },
    fields: {
      type: 'field list',
      description: 'Co najmniej jedno pole. Ta sama lista pól co wejście akcji.',
      required: true,
    },
  }}
/>

`fields` to [lista pól](/docs/pl/extensions/reference/actions#field-lists): każde pole ma `type` i może mieć `label`, `help`, `required`, `default` oraz `options`, `items` albo `fields`, zależnie od typu. Dwie rzeczy różnią się od wejścia akcji:

- `secret` i `hint` są odrzucane. Wartość, która musi pozostać tajna, to pole danych uwierzytelniających połączenia.
- Zamiast listy nie można użyć pliku schematu.

<Callout title="Klucze pól są unikalne w całym pliku">
Grupa tylko układa formularz. Wartości to jeden płaski zestaw pól, więc dwie grupy nie mogą zadeklarować tego samego klucza pola (`name.duplicate`), a przeniesienie pola do innej grupy niczego nie zmienia dla akcji, które je odczytują. Plik ma łącznie najwyżej 100 pól.
</Callout>

## Gdzie są przechowywane wartości [#where-the-values-live]

Wartości należą do rozszerzenia zainstalowanego w organizacji: jedna wartość na ustawienie, taka sama dla każdej firmy. Nie są częścią połączenia.

- **Wartości domyślne obowiązują, dopóki nic nie zapisano.** Opero przechowuje tylko to, co ustawił administrator. Pole z `default` bez zapisanej wartości ma wartość domyślną, a wartość domyślna zmieniona w nowej wersji od razu obowiązuje we wszystkich ustawieniach, których administrator nie ustawił.
- **Pole bez wartości domyślnej i bez zapisanej wartości nie ma wartości.** Brakuje go w tym, co odczytują akcje.

## Co widzi administrator [#what-the-administrator-sees]

Strona rozszerzenia ma kartę **Ustawienia** między kartami **Szczegóły** i **Połączenie**, widoczną, gdy paczka ma ustawienia. Ma jedną sekcję na każdą grupę, z jej etykietą i opisem, a w niej każde pole z etykietą, pomocą, wartością domyślną i oznaczeniem pola wymaganego, w języku oglądającego.

Odczyt ustawień wymaga `org.extensions.read`, a zapis `org.extensions.update`; bez tego uprawnienia formularz jest tylko do odczytu. Jest też tylko do odczytu, gdy dla rozszerzenia trwa instalacja, aktualizacja albo inne polecenie.

Formularz można zapisać z pustym polem wymaganym. Wartość każdego wypełnionego pola musi pasować do tego pola, a pole, którego plik nie deklaruje, jest odrzucane.

## Wymagane ustawienia [#required-settings]

Pole z `required: true` musi mieć wartość, zapisaną albo domyślną. Dopóki jej nie ma:

- rozszerzenie ma status **Nie działa: niekompletne ustawienia**, a karta **Ustawienia** wymienia brakujące ustawienia;
- jego kroków brakuje w edytorze reguł, a zapisana reguła, która do nich dotrze, kończy się błędem na tym kroku z kodem `extension_inactive`.

Rozszerzenie znów działa, gdy tylko administrator uzupełni brakujące ustawienia i zapisze. Ten warunek nie zależy od połączenia: rozszerzenie z połączeniem musi mieć zarówno kompletne ustawienia, jak i włączone połączenie.

<Callout type="idea" title="Podaj wartość domyślną, gdy ma to sens">
Wymagane pole z wartością domyślną nigdy nie zatrzymuje rozszerzenia. Pomiń wartość domyślną tylko dla wartości, której nikt nie zgadnie, na przykład numeru konta albo adresu e-mail. Wtedy rozszerzenie nie działa zaraz po instalacji, dopóki administrator jej nie uzupełni.
</Callout>

## Odczyt ustawień [#reading-settings]

Akcje odczytują wartości z zastosowanymi wartościami domyślnymi. Ustawienia nie są sekretne, więc można ich używać wszędzie tam, gdzie można użyć szablonu albo skryptu.

<Tabs items={['Plik reguły', 'Skrypt']}>
<Tab value="Plik reguły">

Napisz `{{ trigger.settings.<field> }}`:

```yaml title="actions/quote/rule.yaml"
entryStepId: call
steps:
  - id: call
    type: CALL_WEBHOOK
    name: Ask for a quote
    contextKey: output
    config:
      url: "https://api.example.com/v1/quotes?region={{ trigger.settings.region }}" # [!code highlight]
      method: POST
      body: { weight: "{{ trigger.data.weight }}", contact: "{{ trigger.settings.owner }}" } # [!code highlight]
edges: []
```

Host w URL kroku **Wywołaj webhook** nadal trzeba wpisać wprost: ustawienie nie może go podać.

</Tab>
<Tab value="Skrypt">

Są w polu `settings` argumentu:

```js title="actions/split/run.js"
/** @type {import('../../.opero/types').Action<'split'>} */
const run = ({ input, settings }) => {
  const batches = [];
  for (let i = 0; i < input.parcels.length; i += settings.batchSize) { // [!code highlight]
    batches.push(input.parcels.slice(i, i + settings.batchSize));
  }
  return { batches };
};
export default run;
```

</Tab>
</Tabs>

Paczka bez `settings.yaml` dostaje pusty obiekt. Akcja weryfikująca połączenie też dostaje zapisane ustawienia.

Narzędzie wiersza poleceń generuje z `settings.yaml` typ `Settings` w `.opero/types/index.d.ts`. Pole z wartością domyślną nigdy nie jest w nim opcjonalne, bo zawsze ma wartość:

```ts title=".opero/types/index.d.ts (fragment)"
export type Settings = {
  /** Region */
  region: "eu" | "us";
  /** Use the sandbox */
  sandbox?: boolean;
  /** Batch size: Parcels per call. */
  batchSize: number;
  /** Owner e-mail */
  owner: string;
};
```

## Ustawienia w testach [#settings-in-tests]

Przypadek testowy podaje ustawienia w `settings:`, na najwyższym poziomie przypadku. Pola, które przypadek pomija, dostają wartości domyślne:

```yaml title="actions/quote/tests.yaml"
- name: the region and the owner come from the settings
  input: { weight: "2" }
  settings: { owner: ops@example.com, region: us } # [!code highlight]
  http:
    - request:
        method: POST
        url: https://api.example.com/v1/quotes?region=us
        body: { weight: "2", contact: ops@example.com }
      response: { status: 200, body: { price: 12 } }
  succeeds: true

- name: the region defaults to eu
  input: { weight: "2" }
  settings: { owner: ops@example.com }
  http:
    - request: { method: POST, url: https://api.example.com/v1/quotes?region=eu }
      response: { status: 200, body: { price: 10 } }
  succeeds: true
```

- Ustawienia przypadku, po uzupełnieniu wartościami domyślnymi, muszą pasować do `settings.yaml`. Wymagane ustawienie bez wartości domyślnej trzeba więc podać w każdym przypadku, także w przypadkach akcji, które go nie odczytują.
- `settings` w paczce bez `settings.yaml` jest odrzucane z kodem `test.invalid`.
- `connection` w przypadku testowym zawiera tylko pola danych uwierzytelniających. Ustawienia w `connection.config` są odrzucane z kodem `test.invalid`.

## Aktualizacje i odinstalowanie [#upgrades-and-uninstalling]

Nowa wersja może dodawać, zmieniać i usuwać ustawienia. Plan instalacji pokazuje, co aktualizacja zrobi z zapisanymi wartościami, zanim się na nią zgodzisz; żaden z tych problemów nie blokuje aktualizacji.

| Nowa wersja | Co się dzieje | W planie |
| --- | --- | --- |
| Usuwa pole, które ma zapisaną wartość | Wartość jest odrzucana. | `settings.value_dropped` |
| Zmienia pole tak, że zapisana wartość już do niego nie pasuje | Wartość jest odrzucana. | `settings.value_dropped` |
| Dodaje wymagane pole bez wartości domyślnej | Po aktualizacji rozszerzenie nie działa, dopóki administrator go nie uzupełni. | `settings.incomplete_after_upgrade` |
| Zmienia wartość domyślną | Nowa wartość domyślna obowiązuje we wszystkich ustawieniach, których administrator nie ustawił. | Nic |

Zmiany ustawień nigdy nie wyłączają połączenia. Odinstalowanie usuwa zapisane wartości razem z rozszerzeniem; ponowna instalacja zaczyna od wartości domyślnych.

## Tłumaczenia [#translations]

Teksty ustawień i grup tłumaczy się w `locales/<lang>.yaml`, pod `settings`:

```yaml title="locales/pl.yaml"
settings:
  groups:
    general: { label: Ogólne }
    sync:
      label: Synchronizacja
      description: Ile jest wysyłane w jednym wywołaniu.
  fields:
    region: { label: Region }
    sandbox: { label: Użyj środowiska testowego }
    batchSize: { label: Rozmiar partii, help: Liczba paczek w jednym wywołaniu. }
    owner: { label: E-mail właściciela }
```

| Klucz | Tłumaczy |
| --- | --- |
| `settings.groups.<group>.label`, `description` | Tytuł i opis grupy. |
| `settings.fields.<field>.label`, `help` | Etykietę i pomoc ustawienia; pola zagnieżdżone w `fields`, elementy listy w `items`. |

Pola są wymienione w `settings.fields` według klucza, bez grupy. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/translations).

## Problemy [#problems]

| Kod | Co jest nie tak |
| --- | --- |
| `settings.invalid` | `settings.yaml` ma nieznany klucz, nie ma grup, ma więcej niż 20 grup, grupę bez `label` lub `fields` albo więcej niż 100 pól. |
| `name.duplicate` | Dwie grupy albo dwa pola w dowolnym miejscu pliku mają ten sam klucz. |
| `field.invalid` | Pole o złej strukturze, w tym `secret` lub `hint` w ustawieniu. |
| `layout.unlisted_feature` | `settings.yaml`, którego nie wskazuje `extension.yaml`. |
| `layout.missing_descriptor` | `extension.yaml` zawiera `settings: settings.yaml`, ale brakuje pliku. |
| `connection.invalid` | `connection.yaml` nadal ma blok `settings`. Przenieś go do `settings.yaml`. |
| `test.invalid` | Przypadek testowy, którego ustawienia nie pasują do `settings.yaml` albo który podaje ustawienia w `connection.config`. |

Wszystkie kody są wymienione w [Kodach błędów](/docs/pl/extensions/error-codes).
