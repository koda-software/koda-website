title: Ustawienia

---

Ustawienia to wartości, które administrator wybiera dla zainstalowanego rozszerzenia, na przykład region, język albo liczbę rekordów wysyłanych w jednym wywołaniu. Nie są sekretne: sekret należy do [połączenia](/docs/pl/extensions/reference/connection-and-secrets). Administrator wypełnia je na karcie [Konfiguracja](/docs/pl/extensions/after-install#configuration) rozszerzenia.

![Karta Konfiguracja z sekcją ustawień i połączeniem](/docs/_assets/extensions/after-install/configuration.webp)

```yaml title="settings.yaml"
groups:
  - group: general
    label: General
    fields:
      region: { type: select, label: Region, options: [eu, us], default: eu }
      sandbox: { type: boolean, label: Use the sandbox }
  - group: sync
    label: Synchronisation
    description: How much is sent in one call.
    fields:
      batchSize: { type: integer, label: Batch size, help: Parcels per call., default: 50 }
      owner: { type: text, label: Owner e-mail, required: true }
```

Plik leży na najwyższym poziomie paczki, obok `extension.yaml`, który wskazuje go wpisem `settings: settings.yaml`. To jedyna dopuszczalna wartość.

## settings.yaml [#settingsyaml]

Plik ma jeden klucz, `groups`: listę od 1 do 20 grup. Każda grupa to jedna sekcja formularza ustawień.

`fields` to [lista pól](/docs/pl/extensions/reference/actions#field-lists). Wartość, która musi pozostać tajna, to pole danych uwierzytelniających połączenia, dlatego `secret` i `hint` są tu odrzucane.

## Klucze pól są unikalne w pliku [#field-keys-are-unique-in-the-file]

Grupa tylko układa formularz. Wartości to jeden płaski zestaw najwyżej 100 pól, więc dwie grupy nie mogą zadeklarować tego samego klucza pola, a przeniesienie pola do innej grupy niczego nie zmienia dla akcji, które je odczytują.

## Wartości domyślne [#defaults]

Pole bez zapisanej wartości ma wartość z `default`. Opero przechowuje tylko to, co ustawił administrator, więc wartość domyślna zmieniona w nowej wersji od razu obowiązuje we wszystkich ustawieniach, których administrator nie ustawił. Pola bez zapisanej wartości i bez wartości domyślnej brakuje w tym, co odczytują akcje.

## Wymagane ustawienia [#required-settings]

Dopóki pole z `required: true` nie ma wartości, zapisanej ani domyślnej, rozszerzenie nie działa: jego kroków brakuje w edytorze reguł, a zapisana reguła, która do nich dotrze, kończy się błędem `extension_inactive`. Rozszerzenie znów działa, gdy tylko wartość zostanie zapisana. Zobacz [Stany](/docs/pl/extensions/after-install#states).

<Callout type="idea" title="Podaj wartość domyślną, gdy ma to sens">
Wymagane pole z wartością domyślną nigdy nie zatrzymuje rozszerzenia. Pomiń wartość domyślną tylko dla wartości, której nikt nie zgadnie, na przykład numeru konta albo adresu e-mail.
</Callout>

## Odczyt ustawień [#reading-settings]

Akcje odczytują wartości z zastosowanymi wartościami domyślnymi. Ustawienia nie są sekretne, więc można ich używać wszędzie tam, gdzie można użyć szablonu albo skryptu.

<Tabs items={['Plik reguły', 'Skrypt']}>
<Tab value="Plik reguły">

Napisz `{{ trigger.settings.<field> }}`. Ustawienie nie może podać hosta w URL kroku **Wywołaj webhook**.

```yaml title="actions/quote/rule.yaml"
entryStepId: call
steps:
  - id: call
    type: CALL_WEBHOOK
    name: Ask for a quote
    contextKey: output
    config:
      url: "https://api.example.com/v1/quotes?region={{ trigger.settings.region }}" # [!code highlight]
      method: POST
      body: { weight: "{{ trigger.data.weight }}", contact: "{{ trigger.settings.owner }}" } # [!code highlight]
edges: []
```

</Tab>
<Tab value="Skrypt">

Są w polu `settings` argumentu:

```js title="actions/split/run.js"
/** @type {import('../../.opero/types').Action<'split'>} */
const run = ({ input, settings }) => {
  const batches = [];
  for (let i = 0; i < input.parcels.length; i += settings.batchSize) { // [!code highlight]
    batches.push(input.parcels.slice(i, i + settings.batchSize));
  }
  return { batches };
};
export default run;
```

</Tab>
</Tabs>

Paczka bez `settings.yaml` dostaje pusty obiekt. Akcja weryfikująca połączenie też dostaje ustawienia. W wygenerowanym typie `Settings` w `.opero/types/index.d.ts` pole z wartością domyślną nigdy nie jest opcjonalne, bo zawsze ma wartość.

## Ustawienia w testach [#settings-in-tests]

Przypadek testowy podaje ustawienia w `settings:`, na najwyższym poziomie przypadku. Pola, które przypadek pomija, dostają wartości domyślne, a wynik musi pasować do `settings.yaml`, więc wymagane ustawienie bez wartości domyślnej podaje się w każdym przypadku.

```yaml title="actions/quote/tests.yaml"
- name: the region and the owner come from the settings
  input: { weight: "2" }
  settings: { owner: ops@example.com, region: us } # [!code highlight]
  http:
    - request:
        method: POST
        url: https://api.example.com/v1/quotes?region=us
        body: { weight: "2", contact: ops@example.com }
      response: { status: 200, body: { price: 12 } }
  succeeds: true
```

## Aktualizacje [#upgrades]

| Zmiana w nowej wersji | Co się dzieje | Kod |
| --- | --- | --- |
| Usunięto pole, które ma zapisaną wartość | Wartość jest odrzucana. Ostrzeżenie. | `settings.value_dropped` |
| Pole zmieniło się tak, że zapisana wartość już do niego nie pasuje | Wartość jest odrzucana. Ostrzeżenie. | `settings.value_dropped` |
| Dodano wymagane pole bez wartości domyślnej | Po aktualizacji rozszerzenie stoi, dopóki administrator go nie uzupełni. Ostrzeżenie. | `settings.incomplete_after_upgrade` |
| Zmieniono wartość domyślną | Nowa wartość domyślna obowiązuje we wszystkich ustawieniach, których administrator nie ustawił. | |

Zmiany ustawień nigdy nie wyłączają połączenia. Odinstalowanie usuwa zapisane wartości. Co widzi administrator, opisuje strona [Aktualizacja i odinstalowanie](/docs/pl/extensions/upgrade-and-uninstall#what-a-new-version-can-change).

## Tłumaczenia [#translations]

Teksty grup trafiają do `settings.groups.<group>`, a teksty pól do `settings.fields.<field>`, według klucza pola, bez grupy. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/translations#translatable-keys).

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `settings.invalid` | Nieznany klucz, brak grup albo więcej niż 20, grupa bez `label` lub `fields` albo więcej niż 100 pól. | Trzymaj się powyższych kluczy i limitów. |
| `name.duplicate` | Dwie grupy albo dwa pola w dowolnym miejscu pliku o tym samym kluczu. | Zmień nazwę jednego z nich. |
| `field.invalid` | Pole o złej strukturze, w tym `secret` lub `hint` w ustawieniu. | Przenieś wartość tajną do połączenia. |
| `layout.unlisted_feature` | `settings.yaml`, którego nie wskazuje `extension.yaml`. | Dodaj `settings: settings.yaml`. |
| `layout.missing_descriptor` | `extension.yaml` zawiera `settings: settings.yaml`, ale brakuje pliku. | Dodaj plik albo usuń klucz. |
| `connection.invalid` | `connection.yaml` nadal ma blok `settings`. | Przenieś go do `settings.yaml`. |
| `test.invalid` | Przypadek testowy, którego ustawienia nie pasują do `settings.yaml` albo który podaje ustawienia w `connection.config`. | Podaj je w `settings:`, tak jak deklaruje je plik. |
