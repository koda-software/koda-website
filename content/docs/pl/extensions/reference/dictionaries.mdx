title: Słowniki

---

Słownik to stała lista wartości, na przykład statusów albo priorytetów, które oferują pola wyboru. Paczka używa własnych słowników w polach swoich [obiektów](/docs/pl/extensions/reference/objects), tak jak przewodnik [Paczka z własnymi danymi](/docs/pl/extensions/own-data).

```yaml title="dictionaries/status/dictionary.yaml"
dictionary: status
name: Order status
description: Where an order is.
entries:
  - { key: open, label: Open }
  - { key: noted, label: Noted, color: "#2563EB" }
  - { key: closed, label: Closed, isActive: false }
```

Każdy słownik ma własny folder w `dictionaries/`, wymieniony w `dictionaries` w `extension.yaml`.

## Klucz po instalacji [#the-installed-key]

Słownik jest instalowany jako słownik organizacji z kluczem `x-<key>-<name>`: `status` rozszerzenia `shop-ext` to `x-shop-ext-status`. Organizacja nie może utworzyć słownika, którego klucz zaczyna się od `x-`.

Pola paczki wskazują słownik jego nazwą, `options: { dictionary: status }`, a nie kluczem po instalacji. Pole wyboru zapisuje `key` wpisu, więc [zapytanie](/docs/pl/extensions/reference/queries) porównuje z nim: `WHERE f_status = 'open'`.

## Tłumaczenia [#translations]

Tłumaczyć można tylko etykiety wpisów, w `dictionaries.<name>.entries.<key>.label`. `name` i `description` słownika pozostają po angielsku. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/translations#translatable-keys).

## Aktualizacje [#upgrades]

| Zmiana w nowej wersji | Co się dzieje | Kod |
| --- | --- | --- |
| Wpis zachowuje klucz | Zachowuje tożsamość, a rekordy zachowują wartości. | |
| Pominięto wpis | Jest usuwany. Dopóki pola własne organizacji wskazują słownik, przegląd instalacji blokuje. | `dictionary.save_validation` |
| Usunięto słownik | Jest usuwany albo zachowany jako słownik organizacji, gdy coś nadal go używa. Ostrzeżenie. | `dictionary.released` |
| Instalacja przejmuje słownik zachowany przy wcześniejszym odinstalowaniu | Słownik znów należy do rozszerzenia. Ostrzeżenie. | `dictionary.adopts_existing` |

Odinstalowanie domyślnie zachowuje słowniki jako własność organizacji. Co widzi administrator, opisuje strona [Aktualizacja i odinstalowanie](/docs/pl/extensions/upgrade-and-uninstall#what-a-new-version-can-change).

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `dictionary.invalid` | Nieznany klucz, nazwa w złej postaci, wpis bez `key` lub `label`, dwa wpisy o tym samym kluczu, kolor niezapisany jako `#RRGGBB`, więcej niż 1000 wpisów albo więcej niż 50 słowników. | Popraw klucz wskazany w komunikacie. |
| `name.duplicate` | Dwa słowniki o tej samej nazwie. | Zmień nazwę jednego z nich. |
| `object.unknown_reference` | Pole wskazuje słownik, którego paczka nie ma. | Popraw nazwę albo dodaj słownik. |
| `dictionary.save_validation` | W przeglądzie instalacji: słownika nie da się zapisać, na przykład dlatego, że wpisy zostałyby usunięte, a pola własne organizacji wskazują słownik. Blokuje instalację. | Zachowaj wpisy albo poproś organizację o zmianę tych pól. |
