Plik reguły to logika akcji zapisana jako reguła: kroki i krawędzie, które zapisuje edytor reguł. Wskazuje go `run: rule.yaml` w [action.yaml](/docs/pl/extensions/reference/actions). Nazwa, opis i wyzwalacz reguły pochodzą z `action.yaml`, więc plik ich nie zawiera.

```yaml title="actions/lookup/rule.yaml"
entryStepId: call
steps:
  - id: call
    type: CALL_WEBHOOK
    name: Find customer
    contextKey: answer
    config:
      url: "https://api.example.com/v1/customers?email={{ trigger.data.email }}"
      method: GET
      headers: { Authorization: "Bearer {{ connection.token }}" }
  - id: shape
    type: RUN_SCRIPT
    name: Keep the first match
    contextKey: output
    config:
      code: { $file: shape.js }
edges:
  - { fromStepId: call, toStepId: shape, branchKey: default }
```

Każdy inny klucz na najwyższym poziomie pliku, w tym `name`, `description` i `trigger`, zostaje odrzucony z kodem `rule.invalid`.

## Wynik [#the-result]

To, co reguła zostawi pod kluczem kontekstu `output`, jest wynikiem akcji i jest sprawdzane z jej polami wyjściowymi. Krokowi, który go tworzy, nadaj `contextKey: output`.

Wynik kroku **Wywołaj webhook** to `{ status, headers, body }`. Status błędu powoduje błąd kroku, a więc i akcji, chyba że wyjście błędu kroku jest podłączone.

## Id kroków [#step-ids]

Id kroków to lokalne nazwy, np. `call` albo `map_items`, a Opero przy instalacji nadaje każdemu krokowi własny identyfikator. Zostaw to samo id między wersjami, a krok zachowa swoją tożsamość.

## Adresy URL kroku Wywołaj webhook [#call-webhook-urls]

Adres URL kroku **Wywołaj webhook** zaczyna się od `https://` i hosta wpisanego w całości, jednego z hostów z [`permissions.network`](/docs/pl/extensions/reference/manifest#network-hosts). Host nie może pochodzić z szablonu, a adres nie zawiera portu, nazwy użytkownika ani hasła. Ścieżka i parametry zapytania mogą używać szablonów.

`auth: connection` wysyła dane uwierzytelniające połączenia jako HTTP Basic, gdy każda metoda połączenia deklaruje `scheme`. Żadne inne `auth` nie jest przyjmowane. Zobacz [HTTP Basic z połączenia](/docs/pl/extensions/reference/connection-and-secrets#http-basic-from-the-connection).

## Pliki skryptów [#script-files]

Krok **Uruchom skrypt** może trzymać kod w pliku skryptu w folderze akcji: `code: { $file: shape.js }`. To jedyne miejsce, w którym przyjmowane jest `$file`. Plik jest modułem, jak opisuje strona [Skrypty](/docs/pl/extensions/reference/scripts).

## Wartości dostępne w pliku reguły [#values-available-in-a-rule-file]

| Wpisz | Aby dostać |
| --- | --- |
| `{{ trigger.data.<field> }}` | Pole wejścia akcji. W akcji uruchamianej przez [harmonogram](/docs/pl/extensions/reference/schedules) wejście harmonogramu: `subject`, `lastSucceededAt` i `firstRun`. |
| `{{ trigger.settings.<field> }}` | Jedno z [ustawień](/docs/pl/extensions/reference/settings) rozszerzenia, z zastosowaną wartością domyślną. Nie jest sekretem, więc działa wszędzie. |
| `{{ connection.<field> }}` | Sekretne pole połączenia, tylko w wartości nagłówka albo wartości parametru zapytania w URL kroku **Wywołaj webhook**, a także w ścieżce URL i treści, gdy `connection.yaml` ustawia `secretsInBody`. Zobacz [Sekrety](/docs/pl/extensions/reference/connection-and-secrets#secrets). |
| `{{ userConnection.<field> }}` | Token albo sekretna wartość członka, tylko w akcji członka, z tymi samymi ograniczeniami co sekret połączenia. Zobacz [Połączenia członków](/docs/pl/extensions/reference/member-connections#the-members-values-in-rules). |
| `{{ trigger.record.id }}` | Rekord, dla którego działa [akcja bloku albo polecenie rekordu](/docs/pl/extensions/reference/member-actions#the-record-the-action-runs-for); także `type`, `moduleKey` i `objectKey`. |
| `{{ <contextKey>.… }}` | Wynik wcześniejszego kroku, pod jego kluczem kontekstu. |

Wewnątrz akcji szablony mają tylko wbudowane filtry Opero. Filtry innych rozszerzeń, własnych skryptów organizacji ani tej paczki nie są dostępne.

## Kroki, których może używać plik reguły [#steps-a-rule-file-may-use]

| Typ kroku | Do czego |
| --- | --- |
| `CALL_WEBHOOK` | Wywołanie zewnętrznej usługi. |
| `RUN_SCRIPT` | Uruchomienie JavaScriptu w piaskownicy między wywołaniami. |
| `CONDITION`, `SWITCH` | Rozgałęzienie zależnie od odpowiedzi. |
| `LOOP` | Powtórzenie kroków dla każdego elementu listy. |
| `FILTER`, `TRANSFORM`, `AGGREGATE`, `SORT`, `DEDUPE` | Przekształcanie list. |
| `SAVE_TO_CONTEXT` | Zachowanie wartości na później. |
| `LOG_OUTPUT` | Zapis w logu uruchomienia. |
| `WAIT` | Pauza. |
| `STOP` | Zakończenie reguły. |
| `x-<key>.<action>` | Uruchomienie innej akcji paczki opublikowanej jako krok reguły. Akcje nie mogą wywoływać się nawzajem w cyklu. |
| `EMIT_EVENT` | Zgłoszenie zdarzeń własnych wyzwalaczy paczki, w akcji uruchamianej przez harmonogram albo zaczep połączenia członka. Zobacz [Zgłaszanie zdarzeń](/docs/pl/extensions/reference/raising-events). |

### Kroki danych [#data-steps]

Te kroki są dozwolone, gdy paczka deklaruje [zakres danych](/docs/pl/extensions/reference/data-permissions), którego każdy z nich potrzebuje, i tylko na własnych obiektach i zapytaniach paczki. Zobacz [Kroki danych](/docs/pl/extensions/reference/data-steps).

| Typ kroku | Do czego | Zakres |
| --- | --- | --- |
| `FETCH_RECORDS` | Odczyt rekordów obiektów paczki. | `records:read` |
| `CREATE_RECORD`, `UPDATE_RECORD` | Tworzenie i zmiana rekordów obiektów paczki. | `records:write` |
| `RUN_QUERY` | Uruchomienie zapytania paczki. | `queries:run` albo `queries:mutate` |
| `UPDATE_CONTRACTOR` | Zmiana kontrahenta. | `contractors:write` |
| `SEND_EMAIL` | Wysłanie e-maila. | `email:send` |
| `SEND_NOTIFICATION` | Powiadomienie członków organizacji. | `notifications:send` |
| `GENERATE_DOCUMENT` | Wygenerowanie dokumentu z szablonu, który wybiera autor reguły. | `documents:generate` |

Każdy inny typ kroku, np. dołączanie plików, wywołanie innej reguły albo uruchomienie obiegu, zostaje odrzucony. Taka praca należy do reguły organizacji, która używa twojego kroku.

## Z edytora reguł do pliku reguły [#from-the-rule-builder-to-a-rule-file]

Możesz najpierw zbudować logikę w edytorze reguł, wyeksportować regułę jako JSON i wkleić ją do pliku reguły, bo JSON jest poprawnym YAML-em. Potem:

<Steps>
<Step>
Usuń `name`, `description`, `trigger` i każdy inny klucz poza `entryStepId`, `steps` i `edges`.
</Step>
<Step>
Zamień UUID kroków na krótkie lokalne id, w krokach i w krawędziach.
</Step>
<Step>
Zamień wpisane na stałe dane uwierzytelniające na `{{ connection.<field> }}`.
</Step>
<Step>
Krokowi, który tworzy wynik, nadaj `contextKey: output`.
</Step>
</Steps>

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `rule.invalid` | Klucz inny niż `entryStepId`, `steps` i `edges`, `steps` albo `edges`, które nie są listą, krok bez `type` albo krawędź, która nie jest obiektem. | Zostaw tylko te trzy klucze, w pokazanym kształcie. |
| `rule.invalid_step_id` | Id kroku, które jest UUID albo zawiera inne znaki. | Użyj krótkiej lokalnej nazwy. |
| `rule.duplicate_step_id` | Dwa kroki o tym samym id. | Zmień jedno z nich. |
| `rule.unknown_step` | `entryStepId` albo krawędź wskazuje krok, którego nie ma w pliku. | Popraw id. |
| `rule.file_reference_misplaced` | `$file` gdziekolwiek poza `code` kroku `RUN_SCRIPT`. | Przenieś skrypt do kroku `RUN_SCRIPT`. |
| `rule.host_not_literal` | URL kroku **Wywołaj webhook**, który nie zaczyna się od `https://` albo którego host jest szablonem lub ma port czy nazwę użytkownika. | Wpisz host wprost. |
| `rule.host_not_declared` | Host kroku **Wywołaj webhook**, którego brak w `permissions.network`. | Dodaj host z powodem. |
| `rule.own_filter_unsupported` | Szablon w regule używa jednego z filtrów tej paczki. | Wykonaj przekształcenie w skrypcie. |
| `rule.connection_unsupported` | `{{ userConnection.<field> }}` w paczce bez połączenia członka. | Dodaj `connection/member.yaml` albo użyj `connection.*`. |
| `step.type_not_allowed` | Typ kroku spoza powyższych list. | Przenieś tę pracę do reguły, która używa twojego kroku. |
| `manifest.missing_file` | `run` wskazuje plik reguły, którego nie ma w folderze akcji. | Dodaj plik albo popraw nazwę. |
| `script.invalid_path`, `script.missing_file` | `$file` nie wskazuje pliku `.js` ani `.ts` w folderze akcji. | Zobacz [Skrypty](/docs/pl/extensions/reference/scripts#problems). |

Kody sekretów w regule (`connection.*`) opisuje strona [Połączenie i sekrety](/docs/pl/extensions/reference/connection-and-secrets), a kody kroków danych (`step.scope_missing`, `step.target_not_own`, `step.target_not_literal`, `step.config_not_allowed`) strona [Kroki danych](/docs/pl/extensions/reference/data-steps).
