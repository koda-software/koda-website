Paczka to folder z `extension.yaml` na górze i jednym folderem na każdą funkcję. Do paczki należy tylko to, co wymienia manifest.

<Files>
  <Folder name="your-extension" defaultOpen>
    <File name="extension.yaml" />
    <File name="settings.yaml" />
    <Folder name="connection" defaultOpen>
      <File name="connection.yaml" />
    </Folder>
    <Folder name="actions" defaultOpen>
      <Folder name="create-shipment" defaultOpen>
        <File name="action.yaml" />
        <File name="rule.yaml (lub run.js / run.ts)" />
        <File name="tests.yaml" />
      </Folder>
    </Folder>
    <Folder name="filters" defaultOpen>
      <Folder name="tracking-url" defaultOpen>
        <File name="filter.yaml" />
        <File name="filter.js" />
      </Folder>
    </Folder>
    <Folder name="locales" defaultOpen>
      <File name="pl.yaml" />
    </Folder>
    <File name="README.md" />
    <Folder name=".github" disabled />
    <Folder name=".opero" disabled />
  </Folder>
</Files>

| Ścieżka | Zawiera |
| --- | --- |
| `extension.yaml` | Tożsamość, wymagania i uprawnienia oraz listy wszystkiego innego. Wymagany. Zobacz [extension.yaml](/docs/pl/extensions/reference/manifest). |
| `actions/<folder>/` | `action.yaml`, plik wskazany w `run` (plik reguły, skrypt albo plik reguły i skrypty, których używają jego kroki), plik lub folder z testami oraz ewentualne pliki schematów. Zobacz [Akcje](/docs/pl/extensions/reference/actions). |
| `filters/<folder>/` | `filter.yaml` i jego skrypt. Zobacz [Filtry](/docs/pl/extensions/reference/filters). |
| `settings.yaml` | Ustawienia rozszerzenia, gdy `extension.yaml` zawiera `settings: settings.yaml`. Zobacz [Ustawienia](/docs/pl/extensions/reference/settings). |
| `connection/` | `connection.yaml`, gdy `extension.yaml` zawiera `connection: connection`. Zobacz [Połączenie i sekrety](/docs/pl/extensions/reference/connection-and-secrets). |
| `<module>/module.yaml` | Grupa funkcji we własnym folderze, dla dużej paczki. Zobacz [Moduły](#modules). |
| `locales/<lang>.yaml` | Jedno tłumaczenie na każdy język z listy `locales`. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/translations). |
| Wszystko inne | README, changelog, licencja, pliki CI, ustawienia edytora: pomijane i niepakowane. |

<Callout type="warn">
Plik deskryptora (`action.yaml`, `filter.yaml` itd.), którego nie wymienia żadna lista, zostaje odrzucony z kodem `layout.unlisted_feature`. Dodaj jego folder do listy albo go usuń. To samo dotyczy pliku `settings.yaml`, którego nie wskazuje `extension.yaml`.
</Callout>

## Nazwy

- Każdy plik używany przez paczkę ma ścieżkę małymi literami: litery, cyfry, `.`, `_` i `-`.
- Nazwy deskryptorów są stałe. Nazwy folderów wybierasz sam i nigdy nie stają się identyfikatorami, więc możesz zmienić nazwę folderu bez psucia czegokolwiek, co korzysta z danej funkcji.

## Zasady YAML

YAML jest czytany ściśle:

- jeden dokument na plik, UTF-8;
- bez kotwic, aliasów, tagów, kluczy scalania i powtórzonych kluczy.

JSON jest poprawnym YAML-em, więc regułę wyeksportowaną z edytora reguł możesz wkleić bez zmian.

## Moduły [#modules]

Duża paczka może grupować funkcje w folderach modułów. Każdy folder modułu zawiera `module.yaml`:

```yaml title="billing/module.yaml"
module: billing
name: Billing
description: Invoice and payment steps.
actions:
  - actions/create-invoice
  - actions/send-invoice
filters:
  - filters/invoice-number
```

| Klucz | Znaczenie |
| --- | --- |
| `module` | Klucz modułu. |
| `name` | Jego nazwa. |
| `description` | Opcjonalny. |
| `actions`, `filters` | Jego własne listy, względem folderu modułu. |

`extension.yaml` wskazuje folder modułu w `include`. Moduły mają tylko jeden poziom zagnieżdżenia.

```yaml title="extension.yaml"
include:
  - billing
```
