Paczka może przynieść ekrany, na których pracują członkowie: **formularze** na własnych obiektach, **listy własne** (Custom Lists), które wyświetlają rekordy, i **strony obszaru roboczego**, które łączą listy, formularze, bloki i liczniki. Są instalowane jako formularze dynamiczne, listy własne i strony własne (Custom Pages) organizacji, tylko do odczytu i zarządzane przez rozszerzenie. Paczka niczego nie umieszcza w menu: administrator dodaje jej strony do menu ręcznie.

```yaml title="extension.yaml"
  - lists/open-orders
  - lists/order-lines
  - lists/suppliers

  - pages/orders

```

Wpisz foldery na listach `forms`, `lists` i `pages` w `extension.yaml` albo w `module.yaml` dołączonego modułu. `opero-ext add form <name> --object <object>`, `add list <name> [--object <object>]` i `add page <name>` zapisują folder startowy i dopisują go do listy; zobacz [Narzędzie wiersza poleceń](/docs/pl/extensions/reference/cli#options).

## form.yaml [#formyaml]

Formularz to formularz dynamiczny na jednym z własnych [obiektów](/docs/pl/extensions/reference/objects) paczki: ekran, który otwiera, edytuje albo tworzy jego rekordy.

```yaml title="forms/order/form.yaml"
form: order                      # referenced as orders.order
object: orders
name: Order
types: [view, edit, create]
default: [view, edit, create]    # claims the object's slots when they are empty
config:
  title: New order
  successMessage: Saved
layout: layout.yaml
```

Układ to dokument układu widoku (View Layout), taki, jaki zapisuje edytor formularzy. Węzły pól podają klucze pól obiektu; bloki, listy, formularze i zapytania paczki wskazuje się [odwołaniami](#references):

```yaml title="forms/order/layout.yaml"
schemaVersion: 2
regions:
  main:
    - id: details
      kind: card
      children:
        - { id: f_title, kind: field, field: { source: dynamic, key: title } }
        - { id: f_status, kind: field, field: { source: dynamic, key: status } }
    - id: summary
      kind: component
      component: custom_block
      config:
        customBlockId: { $ref: "block:order_summary" }
        inputs: { title: "Order {{ record.title }}" }
    - id: lines
      kind: component
      component: layout.customList
      config:
        customListId: { $ref: "list:order-lines" }
        params: { order: "{{ record.id }}" }
```

### Formularze domyślne [#default-forms]

Każdy obiekt ma domyślny formularz do oglądania, edycji i tworzenia rekordów. Formularz z `default` zajmuje każde wskazane miejsce, które jest puste albo zajęte przez formularz tego rozszerzenia. Miejsce, w którym organizacja ustawiła własny formularz, zostaje bez zmian, a plan instalacji to mówi (`form.default_taken`, nie blokuje). Aktualizacja i ponowna instalacja robią to samo: nigdy nie przejmują domyślnego formularza wybranego przez organizację.

## list.yaml [#listyaml]

Lista to lista własna na jednym z obiektów paczki albo na wbudowanym źródle list. Członkowie widzą ją tam, gdzie osadza ją strona albo formularz.

```yaml title="lists/open-orders/list.yaml"
list: open-orders                # installed as x-shop-open-orders
name: Open orders
description: Orders that are not closed yet.
source: { object: orders }
config:
  columns: [{ field: title }, { field: status }]
  baseFilter:
    op: AND
    items: [{ field: status, operator: neq, value: closed }]
  modes: [table]
  views: [{ id: default, name: Default, default: true, config: { schemaVersion: 2 } }]
  builtInActions: [create, open]
  create: { formId: { $ref: "form:orders.order" } }
actions:
  - key: open_in_shop
    type: OPEN_LINK
    label: Open in shop
    config: { url: "https://shop.example.test/orders/{{ row.external_id }}" }
```

```yaml title="lists/suppliers/list.yaml"
list: suppliers
name: Suppliers

```

Czytnik sprawdza budowę i odwołania. To, czy konfiguracja pasuje do źródła (kolumny, filtry i formularz tworzenia), Opero sprawdza tak, jak zrobiłby to zapis samej listy: w planie instalacji (`list.save_validation`), a dla listy na obiekcie, który tworzy ta sama instalacja, przy instalowaniu listy.

### Akcje [#actions]

Lista z paczki ma tylko akcje `OPEN_LINK`, które otwierają adres dla wiersza. Akcja reguły albo skryptu jest odrzucana z kodem `list.action_unsupported`: ich identyfikatory nie mogą podróżować z paczką.

| Klucz | Znaczenie |
| --- | --- |
| `key` | Mała litera, potem małe litery, cyfry i `_`, do 80 znaków. Unikalny w liście. |
| `label` | Do 160 znaków. |
| `type` | `OPEN_LINK`. |
| `isActive` | Opcjonalne. |
| `config.url` | Ścieżka albo adres https na hoście z `permissions.links`, z Liquid nad `row`. Zobacz [Adresy URL](#urls). |
| `config.openIn` | `same_tab` albo `new_tab`. Gdy pominięte, `new_tab`. |
| `config.isDefault` | Opcjonalne. Pokazuje akcję jako skrót wiersza obok menu jego akcji. |

## Odwołania [#references]

Ekran nigdy nie wskazuje niczego identyfikatorem, bo identyfikatory są w każdej organizacji inne. Własne bloki, listy, formularze i zapytania paczki wskazuje odwołaniem, które Opero zastępuje identyfikatorem po instalacji:

```yaml
customListId: { $ref: "list:open-orders" }
```

| Rodzaj | Wskazuje | Przykład |
| --- | --- | --- |
| `block` | [Blok](/docs/pl/extensions/reference/blocks) po nazwie z `block`. | `{ $ref: "block:order_summary" }` |
| `list` | Listę po nazwie z `list`. | `{ $ref: "list:open-orders" }` |
| `form` | Formularz jako `<object>.<form>`. | `{ $ref: "form:orders.order" }` |
| `query` | [Zapytanie](/docs/pl/extensions/reference/queries) po nazwie z `query`. | `{ $ref: "query:open_count" }` |

Odwołanie może stać tylko tam, gdzie Opero przechowuje identyfikator jego rodzaju:

| Gdzie | Rodzaj |
| --- | --- |
| `config.customBlockId` komponentu `custom_block` | `block` |
| `config.customListId` komponentu `layout.customList` | `list` |
| `config.formId` komponentu `page.form` | `form` |
| `config.savedQueryId` komponentu `counter` albo `page.counter` | `query` |
| `owned.rowForms.<operation>` węzła `field` albo `relationTable` | `form` |
| `config.create.formId` listy | `form` |

- Odwołanie w każdym innym miejscu albo niewłaściwego rodzaju dla swojego miejsca jest odrzucane z kodem `layout.ref_position`.
- Odwołanie, które nie ma dokładnie postaci `{ $ref: "<kind>:<name>" }`, to `layout.ref_invalid`.
- Nazwa, której paczka nie ma, to `layout.ref_unknown`.
- Każdy inny klucz z identyfikatorem (reguły, raportu, procesu, kalendarza, listy SQL, pola własnego: każdy klucz kończący się na `Id` albo `Ids`) oraz identyfikator wpisany tam, gdzie należy się odwołanie, są odrzucane z kodem `layout.reference_unsupported`. Pomiń taki klucz albo zostaw go pustym.

Klucze pól i relacji wpisuje się bez zmian: są takie same w każdej organizacji, która instaluje paczkę.

## Adresy URL [#urls]

`url` w układzie, `config.url` akcji listy i `config.redirectUrl` formularza muszą być albo ścieżką Opero zaczynającą się od `/`, albo adresem https, którego host jest wpisany wprost i wymieniony w [`permissions.links`](/docs/pl/extensions/reference/manifest#link-hosts-page-scripts-and-company-permissions). Liquid może uzupełnić ścieżkę, nigdy host. Wszystko inne jest odrzucane z kodem `layout.host_not_declared`. Host, który otwierają ekrany, liczy się jako używany, więc nie potrzebuje linku rekordu.

## Tłumaczenia [#translations]

| Klucz | Tłumaczy |
| --- | --- |
| `pages.<page>.title`, `description` | Tytuł i opis strony. Są instalowane razem ze stroną. |
| `forms.<object>.<form>.config.title`, `successMessage` | Tytuł i komunikat po zapisie formularza. `validate` je sprawdza, ale formularz jest instalowany z tekstami angielskimi. |

```yaml title="locales/pl.yaml"
pages:
  orders:
    title: Zamówienia
    description: Otwarte zamówienia i ich liczba.
forms:
  orders:
    order:
      config:
        title: Nowe zamówienie
        successMessage: Zapisano
```

Nazwy formularzy, nazwy i opisy list, etykiety kolumn i etykiety akcji są tylko po angielsku.

## Po instalacji [#after-install]

- **Tylko do odczytu.** Formularze, ich układy, listy i strony są zarządzane przez rozszerzenie. Zmiana albo usunięcie formularza, zapis, publikacja albo przywrócenie układu formularza lub strony z paczki, zapis, archiwizacja albo przywrócenie listy oraz zmiana, publikacja albo archiwizacja strony są odrzucane z kodem `EXTENSION_MANAGED_ASSET`. Zmieniają się tylko przy aktualizacji rozszerzenia.
- **Nadal należy do organizacji.** To, kto może używać każdego formularza (jego dostęp i dostęp z portalu), domyślne formularze obiektu, to, które firmy i którzy członkowie widzą stronę, oraz menu. Aktualizacja nigdy tego nie zmienia.
- **Kto je widzi.** Nowa strona jest udostępniona każdej firmie i każdemu członkowi zaraz po instalacji. Formularzy można używać wszędzie tam, gdzie udostępniony jest moduł rozszerzenia `x-<key>`, czyli w każdej firmie, dopóki administrator tego nie zawęzi. Listy nie mają własnego udostępnienia: członkowie widzą listę tam, gdzie osadza ją strona albo formularz. Plan instalacji mówi, co zobaczą członkowie, i że strony trzeba dodać do menu ręcznie.
- **Zastrzeżone nazwy.** Organizacja nie może utworzyć listy własnej z kluczem zaczynającym się od `x-` ani utworzyć strony ze slugiem zaczynającym się od `x-` lub zmienić slugu na taki (`CUSTOM_LIST_KEY_RESERVED`, `CUSTOM_PAGE_SLUG_RESERVED`).
- **Sprawdzane przed instalacją.** Plan instalacji sprawdza każdy formularz, układ i listę tak, jak zrobiłby to ich własny zapis, i blokuje przy problemie (`form.save_validation`, `layout.save_validation`, `list.save_validation`).
- **Uprawnienia.** Instalacja formularzy wymaga `org.customModules.create` i `org.customModules.update`, list `org.customLists.create` i `org.customLists.update`, a stron `org.pages.create` i `org.pages.update`. Ich usunięcie wymaga `org.customModules.delete`, `org.customLists.update` i `org.pages.delete`.
- **Wyłączone.** Wyłączenie rozszerzenia nie zmienia niczego, co się wyświetla: formularze, listy i strony działają dalej. Akcje rozszerzenia umieszczone w nich przestają działać, dopóki rozszerzenie znów nie działa.
- **Aktualizacja.** Zmieniony układ formularza albo strony jest publikowany jako nowa wersja, a zmieniona lista jest zapisywana w miejsce starej. Wersja, która pomija formularz, usuwa go: jego domyślne miejsca przechodzą na inny formularz rozszerzenia tego samego typu albo zostają puste. Pominięcie formularza, który wskazują układy, listy albo bloki organizacji, daje ostrzeżenie (`form.in_use`), a pominięcie ostatniego formularza danego typu na obiekcie - ostrzeżenie `object.formless`. Pominięta lista albo strona jest archiwizowana; plan ostrzega, gdy listę osadzają układy organizacji (`list.in_use`) albo stronę otwierają jej menu (`page.in_use`). Żadne z nich nie blokuje.

## Odinstalowanie [#uninstall]

Odinstalowanie usuwa ekrany niezależnie od wyboru dotyczącego danych:

- **Formularze są usuwane** razem z układami i dostępem. Nic nie jest generowane w ich miejsce. Domyślne miejsca, które zajmowały, są najpierw zwalniane; miejsc zajętych przez własne formularze organizacji to nie dotyczy.
- **Listy i strony są archiwizowane** jako usunięte przez rozszerzenie. Osadzona taka lista pokazuje, że usunęło ją rozszerzenie. Pozycja menu, która otwiera taką stronę, zostaje i jest ukryta. Organizacja nie może przywrócić listy (`CUSTOM_LIST_EXTENSION_REMOVED`) ani strony.
- Przy **Usuń dane** listy na obiektach paczki są usuwane razem z obiektami; lista na wbudowanym źródle jest archiwizowana.

<Callout type="warn" title="Obiekty bez formularza">
Gdy dane zostają, obiekt może zostać bez formularza do oglądania, edycji albo tworzenia rekordów. Dopóki administrator go nie zbuduje, rekordów nie da się otworzyć (`DYNAMIC_FORM_ACCESS_DENIED`) ani utworzyć. Przed potwierdzeniem odinstalowanie wymienia każdy taki obiekt z liczbą rekordów i tym, co zrobić: otwórz obiekt w Obiektach, utwórz formularz (zaczyna się ze wszystkimi polami), ustaw go jako domyślny i ustaw jego dostęp.
</Callout>

**Ponowna instalacja** przywraca te same listy i strony pod tymi samymi identyfikatorami, z udostępnieniem firmom i odbiorcami, jakie zostawiła organizacja, a ich pozycje menu znów są widoczne. Formularze są tworzone od nowa i zajmują domyślne miejsca, które nadal są puste.
