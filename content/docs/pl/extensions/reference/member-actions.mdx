---
title: Akcje bloków i polecenia rekordów
description: Pozwól członkom samodzielnie uruchamiać akcje paczki, przyciskiem w bloku albo poleceniem na rekordzie, przez expose.blockAction i expose.recordCommand.
---

Krok reguły jest dla osób, które budują reguły. Akcję można też udostępnić członkom organizacji, którzy uruchamiają ją sami, tak jak w przewodniku [Blok, przycisk i link](/docs/pl/extensions/blocks-and-actions):

| Udostępnienie | Członkowie uruchamiają ją z | Działa dla |
| --- | --- | --- |
| `expose.blockAction` | Przycisku w jednym z [bloków](/docs/pl/extensions/reference/blocks#buttons-that-run-actions) paczki. | Rekordu, który pokazuje strona, albo bez rekordu na stronie własnej. |
| `expose.recordCommand` | Akcji rekordu, którego dotyczy: obiektu paczki albo rekordu wbudowanego, na przykład kontrahenta. | Tego rekordu. |

W obu przypadkach akcja działa jako członek, który ją uruchomił. Jedna akcja może być jednocześnie akcją bloku, poleceniem rekordu i krokiem reguły.

```yaml title="actions/track-parcel/action.yaml"
action: track_parcel
label: Track parcel
description: Asks the carrier where the parcel is and returns its status.

output:
  message: { type: text, label: Message }
  status: { type: text, label: Carrier status }
  scannedAt: { type: text, label: Last scan }

run: rule.yaml
tests: tests.yaml

expose:
  blockAction: { permission: track }
  recordCommand:
    permission: track
    targets: [{ object: parcels }]
    icon: truck
    confirm: { title: Track parcel, message: Ask the carrier where this parcel is? }
    result: { message: message, details: [status, scannedAt] }
```

Akcja udostępniona członkom potrzebuje `description`, a każde udostępnienie wskazuje [uprawnienie paczki](/docs/pl/extensions/reference/package-permissions), które członkowie muszą mieć.

Formularz polecenia to pola wejścia akcji; akcja bez wejścia działa, gdy tylko członek potwierdzi. Polecenie pojawia się tylko na rekordach, których dotyczy, i nie ma go w zewnętrznym API ani w MCP. Jego klucz, `x-<key>.<action>`, można ukryć na etapie procesu jak każdą akcję rekordu.

## Rekord, dla którego działa akcja [#the-record-the-action-runs-for]

Akcja dostaje rekord przez odwołanie, a nie jego wartości:

| Napisz | Żeby dostać |
| --- | --- |
| `{{ trigger.record.id }}` | Identyfikator rekordu. |
| `{{ trigger.record.type }}` | `custom_record` dla rekordu obiektu; `contractor`, `sales_invoice`, `cost_invoice`, `budget` albo `helpdesk_ticket` dla rekordu wbudowanego. |
| `{{ trigger.record.moduleKey }}`, `{{ trigger.record.objectKey }}` | Dla rekordu obiektu: `x-<key>` i klucz obiektu. |

Skrypt dostaje to samo jako `record` w argumencie albo `null`, gdy akcja działa bez rekordu. Żeby odczytać wartości rekordu, pobierz go krokiem [`FETCH_RECORDS`](/docs/pl/extensions/reference/data-steps#fetch-records).

```yaml title="actions/track-parcel/rule.yaml"
entryStepId: ask
steps:
  - id: ask
    type: CALL_WEBHOOK
    name: Ask the carrier
    contextKey: asked
    config:
      url: "https://api.example.com/v1/parcels?reference={{ trigger.record.id }}"
      method: GET
  - id: answer
    type: RUN_SCRIPT
    name: Answer
    contextKey: output
    config:
      code: { $file: answer.js }
edges:
  - { fromStepId: ask, toStepId: answer }
```

## Co dostaje członek [#what-the-member-gets-back]

| Uruchomione z | Po sukcesie |
| --- | --- |
| Bloku | Tekst `message` z wyjścia jest pokazywany członkowi. Blok dostaje całe wyjście w zdarzeniu `opero:action-done`, a potem się odświeża. |
| Polecenia rekordu | Pole `result.message` jest pokazywane jako komunikat, a pod nim pola `result.details`, każde z etykietą wyjścia w języku członka. |

Gdy akcja się nie powiedzie, członek widzi jej komunikat, który nigdy nie cytuje odpowiedzi usługi. Uruchomienie dłuższe niż 15 sekund jest zgłaszane jako wciąż trwające; nie jest przerywane.

## Kto może ich używać [#who-may-use-them]

Każda akcja bloku, polecenie rekordu i [link do rekordu](/docs/pl/extensions/reference/record-links) są sprawdzane w tej kolejności, za każdym razem, gdy są pokazywane, i ponownie przy użyciu:

1. **Rozszerzenie działa**: jest włączone, ma kompletne ustawienia i włączone połączenie.
2. **Jest udostępnione firmie członka.** Po instalacji każda akcja bloku, polecenie i link są udostępnione wszystkim firmom.
3. **Członek jest w jego grupie odbiorców.** Po instalacji to każdy członek.
4. **Członek ma jego uprawnienie paczki**, `company.x-<key>.<name>`, przez jedną ze swoich ról.

Organizacja może osobno zawęzić firmy i odbiorców każdego z nich, a aktualizacja zachowuje te wybory. Polecenie albo link, które nie przejdą sprawdzenia, w ogóle nie są pokazywane, nigdy jako wyłączone. Blok dostaje `false` w `extension_actions` dla akcji bloku, której oglądający nie może uruchomić.

## Testy [#tests]

Przypadek testowy takiej akcji podaje rekord w `record`: `type`, `id`, a dla `custom_record` obiekt paczki jako `object`. Zobacz [Testy](/docs/pl/extensions/reference/tests#a-test-case).

```yaml title="actions/track-parcel/tests.yaml"
- name: the carrier's status comes back
  record: { type: custom_record, id: rec-1, object: parcels }
  http:
    - request:
        method: GET
        url: https://api.example.com/v1/parcels?reference=rec-1
      response:
        status: 200
        body: { status: in_transit, scannedAt: "2026-11-12T08:30:00Z" }
  returns:
    message: "The carrier says: in_transit."
    status: in_transit
    scannedAt: "2026-11-12T08:30:00Z"
```

## Czego te akcje nie mogą robić [#what-these-actions-cannot-do]

| Akcja, która | Nie może być akcją bloku ani poleceniem rekordu | Kod |
| --- | --- | --- |
| Zgłasza zdarzenia krokiem `EMIT_EVENT` | Zdarzenia pochodzą tylko z harmonogramów i haków połączenia członka. | `event.emitted_from_step` |
| Używa `{{ userConnection.<field> }}` | Wartości członka istnieją tylko w uruchomieniach członka. | `action.member_outside_member_run` |
| Jest uruchamiana przez harmonogram | Akcja harmonogramu nie jest udostępniana. | `schedule.action_exposed` |

Polecenie zawsze działa, gdy członek czeka; nic nie działa w tle.

## Gdy uruchomienie członka zostaje odrzucone [#when-a-members-run-is-refused]

Ekrany pokazują je członkowi; kody mają znaczenie, gdy czytasz API.

| Kod | Kiedy |
| --- | --- |
| `EXTENSION_INACTIVE` (409) | Akcja bloku rozszerzenia, które nie działa. |
| `EXTENSION_ACTION_FORBIDDEN` (403) | Członek jest spoza grupy odbiorców albo nie ma uprawnienia paczki. `meta.reason` mówi, które z nich. |
| `block_action_unavailable` (404) | Akcji bloku nie ma na stronie członka w postaci, w jakiej się dla niego renderuje, nie jest udostępniona jego firmie albo zainstalowana wersja już jej nie ma. |
| `ENTITY_ACTION_NOT_FOUND` (404) | Polecenie rekordu nie jest już dostępne dla członka, na przykład dlatego, że rozszerzenie wyłączono. |
| `ENTITY_ACTION_DISABLED` (409) | Polecenie z `editGated` na rekordzie, który na swoim etapie jest tylko do odczytu. |
| `EXTENSION_ACTION_INPUT_INVALID` (400) | Wejście nie pasuje do pól wejścia akcji. |
| `EXTENSION_ACTION_RATE_LIMITED` (429) | Usługa odpowiedziała `429`. Zawiera `retryAfterSeconds`, gdy usługa go podała. |
| `EXTENSION_ACTION_FAILED`, `EXTENSION_ACTION_OUTPUT_INVALID` (422) | Akcja zadziałała i się nie powiodła albo zwróciła wyjście niepasujące do jej pól wyjścia. |
| `ENTITY_ACTION_TIMEOUT` (504) | Brak odpowiedzi w ciągu 15 sekund. Uruchomienie trwa dalej. |

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `action.invalid` | Akcja udostępniona członkom bez `description` albo klucz udostępnienia o złej strukturze. | Dodaj opis; popraw klucz wskazany w komunikacie. |
| `action.permission_undeclared` | `permission` nie wskazuje niczego w `permissions.company`. | Zadeklaruj uprawnienie albo popraw nazwę. |
| `action.record_command_invalid` | Polecenie rekordu bez celu albo z więcej niż 20 celami. | Wskaż od 1 do 20 celów. |
| `action.record_command_unknown_target` | Cel obiektu, który nie jest obiektem paczki. | Popraw klucz albo dodaj obiekt. |
| `action.record_command_unknown_field` | `result` wskazuje pole, które nie jest polem wyjścia akcji. | Wskaż pole wyjścia. |
| `event.emitted_from_step` | Akcja, która zgłasza zdarzenia, jest udostępniona. | Zgłaszaj zdarzenia z akcji harmonogramu. |
| `action.member_outside_member_run` | Akcja, która używa wartości członka, jest udostępniona. | Uruchamiaj ją z haka albo harmonogramu połączenia członka. |
| `schedule.action_exposed` | Akcja harmonogramu jest udostępniona. | Daj harmonogramowi własną akcję. |
