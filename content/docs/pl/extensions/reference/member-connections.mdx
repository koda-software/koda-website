title: Połączenia członków
description: Pozwól każdemu członkowi połączyć przez OAuth własne konto w twojej usłudze dzięki connection/member.yaml i uruchamiaj akcje z jego tokenem.
---

Połączenie członka pozwala każdemu członkowi organizacji połączyć własne konto w usłudze zewnętrznej przez OAuth. Akcje paczki wywołują wtedy usługę z tokenem tego członka, wyłącznie dla niego, zwykle z [harmonogramu](/docs/pl/extensions/reference/schedules), który odczytuje nowe dane każdego członka i [zgłasza zdarzenia](/docs/pl/extensions/reference/raising-events). Takie połączenie buduje przewodnik [Dane z konta każdego członka](/docs/pl/extensions/member-accounts).

```yaml title="connection/member.yaml"
label: Sandbox account
description: Sends your sandbox activities to your company's rules.
oauth:
  authorize: https://auth.example.com/oauth2/authorize
  token: https://api.example.com/oauth2/token
  scopes: [activities.read]
  clientAuth: basic
  pkce: false
  client: { id: clientId, secret: clientSecret }
config:
  companyId: { type: company, label: Company receiving your data, required: true }
data:
  - Activities
afterConnect:
  action: register_member
  output:
    sandboxUserId: meta
    signingKey: secret
  failures:
    "403":
      name: consents_missing
      message: Accept every data consent in the sandbox, then connect again.
    "409": already_registered
beforeDisconnect:
  action: deregister_member
```

Należy do [połączenia](/docs/pl/extensions/reference/connection-and-secrets) paczki: `connection.yaml` wskazuje je wpisem `member: member.yaml`, jedyną dopuszczalną wartością, a administrator organizacji wpisuje tam klienta OAuth. Paczka ma najwyżej jedno połączenie członka.

## OAuth [#oauth]

Członkowie łączą się przepływem OAuth z kodem autoryzacji; inne sposoby logowania członków nie są obsługiwane.

| Zasada | Szczegóły |
| --- | --- |
| Oba adresy są wpisane wprost | Bez szablonu, portu ani nazwy użytkownika, a oba hosty są w `permissions.network`, więc administrator widzi je przed instalacją. |
| Klient należy do organizacji | `client` wskazuje dwa pola danych uwierzytelniających jednej metody połączenia. Administrator wpisuje je w formularzu połączenia. |
| Zarejestruj Opero u dostawcy | Klient OAuth musi akceptować adres zwrotny połączeń członków danej instalacji Opero. Zapytaj o niego administratora instalacji. |
| Co jest przechowywane | Token dostępu, token odświeżania i czas wygaśnięcia, gdy dostawca je przyśle, zaszyfrowane. Niczego nie da się odczytać z powrotem. |
| Bez odświeżania tokenu | Opero nie odnawia tokenu dostępu. Gdy dostawca przestanie go akceptować, członek łączy się ponownie; zobacz [Odrzucony token](#a-refused-token). |

## Formularz członka [#the-members-form]

`config` to [lista pól](/docs/pl/extensions/reference/actions#field-lists) bez sekretów: formularz, który każdy członek wypełnia dla swojego połączenia. Jego wartości trafiają do akcji jako `config`.

Jedno pole może mieć typ `company`, na najwyższym poziomie listy. Członek wybiera jedną ze swoich firm i staje się ona firmą jego uruchomień: w niej działają uruchomienia harmonogramu i akcje haków, w niej pracują kroki danych i do niej trafiają zgłaszane zdarzenia. Typ `company` jest dozwolony tylko tutaj.

## Połączenie: afterConnect [#connecting-afterconnect]

Gdy członek wyrazi zgodę u dostawcy, a Opero ma jego token, Opero uruchamia akcję `afterConnect`. Użyj jej, żeby zarejestrować członka w usłudze i zachować to, czego potrzebują późniejsze uruchomienia, na przykład identyfikator tego członka w usłudze.

```yaml title="actions/register-member/rule.yaml"
entryStepId: register
steps:
  - id: register
    type: CALL_WEBHOOK
    name: Register
    contextKey: registered
    config:
      method: POST
      url: https://api.example.com/v1/users
      headers: { Authorization: "Bearer {{ userConnection.accessToken }}" }
      body: { memberId: "{{ trigger.data.credentialId }}" }
  - id: keep
    type: SAVE_TO_CONTEXT
    name: Keep the ids
    contextKey: output
    config:
      value:
        sandboxUserId: "{{ registered.body.id }}"
        signingKey: "{{ registered.body.signingKey }}"
edges:
  - { fromStepId: register, toStepId: keep }
```

Wejście akcji:

| Pole | Wartość |
| --- | --- |
| `credentialId` | Identyfikator połączenia członka. |
| `token.scopes`, `token.expiresAt` | Co przyznał dostawca i do kiedy, jeśli to podaje. |
| `token.extra` | Inne zwykłe wartości z odpowiedzi tokenu, na przykład identyfikator użytkownika u dostawcy. Wartości, których nazwa zawiera `token`, `secret`, `password` albo `key`, są pomijane. |
| `config` | Formularz członka. |

Token dostępu nigdy nie jest częścią wejścia: reguła wysyła go przez `{{ userConnection.accessToken }}`.

`output` mówi, jak każde pole wyjścia akcji jest przechowywane z połączeniem. Pola wyjścia, których `output` nie wymienia, nie są przechowywane.

| `output` | Przechowywane | Odczytywane jako |
| --- | --- | --- |
| `<field>: secret` | Zaszyfrowane, nigdy nie pokazywane ani nie odczytywane z powrotem. | `{{ userConnection.<field> }}` w późniejszych akcjach członka. |
| `<field>: meta` | Jako publiczna informacja o połączeniu, widoczna dla członka. | `subject.meta` w każdym uruchomieniu harmonogramu, `meta` w `beforeDisconnect`. |

## Niepowodzenia [#failures]

Gdy `afterConnect` się nie powiedzie, połączenie się nie udaje i nic nie jest zapisywane. `failures` przypisuje nazwę statusowi HTTP nieudanego żądania, zapisanemu w cudzysłowie i z zakresu `4xx` albo `5xx`:

| Zapis | Kod niepowodzenia | Co widzi członek |
| --- | --- | --- |
| `"409": already_registered` | `x-<key>.member.already_registered` | Ogólny komunikat Opero, że połączenie się nie udało. |
| `"403": { name: consents_missing, message: … }` | `x-<key>.member.consents_missing` | Ten komunikat, przetłumaczony. Jedna nazwa ma jeden komunikat. |
| Status, którego `failures` nie wymienia | Ogólne niepowodzenie połączenia Opero | Ogólny komunikat. Odpowiedź dostawcy nigdy nie jest pokazywana. |

Żeby zamiast tego potraktować status jako sukces, na przykład `409` dla członka, który jest już zarejestrowany, podłącz port błędu kroku webhooka (`branchKey: error`), sprawdź tam `{{ error.httpStatus }}` i zakończ akcję z tej gałęzi.

## Rozłączenie: beforeDisconnect [#disconnecting-beforedisconnect]

`beforeDisconnect` działa przed usunięciem połączenia członka: gdy członek się rozłącza, gdy opuszcza organizację i dla każdego członka przy odinstalowaniu rozszerzenia. Użyj go, żeby wyrejestrować członka z usługi.

Jego wejście to `{ meta, config }`, a `{{ userConnection.<field> }}` nadal daje wartości członka. Działa w miarę możliwości: gdy się nie powiedzie, połączenie i tak jest usuwane. Podczas odinstalowania połączenie organizacji jest już wyłączone, więc używaj tam tylko wartości członka.

## Wartości członka w regułach [#the-members-values-in-rules]

Plik reguły zapisuje sekrety członka jako `{{ userConnection.<field> }}`, ze wszystkimi zasadami [sekretów połączenia](/docs/pl/extensions/reference/connection-and-secrets#secrets):

| Pole | Wartość |
| --- | --- |
| `accessToken` | Token dostępu członka. |
| `refreshToken` | Token odświeżania, jeśli dostawca go przysłał. |
| Wyjście `secret` z `afterConnect` | Ta zapisana wartość. |

Akcja, której reguła używa `{{ userConnection.<field> }}`, to **akcja członka**. Działa tylko dla jednego członka, z jego wartościami, z haka `afterConnect` lub `beforeDisconnect` albo z harmonogramu `forEach: userConnection`. Nigdy nie jest krokiem reguły, akcją bloku, poleceniem rekordu ani akcją weryfikującą. W przypadku testowym podaj wartości w `userConnection`; zobacz [Testy](/docs/pl/extensions/reference/tests#member-actions).

## Odrzucony token [#a-refused-token]

Gdy żądanie z tokenem członka dostanie w uruchomieniu harmonogramu odpowiedź `401`, uruchomienie kończy się jako cofnięte dane uwierzytelniające (`EXTENSION_ACTION_CREDENTIAL_REVOKED`). Dla tego członka nic więcej nie jest uruchamiane i jest on proszony o ponowne połączenie; gdy to zrobi, jego uruchomienia ruszają w ciągu minuty.

`401` na żądanie, które niosło tylko połączenie organizacji, to zwykłe niepowodzenie: uwagi wymaga połączenie administratora. `401` podczas łączenia członka to niepowodzenie połączenia.

## Aktualizacje [#upgrades]

| Zmiana w nowej wersji | Co się dzieje | Kod |
| --- | --- | --- |
| Dodano zakres OAuth | Każdy połączony członek jest proszony o ponowne połączenie i nic nie działa dla niego, dopóki tego nie zrobi. Ostrzeżenie. | `member.reconsent_required` |
| Zmienił się host `authorize` albo `token` | To samo. | `member.reconsent_required` |
| `afterConnect` zapisuje nowe wyjście | To samo. | `member.reconsent_required` |
| Usunięto zakres albo zmieniła się ścieżka lub `clientAuth` | Członkowie pozostają połączeni. | |

Co widzą administrator i członkowie, opisują strony [Aktualizacja i odinstalowanie](/docs/pl/extensions/upgrade-and-uninstall#what-a-new-version-can-change) i [Co robią członkowie](/docs/pl/extensions/member-accounts#what-members-do).

## Tłumaczenia [#translations]

Teksty trafiają do `member`: `label`, `description`, każdy tekst `data` według pozycji (`member.data."0"`), `failures.<name>` i `config.<field>`. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/translations#translatable-keys).

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `member.invalid` | Nieznany klucz, brak `label`, `oauth` lub `afterConnect`, adres niewpisany w całości, akcja haka udostępniona jako krok reguły, pole `output`, którego akcja nie zwraca, dwa pola firmy albo jedna nazwa niepowodzenia z dwoma komunikatami. | Popraw klucz wskazany w komunikacie. |
| `member.host_not_listed` | Hosta `authorize` albo `token` nie ma w `permissions.network`. | Dodaj oba hosty z powodem. |
| `member.client_field_unknown` | `oauth.client` nie wskazuje dwóch pól danych uwierzytelniających jednej metody połączenia. | Wskaż pola identyfikatora i sekretu metody. |
| `member.action_unknown` | Hak wskazuje akcję, której paczka nie ma. | Popraw nazwę albo dodaj akcję. |
| `member.requires_connection` | `connection/member.yaml` w paczce, której `extension.yaml` nie ma `connection`. | Dodaj `connection: connection` i jego `connection.yaml`. |
| `layout.unlisted_feature` | `connection/member.yaml`, którego nie wskazuje `connection.yaml`. | Dodaj `member: member.yaml`. |
| `field.invalid` | Pole `company` poza formularzem członka albo pole o złej strukturze. | Trzymaj pola `company` w `config`. |
| `action.member_outside_member_run` | Akcja członka udostępniona jako krok, akcja bloku albo polecenie rekordu, użyta jako akcja weryfikująca albo uruchamiana przez harmonogram, który nie dotyczy członków. | Uruchamiaj ją tylko z haka albo z harmonogramu `forEach: userConnection`. |
| `rule.connection_unsupported` | `{{ userConnection.<field> }}` w paczce bez połączenia członka. | Dodaj `connection/member.yaml` albo użyj `connection.*`. |
| `connection.placeholder_position`, `connection.placeholder_not_bare`, `connection.unknown_field` | Wartość członka poza miejscami, w których może stać sekret, z filtrem albo bez odpowiadającej jej wartości członka. | Zobacz [Połączenie i sekrety](/docs/pl/extensions/reference/connection-and-secrets#problems). |
| `file.yaml_feature_not_allowed` | Status w `failures` zapisany bez cudzysłowu. | Napisz `"403":`. |
