Reguła z paczki zgłasza zdarzenia własnych [wyzwalaczy](/docs/pl/extensions/reference/triggers) paczki krokiem `EMIT_EVENT`. Każdy element listy staje się jednym zdarzeniem, a każde zdarzenie może uruchomić reguły organizacji na tym wyzwalaczu.

```yaml title="actions/sync-orders/rule.yaml"
entryStepId: fetch
steps:
  - id: fetch
    type: CALL_WEBHOOK
    name: Open orders
    contextKey: orders
    config:
      method: GET
      url: "https://api.example.com/v1/orders?company={{ trigger.data.subject.companyId }}&status=open"
  - id: emit
    type: EMIT_EVENT
    name: Raise order events
    contextKey: output
    config:
      event: order_changed
      items: "{{ orders.body.items }}"
      key: number
      dedupe: true
edges:
  - { fromStepId: fetch, toStepId: emit }
```

Nic więcej nie jest przyjmowane (`step.config_not_allowed`). W szczególności krok nie ustawia firmy ani wykonawcy: zdarzenie należy do firmy uruchomienia, które je zgłasza, pochodzi od rozszerzenia i niesie łańcuch reguł tego uruchomienia, więc reguła, która już jest w tym łańcuchu, nie uruchamia się ponownie.

## Elementy [#items]

`items` daje listę. Każdy jej element to obiekt, który musi pasować do `data` wyzwalacza:

- pole, którego lista pól wyzwalacza nie wymienia, jest odrzucane, tak samo jak brak pola wymaganego albo wartość złego typu;
- pole oznaczone `nullable` może mieć wartość `null`;
- jeden element to najwyżej 32 KB JSON.

Gdy odpowiedź usługi nie ma kształtu wyzwalacza, najpierw ją przekształć krokiem **Uruchom skrypt** albo krokami list (`TRANSFORM`, `FILTER` i innymi) i podaj `EMIT_EVENT` wynik.

`key` wskazuje pole, którego wartość identyfikuje element. W każdym elemencie ta wartość musi być tekstem o długości od 1 do 200 znaków albo liczbą.

## Wynik kroku [#the-steps-result]

Krok zwraca `{ emitted, unchanged }`: ile zdarzeń zgłosił i ile elementów pominął, bo się nie zmieniły. Pod kluczem kontekstu `output` staje się wynikiem akcji, jak w przykładzie; pod innym kluczem mogą go odczytać dalsze kroki.

## Deduplikacja [#dedupe]

Bez `dedupe` każdy element jest zgłaszany przy każdym uruchomieniu. Z `dedupe: true` i `key`:

- Element jest zgłaszany, gdy Opero nie pamięta jego klucza albo gdy jego treść różni się od tej, która ostatnio została zgłoszona pod tym kluczem. Wtedy zostaje zapamiętany.
- Element jest **niezmieniony**, gdy wszystkie jego dane są takie same jak przy ostatnim zgłoszeniu pod tym kluczem. Kolejność pól nie ma znaczenia; każda inna różnica, nawet w polu, którego reguły nie czytają, liczy się jako zmiana.
- Pamięć jest osobna dla każdego podmiotu uruchomienia: instalacji, jednej firmy albo jednego połączonego członka. Ten sam klucz w dwóch firmach to dwa elementy.
- Klucz, który powtarza się w jednym kroku, jest porównywany z tym, co ten krok właśnie zgłosił.
- Jak długo element jest pamiętany, mówi [`dedupe.retentionDays`](/docs/pl/extensions/reference/triggers#dedupe-retention) wyzwalacza.

`dedupe: true` bez `key` jest odrzucane z kodem `event.key_required`.

## Dostarczane co najmniej raz [#delivered-at-least-once]

Przy deduplikacji Opero najpierw zgłasza zdarzenie, a dopiero potem je zapamiętuje. Jeśli coś przerwie pracę pomiędzy, następne uruchomienie zgłosi ten sam element jeszcze raz. Bez deduplikacji każde uruchomienie i tak zgłasza każdy element. Reguły organizacji na wyzwalaczu powinny więc być napisane tak, żeby dwukrotne otrzymanie zdarzenia nie szkodziło: znajdź rekord po kluczu elementu i zaktualizuj go albo utwórz, gdy go brakuje.

## Gdzie wolno go używać [#where-it-may-be-used]

`EMIT_EVENT` działa tylko w uruchomieniach, które Opero rozpoczyna dla samego rozszerzenia:

| Akcję, która go używa, uruchamia | Dozwolone |
| --- | --- |
| [Harmonogram](/docs/pl/extensions/reference/schedules) | Tak |
| Akcja `afterConnect` albo `beforeDisconnect` [połączenia członka](/docs/pl/extensions/reference/member-connections) | Tak |
| Reguła organizacji, jako krok reguły (`expose.ruleStep`) | Nie: `event.emitted_from_step` |
| **Sprawdź połączenie** w połączeniu (`verify`) | Nie: `event.emitted_from_step` |

- Akcja, której reguła używa `EMIT_EVENT`, nigdy więc nie jest udostępniana jako krok. Zobacz [Akcje](/docs/pl/extensions/reference/actions).
- Własne reguły organizacji nie mogą używać `EMIT_EVENT`: edytor reguł go nie oferuje, a zapis reguły, która go zawiera, jest odrzucany (`step_type_managed_only`).
- Akcja, która go używa, potrzebuje co najmniej jednego przypadku testowego wymieniającego oczekiwane zdarzenia (`test.event_untested`). Zobacz [Testy](/docs/pl/extensions/reference/tests#events).

## Limity i błędy [#limits-and-failures]

| Co | Limit |
| --- | --- |
| Elementy w jednym kroku | 500 |
| Zdarzenia w jednym uruchomieniu | 2000 |
| Jeden element | 32 KB JSON |

Każdy element jest sprawdzany, zanim którykolwiek zostanie zgłoszony. Gdy sprawdzenie się nie powiedzie, krok kończy się błędem, niczego nie zgłasza, a uruchomienie zatrzymuje się na nim, chyba że port błędu kroku jest podłączony. Zdarzenia zgłoszone przez wcześniejsze kroki uruchomienia pozostają zgłoszone.

| Kod | Przyczyna |
| --- | --- |
| `EXTENSION_EVENT_INVALID` | `items` nie jest listą, element nie jest obiektem, nie pasuje do danych wyzwalacza, ma ponad 32 KB albo nie ma użytecznego klucza. |
| `EXTENSION_EVENT_LIMIT` | Ponad 500 elementów w kroku albo ponad 2000 zdarzeń w uruchomieniu. |
| `EXTENSION_EVENT_NOT_ALLOWED` | Uruchomienie nie zostało rozpoczęte przez Opero dla rozszerzenia albo zainstalowana wersja nie deklaruje tego wyzwalacza. Paczka, która przeszła sprawdzenie, go nie spotyka. |

Błąd widać w uruchomieniu reguły akcji; w harmonogramie liczy się jako nieudane uruchomienie.

## Problemy [#problems]

| Kod | Co jest nie tak |
| --- | --- |
| `event.unknown` | `event` nie wskazuje wyzwalacza paczki. |
| `event.not_literal` | `event` jest szablonem. |
| `event.key_required` | `dedupe: true` bez `key`. |
| `event.emitted_from_step` | Akcja, która zgłasza zdarzenia, jest udostępniona jako krok reguły albo jest akcją weryfikacji połączenia. |
| `step.config_not_allowed` | Ustawienie inne niż cztery powyższe, `items`, które nie jest jednym wyrażeniem, `dedupe` inne niż true lub false albo `key`, które nie jest polem danych wyzwalacza. |
| `test.event_untested` | Żaden przypadek testowy akcji nie wymienia oczekiwanych zdarzeń. |
