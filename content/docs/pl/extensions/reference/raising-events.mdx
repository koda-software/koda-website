Reguła paczki zgłasza zdarzenia własnych [wyzwalaczy](/docs/pl/extensions/reference/triggers) paczki krokiem `EMIT_EVENT`. Każdy element listy staje się jednym zdarzeniem, a każde zdarzenie może uruchomić reguły organizacji na tym wyzwalaczu. Używa go przewodnik [Zdarzenia z usługi](/docs/pl/extensions/scheduled-events).

```yaml title="actions/sync-orders/rule.yaml"
entryStepId: fetch
steps:
  - id: fetch
    type: CALL_WEBHOOK
    name: Open orders
    contextKey: orders
    config:
      method: GET
      url: "https://api.example.com/v1/orders?company={{ trigger.data.subject.companyId }}&status=open"
  - id: emit
    type: EMIT_EVENT
    name: Raise order events
    contextKey: output
    config:
      event: order_changed
      items: "{{ orders.body.items }}"
      key: number
      dedupe: true
edges:
  - { fromStepId: fetch, toStepId: emit }
```

Nic więcej nie jest przyjmowane. Krok nie ustawia firmy ani wykonawcy: zdarzenie należy do firmy uruchomienia, które je zgłasza, pochodzi od rozszerzenia i niesie łańcuch reguł tego uruchomienia, więc reguła, która już jest w tym łańcuchu, nie startuje ponownie.

## Elementy [#items]

Każdy element `items` to obiekt, który musi pasować do `data` wyzwalacza: pole, którego lista pól nie wymienia, brak wymaganego pola albo wartość złego typu są odrzucane, a pole oznaczone `nullable` może mieć wartość `null`. Gdy odpowiedź usługi ma inny kształt, najpierw przekształć ją krokiem **Uruchom skrypt** albo krokami list (`TRANSFORM`, `FILTER` i innymi).

`key` wskazuje pole, którego wartość identyfikuje element. W każdym elemencie ta wartość to tekst o długości od 1 do 200 znaków albo liczba.

Krok zwraca `{ emitted, unchanged }`: ile zdarzeń zgłosił i ile elementów pominął, bo się nie zmieniły.

## Deduplikacja [#dedupe]

Bez `dedupe` każdy element jest zgłaszany przy każdym uruchomieniu. Z `dedupe: true` i `key` element jest zgłaszany, gdy Opero nie pamięta jego klucza albo gdy jego treść różni się od ostatnio zgłoszonej dla tego klucza.

| Zasada | Szczegóły |
| --- | --- |
| Niezmieniony | Wszystkie dane elementu są takie same jak przy ostatnim zgłoszeniu dla tego klucza. Kolejność pól nie ma znaczenia; każda inna różnica jest zmianą, nawet w polu, którego nie odczytuje żadna reguła. |
| Na podmiot uruchomienia | Pamięć jest osobna dla instalacji, firmy albo połączonego członka. Ten sam klucz w dwóch firmach to dwa elementy. |
| W jednym kroku | Powtarzający się klucz jest porównywany z tym, co krok właśnie zgłosił. |
| Jak długo | [`dedupe.retentionDays`](/docs/pl/extensions/reference/triggers#dedupe-retention) wyzwalacza. |

## Dostarczane co najmniej raz [#delivered-at-least-once]

Opero najpierw zgłasza zdarzenie, a potem je zapamiętuje, więc jeśli coś przerwie pracę pomiędzy, następne uruchomienie zgłosi ten sam element ponownie. Reguły organizacji na wyzwalaczu powinny więc traktować drugie zdarzenie jako nieszkodliwe: znaleźć rekord po kluczu elementu i go zaktualizować albo utworzyć, gdy go brakuje.

## Gdzie można go używać [#where-it-may-be-used]

`EMIT_EVENT` działa tylko w uruchomieniach, które Opero rozpoczyna dla samego rozszerzenia:

| Akcję, która go używa, uruchamia | Dozwolone |
| --- | --- |
| [Harmonogram](/docs/pl/extensions/reference/schedules) | Tak |
| Hak `afterConnect` albo `beforeDisconnect` [połączenia członka](/docs/pl/extensions/reference/member-connections) | Tak |
| Reguła organizacji, jako krok reguły | Nie |
| Członek, jako akcja bloku albo polecenie rekordu | Nie |
| **Sprawdź połączenie**, jako akcja weryfikująca | Nie |

Własne reguły organizacji też nie mogą używać `EMIT_EVENT`: edytor reguł go nie oferuje, a zapis reguły, która go zawiera, jest odrzucany (`step_type_managed_only`). Akcja, która go używa, potrzebuje co najmniej jednego przypadku testowego wymieniającego oczekiwane zdarzenia; zobacz [Testy](/docs/pl/extensions/reference/tests#events).

## Limity i błędy [#limits-and-failures]

| Co | Limit |
| --- | --- |
| Elementy w jednym kroku | 500 |
| Zdarzenia w jednym uruchomieniu | 2000 |
| Jeden element | 32 KB JSON-a |

Każdy element jest sprawdzany, zanim jakikolwiek zostanie zgłoszony. Gdy sprawdzenie się nie powiedzie, krok kończy się błędem i niczego nie zgłasza, a uruchomienie zatrzymuje się na nim, chyba że port błędu kroku jest podłączony. Zdarzenia zgłoszone przez wcześniejsze kroki uruchomienia pozostają zgłoszone. Dla harmonogramu liczy się to jako nieudane uruchomienie.

| Kod przy uruchomieniu | Przyczyna |
| --- | --- |
| `EXTENSION_EVENT_INVALID` | `items` nie jest listą albo element nie jest obiektem, nie pasuje do danych wyzwalacza, ma ponad 32 KB albo nie ma użytecznego klucza. |
| `EXTENSION_EVENT_LIMIT` | Ponad 500 elementów w kroku albo ponad 2000 zdarzeń w uruchomieniu. |
| `EXTENSION_EVENT_NOT_ALLOWED` | Uruchomienie nie zostało rozpoczęte przez Opero dla rozszerzenia albo wyzwalacza nie deklaruje zainstalowana wersja. Paczka, która przeszła sprawdzenia, go nie spotyka. |

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `event.unknown` | `event` nie wskazuje żadnego wyzwalacza paczki. | Popraw nazwę albo dodaj wyzwalacz. |
| `event.not_literal` | `event` jest szablonem. | Wpisz nazwę wyzwalacza wprost. |
| `event.key_required` | `dedupe: true` bez `key`. | Dodaj pole, które identyfikuje element. |
| `event.emitted_from_step` | Akcja, która zgłasza zdarzenia, jest w jakikolwiek sposób udostępniona albo jest akcją weryfikującą połączenie. | Uruchamiaj ją z harmonogramu albo z haka połączenia członka. |
| `step.config_not_allowed` | Ustawienie inne niż cztery powyższe, `items`, które nie jest jednym wyrażeniem, `dedupe`, które nie jest true ani false, albo `key`, który nie jest polem danych wyzwalacza. | Trzymaj się czterech ustawień. |
| `test.event_untested` | Żaden przypadek testowy akcji nie wymienia oczekiwanych zdarzeń. | Dodaj przypadek z `events`. |
