Połączenie przechowuje dane uwierzytelniające zewnętrznej usługi. Administrator wpisuje je po instalacji, sprawdza i aktywuje połączenie na karcie [Konfiguracja](/docs/pl/extensions/after-install#configuration); do tego czasu rozszerzenie nie działa. Takie połączenie buduje [samouczek](/docs/pl/extensions/tutorial/call-a-service).

```yaml title="connection/connection.yaml"
methods:
  - method: token
    kind: api_token
    label: API token
    fields:
      token: { type: text, label: API token, required: true, hint: true }
verify: verify
```

`extension.yaml` wskazuje folder przez `connection: connection` i wymienia co najmniej jeden host w `permissions.network`.

Każde pole danych uwierzytelniających jest sekretne, chyba że ma `secret: false`. `hint: true` pozwala Opero pokazać ostatnie cztery znaki zapisanej wartości; bez tego wartość widać tylko jako `***`. Wartości, które nie są sekretne, np. język albo numer konta, to [ustawienia](/docs/pl/extensions/reference/settings).

## Dane uwierzytelniające organizacji lub firmy [#organization-or-company-credentials]

`scopes` decyduje, czy jest jeden zestaw danych uwierzytelniających dla całej organizacji, czy osobny dla każdej firmy.

| `supported` | `active` | Wynik |
| --- | --- | --- |
| `[organization]` | `organization` | Jedne dane uwierzytelniające dla wszystkich firm. Domyślnie. |
| `[company]` | `company` | Osobne dane uwierzytelniające dla każdej firmy. |
| `[organization, company]` | `selectable` | Wybiera administrator. |

Przy danych uwierzytelniających firmy krok używa danych firmy, dla której działa wywołująca reguła, a testy paczki podają `companyId`.

## Weryfikacja [#verification]

`verify` wskazuje akcję paczki, zwykle taką, której nic nie udostępnia. Działa ona z danymi uwierzytelniającymi, które są sprawdzane, i z ustawieniami rozszerzenia, a dopóki się nie powiedzie, połączenia nie da się aktywować. Napisz ją jako tanie wywołanie tylko do odczytu, które dowodzi, że dane uwierzytelniające działają:

```yaml title="actions/verify/rule.yaml"
entryStepId: call
steps:
  - id: call
    type: CALL_WEBHOOK
    name: Check token
    contextKey: output
    config:
      url: https://api.example.com/v1/me
      method: GET
      headers: { Authorization: "Bearer {{ connection.token }}" }
edges: []
```

Akcja weryfikująca działa bez firmy, więc nie może używać [kroku danych](/docs/pl/extensions/reference/data-steps). Nie może też zgłaszać zdarzeń ani używać wartości członka.

## Sekrety [#secrets]

Sekret zapisuje się jako `{{ connection.<field> }}`, sam w nawiasach klamrowych, w wartości nagłówka albo wartości parametru zapytania w URL kroku **Wywołaj webhook**. Z `secretsInBody: true` może stać także w ścieżce URL i w treści.

| Przykład | Akceptowane |
| --- | --- |
| `Authorization: "Bearer {{ connection.token }}"` | Tak |
| `url: "https://api.example.com/v1/items?key={{ connection.token }}"` | Tak |
| `X-Key: "{{ connection.token \| upcase }}"` | Nie: użyto filtra |
| `body: { key: "{{ connection.token }}" }` | Tylko z `secretsInBody: true` |
| W skrypcie, warunku, logu albo przekształceniu | Nie |
| `{{ connection.other }}` dla pola, którego nie deklaruje żadna metoda | Nie |

<Callout type="success" title="Co gwarantuje Opero">
- Prawdziwa wartość jest wstawiana dopiero przy wysyłaniu żądania, więc nigdy nie pojawia się w logu, historii uruchomień ani w skrypcie.
- Sekret trafia tylko do hostów z `permissions.network` i tylko wtedy, gdy działa twoja własna akcja.
- Reguła napisana przez organizację nie może odwołać się do twojego połączenia, a ręczne uruchomienie jednej z twoich zainstalowanych reguł nigdy nie wysyła sekretu.
- Komunikat błędu nigdy nie cytuje tego, co odesłała usługa, bo treść błędu mogłaby powtórzyć sekret.
</Callout>

## HTTP Basic z połączenia [#http-basic-from-the-connection]

Niektóre usługi chcą danych uwierzytelniających jako HTTP Basic, czyli base64 z `id:sekret`. Symbolu zastępczego nie da się zakodować, więc metoda deklaruje `scheme`, który wskazuje dwa jej pola, a krok **Wywołaj webhook** pisze `auth: connection`, bez symbolu zastępczego:

```yaml title="connection/connection.yaml"
methods:
  - method: client
    kind: custom
    label: API client
    fields:
      clientId: { type: text, label: Client ID, required: true, secret: false }
      clientSecret: { type: text, label: Client secret, required: true }
    scheme: { kind: basic, username: clientId, password: clientSecret }
verify: verify_client
```

```yaml title="actions/verify-client/rule.yaml"
entryStepId: check
steps:
  - id: check
    type: CALL_WEBHOOK
    name: Check the client
    config:
      method: GET
      url: https://api.example.com/v1/client
      auth: connection
edges: []
```

`basic` to jedyny `kind`. `auth: connection` wymaga `scheme` w każdej metodzie, żeby krok działał niezależnie od metody, którą wybierze administrator; wysyłana jest pierwsza metoda, której oba pola są wypełnione. Krok z paczki nie przyjmuje żadnej innej wartości `auth`. W przypadku testowym podaj oba pola w `connection` i oczekuj zakodowanego nagłówka, na przykład `authorization: Basic Y2xpZW50LTE6c2VjcmV0LTE=` dla `client-1` i `secret-1`.

## Połączenia członków [#member-connections]

`member: member.yaml` pozwala też każdemu członkowi połączyć własne konto w usłudze przez OAuth. Identyfikator i sekret klienta OAuth są wtedy polami danych uwierzytelniających jednej z metod. Zobacz [Połączenia członków](/docs/pl/extensions/reference/member-connections).

## Aktualizacje [#upgrades]

| Zmiana w nowej wersji | Co się dzieje | Kod |
| --- | --- | --- |
| Zmieniły się pola danych uwierzytelniających | Po aktualizacji połączenie jest wyłączone, dopóki znów nie przejdzie sprawdzenia. Ostrzeżenie. | `connection.reverify_required` |
| Cokolwiek innego w `connection.yaml` albo w ustawieniach | Połączenie pozostaje włączone. | |

Co widzi administrator, opisuje strona [Aktualizacja i odinstalowanie](/docs/pl/extensions/upgrade-and-uninstall#what-a-new-version-can-change).

## Tłumaczenia [#translations]

Etykieta metody trafia do `connection.methods.<method>.label`, a jej pola do `fields.<field>`. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/translations#translatable-keys).

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `connection.invalid` | Nieznany klucz, blok `settings`, klucz metody w złej postaci lub użyty dwa razy, zakres `active` spoza `supported`, `verify`, który nie wskazuje żadnej akcji, albo pole w `scheme`, którego metoda nie ma. | Popraw klucz wskazany w komunikacie; ustawienia przenieś do `settings.yaml`. |
| `connection.schema_invalid` | Plik schematu metody nie jest schematem obiektu, nie kompiluje się albo używa kluczy tekstów. | Napisz poprawny JSON Schema po angielsku albo użyj listy pól. |
| `connection.hosts_required` | Paczka z połączeniem nie wymienia żadnego hosta w `permissions.network`. | Dodaj host usługi z powodem. |
| `connection.undeclared` | `{{ connection.<field> }}` albo `auth: connection` w paczce bez połączenia. | Dodaj `connection/connection.yaml`. |
| `connection.placeholder_position` | Sekret poza wartością nagłówka lub parametru zapytania w URL kroku **Wywołaj webhook**, albo poza ścieżką i treścią przy `secretsInBody`. | Przenieś go albo ustaw `secretsInBody: true`, jeśli usługa tego wymaga. |
| `connection.placeholder_not_bare` | Sekret z filtrem, tagiem albo innym tekstem w nawiasach klamrowych. | Napisz dokładnie `{{ connection.<field> }}`. |
| `connection.unknown_field` | Pole, którego nie deklaruje żadna metoda połączenia. | Popraw nazwę albo dodaj pole. |
| `step.config_not_allowed` | `auth` inne niż `connection` albo `auth: connection` przy metodzie bez `scheme`. | Daj każdej metodzie `scheme` albo wyślij sekret w nagłówku. |
| `action.verify_uses_data` | Akcja weryfikująca używa kroku danych. | Sprawdzaj dane uwierzytelniające tylko krokiem **Wywołaj webhook**. |
| `event.emitted_from_step` | Akcja weryfikująca zgłasza zdarzenia. | Zgłaszaj zdarzenia z akcji harmonogramu. |
| `action.member_outside_member_run` | Akcja weryfikująca używa `{{ userConnection.<field> }}`. | Weryfikuj danymi uwierzytelniającymi organizacji. |
| `layout.missing_descriptor` | `extension.yaml` zawiera `connection: connection`, ale brakuje `connection/connection.yaml`. | Dodaj plik. |
