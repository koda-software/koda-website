---
title: Akcje i listy pól
description: Dokumentacja action.yaml, folderu z jedną akcją rozszerzenia, oraz list pól, które opisują jej wejście i wyjście.
---

Akcja to jeden fragment logiki paczki: folder z `action.yaml`, logiką ([plikiem reguły](/docs/pl/extensions/reference/rule-files) albo [skryptem](/docs/pl/extensions/reference/scripts)) i [testami](/docs/pl/extensions/reference/tests). Opublikowana jako krok reguły jest tym, czego używają autorzy reguł organizacji. [Część 2 samouczka](/docs/pl/extensions/tutorial/call-a-service) buduje trzy takie akcje.

```yaml title="actions/greet/action.yaml"
action: greet
label: Greet
description: Sends a greeting for a name to httpbin.org and returns its answer.

input:
  name: { type: text, label: Name, required: true }
output:
  status: { type: integer, label: HTTP status }
  body: { type: object, label: Answer, fields: {} }

run: rule.yaml
tests: tests.yaml

expose:
  ruleStep: { category: integrations }
```

## Co uruchamia akcję [#what-runs-an-action]

Akcja działa tylko wtedy, gdy coś ją uruchomi. Bez `expose` jest zainstalowana, ale autorzy reguł jej nie widzą.

| Uruchamia ją | Deklaracja | Dokumentacja |
| --- | --- | --- |
| Reguła organizacji, jako krok | `expose.ruleStep` | Ta strona |
| Przycisk w bloku albo akcje rekordu, jako członek | `expose.blockAction`, `expose.recordCommand` | [Akcje bloków i polecenia rekordów](/docs/pl/extensions/reference/member-actions) |
| **Sprawdź połączenie** w połączeniu | `verify` w `connection.yaml` | [Połączenie i sekrety](/docs/pl/extensions/reference/connection-and-secrets) |
| Harmonogram | `action` w `schedule.yaml` | [Harmonogramy](/docs/pl/extensions/reference/schedules) |
| Zaczep połączenia członka | `afterConnect`, `beforeDisconnect` w `member.yaml` | [Połączenia członków](/docs/pl/extensions/reference/member-connections) |
| Inna akcja paczki | krok `x-<key>.<action>` w jej pliku reguły | [Pliki reguł](/docs/pl/extensions/reference/rule-files#steps-a-rule-file-may-use) |

Reguła akcji jest instalowana jako `<nazwa paczki>: <label>` i działa tylko w ten sposób. Ręczne uruchomienie, test lub ponowne odtworzenie albo wywołanie jej krokiem **Wywołaj regułę** jest odrzucane z kodem `EXTENSION_MANAGED_RULE_RUN`. Żeby wypróbować akcję, użyj jej kroku w regule organizacji albo uruchom jej testy.

### Akcje, które nie są krokami [#actions-that-are-not-steps]

Niektóre akcje działają tylko z wnętrza paczki, więc nie można ich udostępnić.

| Akcja | Nie może być | Kod |
| --- | --- | --- |
| Uruchamiana przez harmonogram albo zaczep połączenia członka | Krokiem reguły, akcją bloku ani poleceniem rekordu | `schedule.action_exposed`, `member.invalid` |
| Zgłaszająca zdarzenia krokiem [`EMIT_EVENT`](/docs/pl/extensions/reference/raising-events) | Udostępniona w żaden sposób ani akcją weryfikacji | `event.emitted_from_step` |
| Akcja członka, której reguła używa `{{ userConnection.<field> }}` | Udostępniona w żaden sposób, akcją weryfikacji ani uruchamiana przez harmonogram, który nie działa dla członków | `action.member_outside_member_run` |
| Akcja weryfikacji | Akcją, która używa kroku danych | `action.verify_uses_data` |

<Callout title="Dwa znaczenia słowa „członek”">
*Akcja członka* na tej stronie używa własnego połączenia członka. Akcje, które członkowie uruchamiają sami z bloków i rekordów, to [akcje bloków i polecenia rekordów](/docs/pl/extensions/reference/member-actions).
</Callout>

## Listy pól [#field-lists]

Lista pól mapuje klucze pól na definicje. Wejście i wyjście akcji, dane uwierzytelniające połączenia, [ustawienia](/docs/pl/extensions/reference/settings) rozszerzenia, dane i filtry [wyzwalacza](/docs/pl/extensions/reference/triggers) oraz formularz [połączenia członka](/docs/pl/extensions/reference/member-connections) to wszystko listy pól.

```yaml title="actions/create-shipment/action.yaml"
input:
  order_id: { type: text, label: Order number, required: true, help: As shown on the order. }
  priority:
    type: select
    label: Priority
    options: [low, normal, { value: high, label: High priority }]
    default: normal
  lines:
    type: list
    label: Lines
    items:
      type: object
      fields:
        sku: { type: text, label: SKU }
        quantity: { type: integer, label: Quantity }
```

Klucz pola to litery, cyfry i `_`, nie zaczyna się od cyfry i ma do 63 znaków.

Lista ma najwyżej pięć poziomów zagnieżdżenia i do 100 pól na każdym poziomie. Wejście jest zamknięte na każdym poziomie: zagnieżdżone pole, którego lista nie wymienia, też zostaje odrzucone.

### Typy pól [#field-types]

| Typ | Wartość |
| --- | --- |
| `text` | Tekst. |
| `number` | Liczba. |
| `integer` | Liczba całkowita. |
| `boolean` | `true` albo `false`. |
| `date` | Data, np. `2026-11-12`. |
| `datetime` | Data i godzina w ISO 8601. |
| `select` | Jedna z `options`. |
| `list` | Lista `items`. |
| `object` | Obiekt z `fields`. |
| `company` | Jedna z firm członka. Tylko na najwyższym poziomie `config` [połączenia członka](/docs/pl/extensions/reference/member-connections#the-members-form), najwyżej raz. |

<Callout type="warn" title="Wejścia liczbowe i logiczne przyjmują stałe wartości">
Wartości, które reguła przekazuje krokowi, są sprawdzane z polami wejściowymi przy zapisie reguły, więc wejście `number` albo `boolean` przyjmuje tylko stałą wartość, a nie szablon w rodzaju `{{ record.price }}`. Zadeklaruj takie wejścia jako `text` i przekształć je w skrypcie. Pokazuje to [Krok, który tylko liczy](/docs/pl/extensions/calculating-step).
</Callout>

### Pliki schematów [#schema-files]

Plik JSON Schema w folderze akcji może zastąpić listę pól, gdy potrzebujesz więcej, niż dają listy pól:

```yaml title="actions/create-shipment/action.yaml"
input: input.schema.json
```

Plik jest w JSON albo YAML, opisuje obiekt i jest pisany tylko po angielsku: jego teksty nie są tłumaczone, a jego pola nie mają typów w skryptach.

## Gdy krok się nie powiedzie [#when-a-step-fails]

Krok zakończony błędem ma na wyjściu błędu jeden z tych kodów. Podłącz wyjście błędu, żeby obsłużyć je w regule.

| Kod na kroku | Przyczyna | Zawiera |
| --- | --- | --- |
| `EXTENSION_ACTION_FAILED` | Akcja się nie powiodła, zwykle dlatego, że usługa odpowiedziała błędem. | `httpStatus`, gdy nie powiodło się wywołanie |
| `EXTENSION_ACTION_RATE_LIMITED` | Usługa odpowiedziała `429`. | `httpStatus` i `retryAfterSeconds`, jeśli usługa go wysłała |
| `EXTENSION_ACTION_INPUT_INVALID` | Wejście kroku nie pasowało do pól wejściowych. | |
| `EXTENSION_ACTION_OUTPUT_INVALID` | Wynik nie pasował do pól wyjściowych. | |

Gdy krok danych rozszerzenia zostanie odrzucony w trakcie działania, własna reguła rozszerzenia pokazuje w swoim uruchomieniu `EXTENSION_SCOPE_DENIED`, a krok w twojej regule kończy się błędem `EXTENSION_ACTION_FAILED`. Komunikat nigdy nie cytuje tego, co odesłała usługa, bo treść błędu mogłaby powtórzyć sekret.

<Callout type="idea" title="Ponawiaj przy limicie zapytań">
`EXTENSION_ACTION_RATE_LIMITED` oznacza, że usługa jest zajęta, a nie że żądanie było błędne. Obsłuż go osobno od innych błędów i użyj `retryAfterSeconds`, żeby zdecydować, kiedy spróbować ponownie.
</Callout>

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `action.invalid` | Nieznany klucz, zła nazwa lub etykieta albo udostępniona akcja bez `description`. | Sprawdź klucz z tabelą wyżej. |
| `action.run_invalid` | `run` wskazuje coś, co nie jest `.yaml`, `.js` ani `.ts`. | Wskaż plik reguły albo skrypt. |
| `action.missing_test` | Akcja bez przypadku testowego albo folder `tests` bez pliku `.yaml`. | Napisz przypadek. |
| `action.cycle` | Akcje wywołują swoje kroki nawzajem w cyklu. | Przerwij cykl. |
| `action.schema_invalid` | Plik schematu, który nie opisuje obiektu, nie kompiluje się albo używa kluczy tekstów, np. `x-titleKey`. | Popraw schemat albo użyj listy pól. |
| `action.verify_uses_data` | Akcja weryfikacji używa kroku danych. | Ogranicz akcję weryfikacji do wywołań i logiki. |
| `action.member_outside_member_run` | Akcja członka jest udostępniona, jest akcją weryfikacji albo uruchamia ją harmonogram, który nie działa dla członków. | Uruchamiaj ją z zaczepu połączenia członka albo z harmonogramu dla członków. |
| `field.invalid` | Lista pól z nieznanym typem lub kluczem, klucz pola w złej postaci, kontener bez `options`, `items` lub `fields`, niepoprawna wartość domyślna albo klucz użyty tam, gdzie lista go nie dopuszcza. | Sprawdź pole z tabelą wyżej. |
| `step.invalid` | Wyjście o nazwie `error`, zapisane dwa razy albo o nazwie innej niż małymi literami. | Użyj unikalnych nazw innych niż `error`. |
| `step.unknown_category` | Przy przesyłaniu: `category` nie jest jedną z sześciu. | Użyj `data`, `logic`, `notifications`, `integrations`, `files` albo `flow`. |
| `name.duplicate` | Dwie akcje o tej samej nazwie. | Zmień jedną z nazw. |
| `EXTENSION_MANAGED_RULE_RUN` | Ktoś uruchomił, przetestował lub odtworzył regułę rozszerzenia bezpośrednio albo wywołał ją krokiem **Wywołaj regułę**. | Użyj kroku w regule. |

Kody akcji bloków i poleceń rekordów opisuje strona [Akcje bloków i polecenia rekordów](/docs/pl/extensions/reference/member-actions), a kody pliku reguły strona [Pliki reguł](/docs/pl/extensions/reference/rule-files#problems).
