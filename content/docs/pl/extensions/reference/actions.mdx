Akcja to folder z `action.yaml`, jej logiką (plikiem reguły albo skryptem) i testami. Udostępniona jako krok reguły, jest tym, z czego korzystają autorzy reguł.

```yaml title="actions/greet/action.yaml"
action: greet
label: Greet
description: Sends a greeting for a name to httpbin.org and returns its answer.

input:
  name: { type: text, label: Name, required: true }
output:
  status: { type: integer, label: HTTP status }
  body: { type: object, label: Answer, fields: {} }

run: rule.yaml
tests: tests.yaml

expose:
  ruleStep: { category: integration }
```

Pola wejściowe najwyższego poziomu typu `text`, `number`, `integer`, `boolean` i `select` stają się też parametrami ręcznego wyzwalacza zainstalowanej reguły. Używanych jest pierwszych 20 takich pól. Pole innego typu, pole, którego klucz zawiera wielką literę (pisz `order_id`, nie `orderId`), oraz wejście podane jako plik schematu nie dają parametru.

Zainstalowana reguła działa tylko przez swój krok. Ręczne uruchomienie, test czy ponowienie jej albo wywołanie jej z innej reguły krokiem **Wywołaj regułę** jest odrzucane z kodem `EXTENSION_MANAGED_RULE_RUN`. Żeby wypróbować akcję, użyj jej jako kroku w regule organizacji albo uruchom jej [testy](/docs/pl/extensions/reference/tests).

<Callout type="warn" title="Dodatkowe wyjścia wyników">
`expose.ruleStep.branches` wymienia dodatkowe wyjścia wyników. Są widoczne na kroku, ale dziś wybierane jest zawsze tylko wyjście domyślne albo wyjście błędu.
</Callout>

## Akcje, które nie są krokami [#actions-that-are-not-steps]

Akcja bez `expose` też jest instalowana i działa, gdy uruchamia ją coś z paczki:

| Uruchamia ją | Przykład |
| --- | --- |
| **Sprawdź połączenie** w połączeniu | `verify: verify` w `connection.yaml`. |
| [Harmonogram](/docs/pl/extensions/reference/schedules) | `action: sync_orders` w `schedule.yaml`. |
| `afterConnect` albo `beforeDisconnect` [połączenia członka](/docs/pl/extensions/reference/member-connections) | `afterConnect` albo `beforeDisconnect` w `member.yaml`. |

Dwóch rodzajów akcji nigdy nie można udostępnić jako kroku reguły:

- **Akcji, która zgłasza zdarzenia**, czyli takiej, której reguła używa [`EMIT_EVENT`](/docs/pl/extensions/reference/raising-events): zdarzenia paczki zgłaszają tylko uruchomienia harmonogramu oraz `afterConnect` i `beforeDisconnect` połączenia członka (`event.emitted_from_step`). Nie może też być akcją weryfikacji.
- **Akcji członka**, czyli takiej, której reguła używa `{{ userConnection.<field> }}`: działa tylko dla jednego członka, uruchamiana przez `afterConnect` lub `beforeDisconnect` połączenia członka albo przez harmonogram dla członków (`action.member_outside_member_run`). Nie może też być akcją weryfikacji.

Akcji harmonogramu ani akcji `afterConnect` i `beforeDisconnect` też nie można udostępnić (`schedule.action_exposed`, `member.invalid`), ani jako kroku reguły, ani jako akcji bloku, ani jako polecenia rekordu. Akcja, która zgłasza zdarzenia, albo taka, która używa `{{ userConnection.<field> }}`, nie może być akcją bloku ani poleceniem rekordu.

<Callout title="Dwa znaczenia słowa „członek”">
*Akcja członka* na tej stronie to akcja, która używa własnego połączenia członka. Akcje, które członkowie uruchamiają sami z bloków i rekordów, to [akcje bloków i polecenia rekordów](/docs/pl/extensions/reference/member-actions).
</Callout>

## Listy pól [#field-lists]

Lista pól mapuje klucze pól (litery, cyfry i `_`, nie zaczynają się od cyfry) na definicje. Wejście i wyjście, dane uwierzytelniające połączenia, [ustawienia](/docs/pl/extensions/reference/settings) rozszerzenia, dane i filtry [wyzwalacza](/docs/pl/extensions/reference/triggers) oraz formularz [połączenia członka](/docs/pl/extensions/reference/member-connections) to wszystko listy pól.

```yaml
input:
  orderId: { type: text, label: Order number, required: true, help: As shown on the order. }
  priority: { type: select, label: Priority, options: [low, normal, high], default: normal }
  lines:
    type: list
    label: Lines
    items:
      type: object
      fields:
        sku: { type: text, label: SKU }
        quantity: { type: integer, label: Quantity }
```

### Typy pól

| Typ | Wartość |
| --- | --- |
| `text` | Tekst. |
| `number` | Liczba. |
| `integer` | Liczba całkowita. |
| `boolean` | `true` lub `false`. |
| `date` | Tekst, np. `2026-11-12`. |
| `datetime` | Data i godzina w formacie ISO 8601. |
| `select` | Jedna z `options`. |
| `list` | Lista `items`. |
| `object` | Obiekt z `fields`. |
| `company` | Jedna z firm członka. Tylko na najwyższym poziomie `config` [połączenia członka](/docs/pl/extensions/reference/member-connections#the-members-form), najwyżej raz. |

Listy zagnieżdżają się do pięciu poziomów i mieszczą do 100 pól.

<Callout type="warn" title="Wejścia number i boolean przyjmują stałe wartości">
Wartości, które reguła podaje krokowi, są sprawdzane względem jego pól wejściowych przy zapisie reguły, więc wejście `number` lub `boolean` przyjmuje tylko stałą wartość, a nie szablon w rodzaju `{{ record.price }}`. Zadeklaruj takie wejścia jako `text` i przekonwertuj je w skrypcie. [Przepis na obliczenia](/docs/pl/extensions/calculating-step) pokazuje, jak to zrobić.
</Callout>

### Pliki schematów

Plik JSON Schema w folderze akcji może zastąpić listę pól, gdy potrzebujesz więcej, niż dają listy pól:

```yaml title="actions/create-shipment/action.yaml"
input: input.schema.json
```

Plik schematu piszesz tylko po angielsku, a jego pola nie są typowane w skryptach.

## Jak nazywane są elementy po instalacji

| Element | Nazwa | Dla klucza `polar-eu` |
| --- | --- | --- |
| Krok reguły | `x-<key>.<action>` | `x-polar-eu.sync` |
| Filtr szablonu | `x_<key with _>_<filter>` | `x_polar_eu_pace` |
| Połączenie | `x-<key>` | `x-polar-eu` |
| Wyzwalacz reguł | `x-<key>.<trigger>` | `x-polar-eu.daily_activity` |
| Blok | `x_<key with _>_<block>` | `x_polar_eu_week_card` |
| Akcja bloku, polecenie rekordu | `x-<key>.<action>` | `x-polar-eu.sync` |
| Link rekordu | `x-<key>.<link>` | `x-polar-eu.open_profile` |
| Uprawnienie paczki | `company.x-<key>.<name>` | `company.x-polar-eu.sync` |
| Zainstalowana reguła | `<name>: <action label>` | `Polar: Sync` |

Krok zachowuje tożsamość między wersjami, dopóki nazwa akcji się nie zmienia, więc reguły, które z niego korzystają, działają dalej po aktualizacji.
