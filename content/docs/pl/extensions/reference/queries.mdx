Zapytanie to zapisane zapytanie SQL, które rozszerzenie przynosi ze sobą i które odczytuje albo zmienia rekordy własnych [obiektów](/docs/pl/extensions/reference/objects) paczki. Po instalacji jest zapisanym zapytaniem organizacji: mogą go używać listy SQL, raporty i bloki, a reguły paczki uruchamiają je krokiem [`RUN_QUERY`](/docs/pl/extensions/reference/data-steps#run-a-query).

```yaml title="queries/orders-by-day/query.yaml"
query: orders_by_day
name: Orders by day
kind: FETCH
sql: query.sql
```

```sql title="queries/orders-by-day/query.sql"
SELECT f_ordered_on AS day, count(*) AS orders
FROM {{object.orders}}
GROUP BY f_ordered_on
```

Każde zapytanie ma własny folder w `queries/` z plikiem `query.yaml` i plikiem SQL, wymieniony w `queries` w `extension.yaml`. Paczka z zapytaniami wymienia `queries` w `requires.modules`.

## Plik SQL [#the-sql-file]

Plik zawiera jedną instrukcję SQL o długości do 10 000 znaków, w UTF-8.

| Napisz | Dla |
| --- | --- |
| `{{object.<key>}}` | Tabela jednego z obiektów paczki, według jego klucza `object`. Przy instalacji Opero wpisuje w to miejsce prawdziwą nazwę tabeli. Spacje w nawiasach klamrowych są dozwolone. |
| `f_<field key>` | Kolumna pola. Pole wyboru zawiera klucz wpisu. |
| `:name` | Parametr zadeklarowany w `parameters`. |

Zapytanie nie może wskazywać tabel własnych obiektów organizacji. Sam SQL sprawdza przegląd instalacji, tak samo jak zapisane zapytanie napisane przez administratora; zapytanie nad tabelą, którą tworzy ta sama instalacja, przechodzi pełne sprawdzenie przy instalacji. Działa na ograniczonych rolach bazy danych, których używają zapisane zapytania, w firmie, dla której jest uruchamiane.

## Parametry [#parameters]

```yaml title="queries/close-old-orders/query.yaml"
query: close_old_orders
name: Close old orders
kind: MUTATION
mutationOperation: UPDATE
sql: query.sql
parameters:
  - { name: before, type: date, required: true, description: Orders placed before this day are closed. }
```

```sql title="queries/close-old-orders/query.sql"
UPDATE {{object.orders}}
SET f_status = 'closed'
WHERE f_ordered_on < :before
```

## Klucz po instalacji [#the-installed-key]

Zapytanie jest instalowane z kluczem `x_<key z _>_<name>`: `orders_by_day` rozszerzenia `orders-ext` to `x_orders_ext_orders_by_day`. Reguły i testy wskazują je tym kluczem. Organizacja nie może utworzyć zapisanego zapytania z kluczem zaczynającym się od `x_` ani nadać mu takiego klucza.

Paczkę z zapytaniem MUTATION instaluje tylko osoba, która ma `org.savedQueries.executeMutation`.

## Aktualizacje [#upgrades]

| Zmiana w nowej wersji | Co się dzieje | Kod |
| --- | --- | --- |
| Zmienił się SQL zapytania | Przegląd instalacji pokazuje nowy SQL. | |
| Usunięto zapytanie, którego używa aktywna lista SQL, raport albo blok | Aktualizacja jest zablokowana, dopóki przestaną go używać. | `query.in_use` |
| Instalacja przejmuje zapytanie zachowane przy wcześniejszym odinstalowaniu | Zapytanie znów należy do rozszerzenia. Ostrzeżenie. | `query.adopts_existing` |

Odinstalowanie usuwa zapytania, których nic nie używa, a pozostałe zachowuje jako własność organizacji. Co widzi administrator, opisuje strona [Aktualizacja i odinstalowanie](/docs/pl/extensions/upgrade-and-uninstall#what-a-new-version-can-change).

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `query.invalid` | Nieznany klucz, brak `kind`, `mutationOperation` w zapytaniu FETCH, dwa parametry o tej samej nazwie, plik SQL, który nie jest `.sql`, nie jest w UTF-8, jest pusty albo ma ponad 10 000 znaków, albo więcej niż 100 zapytań. | Popraw klucz albo plik wskazany w komunikacie. |
| `query.unknown_object` | `{{object.<key>}}` nie wskazuje żadnego obiektu paczki. Komunikat podaje wiersz w pliku SQL. | Popraw klucz albo dodaj obiekt. |
| `manifest.missing_file` | Brak pliku SQL wskazanego w `sql`. | Dodaj plik albo popraw nazwę. |
| `name.duplicate` | Dwa zapytania o tej samej nazwie. | Zmień nazwę jednego z nich. |
| `requires.module_undeclared` | Paczka ma zapytania, ale w `requires.modules` brakuje `queries`. | Dodaj `queries`. |
| `query.save_validation` | W przeglądzie instalacji: SQL nie da się zapisać albo `kind` nie odpowiada temu, co robi SQL. Blokuje instalację. | Popraw SQL albo `kind`. |
