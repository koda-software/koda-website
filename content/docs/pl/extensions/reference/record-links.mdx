title: Linki rekordów
description: Dodaj akcję rekordu, która otwiera stronę twojej usługi dla rekordu, czyli adres https zbudowany z identyfikatora i pól rekordu, przez link.yaml.
---

Link do rekordu otwiera stronę usługi zewnętrznej dla rekordu, który ogląda członek, na przykład stronę śledzenia przesyłki u przewoźnika. Pojawia się wśród akcji rekordu i niczego nie uruchamia na serwerze Opero: przeglądarka członka otwiera adres https zbudowany z identyfikatora rekordu i pól, które deklaruje link. Taki link dodaje przewodnik [Blok, przycisk i link](/docs/pl/extensions/blocks-and-actions).

```yaml title="links/open-tracking/link.yaml"
link: open_tracking
label: Open tracking page
description: Opens the parcel's page at the carrier.
permission: openTracking
targets: [{ object: parcels }]
fields:
  number: { label: Parcel number }
url: "https://track.example.com/parcels/{fields.number}?ref={record.id}"
```

Wymień folder w `links` w `extension.yaml` albo w `module.yaml` dołączonego modułu. `opero-ext add link <name>` zapisuje link, który kierujesz potem na własny host i uprawnienie. Paczka ma najwyżej 20 linków.

## Adres [#the-address]

Adres zaczyna się od `https://`, a jego host jest wpisany wprost, bez symbolu zastępczego, nazwy użytkownika i hasła. `{record.id}` to identyfikator rekordu, a `{fields.<field>}` wartość pola, które deklaruje link; oba mogą stać w ścieżce albo w zapytaniu. Każda wartość jest kodowana tam, gdzie stoi, jako jeden segment ścieżki albo wartość parametru, więc `A/1 B` w ścieżce staje się `A%2F1%20B`.

Host jest wymieniony w `permissions.links` w `extension.yaml`, z powodem. Host linku nie jest hostem, który wywołuje paczka, więc nie trafia do `permissions.network`.

```yaml title="extension.yaml"
permissions:
  links:
    - host: track.example.com
      reason: Opens a parcel's tracking page at the carrier.
```

Paczka wymienia do 20 hostów linków, a każdy otwiera link albo [ekran](/docs/pl/extensions/reference/screens#urls).

## Linki na obiektach paczki [#links-on-the-packages-objects]

Przy celach `{ object: <key> }` każde zadeklarowane pole jest polem każdego obiektu docelowego. Link pojawia się na rekordzie tych obiektów tylko wtedy, gdy spełnione są wszystkie warunki; w przeciwnym razie go nie ma, więc członek nigdy nie dostaje adresu z brakującą wartością:

| Warunek | Szczegóły |
| --- | --- |
| Członek przechodzi sprawdzenie | Rozszerzenie działa, link jest udostępniony firmie, członek jest w jego grupie odbiorców i ma jego uprawnienie. Zobacz [Kto może ich używać](/docs/pl/extensions/reference/member-actions#who-may-use-them). |
| Pola są w formularzu członka | Każde pole, które deklaruje link, jest w formularzu pokazywanym członkowi. |
| Pola mają wartości | Członek może odczytać rekord, a każde zadeklarowane pole ma tekst, liczbę albo tak/nie. Puste pole albo lista ukrywa link. |

## Linki na rekordach wbudowanych [#links-on-built-in-records]

Link może zamiast tego dotyczyć jednego typu wbudowanego i wtedy bierze pola ze stałego zestawu tego typu:

```yaml title="links/open-registry/link.yaml"
link: open_registry
label: Open in the registry
permission: checkCompanies
targets: [{ entity: contractor }]
fields:
  vatId: { label: VAT ID }
url: "https://registry.example.com/companies/{fields.vatId}"
```

| Typ | Pola |
| --- | --- |
| `contractor` | `name`, `shortName`, `vatId`, `regon`, `krs`, `country`, `externalId.<system>` (identyfikator kontrahenta w tym systemie zewnętrznym) |
| `sales_invoice` | `number`, `issueDate`, `saleDate`, `ksefNumber`, `currencyCode`, `grossAmount`, `buyerVatId` |
| `cost_invoice` | `supplierInvoiceNumber`, `issueDate`, `ksefNumber`, `currencyCode`, `grossAmount`, `supplierVatId` |
| `budget` | `number`, `name`, `periodStart`, `periodEnd`, `currencyCode` |
| `helpdesk_ticket` | `reference`, `number`, `typeKey` |

Daty są zapisywane jako `YYYY-MM-DD`, a kwoty jako zwykłe liczby dziesiętne, na przykład `1230.5`. Do tych zestawów mogą później dojść pola; żadne nie zostanie usunięte. Dane osobowe, takie jak PESEL, adresy e-mail i numery telefonów, są celowo pominięte.

Na rekordzie wbudowanym link pojawia się, gdy członek przechodzi to samo sprawdzenie, może odczytać ten rekord (ma uprawnienie do odczytu; dla zgłoszenia dostęp do jego działu) i każde pole ma wartość. Pola nie muszą być na stronie. Na potrzeby zgody przegląd instalacji pokazuje własne etykiety Opero dla tych pól; etykiety, które piszesz, są mimo to wymagane.

## Aktualizacje [#upgrades]

| Zmiana w nowej wersji | Co się dzieje | Kod |
| --- | --- | --- |
| Dodano host linku albo zmienił się adres lub pola linku | Przegląd pokazuje to jako nowe, do akceptacji przez administratora. | |

Każdy link ma osobne udostępnienie i grupę odbiorców, niezależnie od akcji bloków i poleceń rekordów paczki. Co widzi administrator, opisuje sekcja [Z czego mogą korzystać członkowie](/docs/pl/extensions/after-install#what-members-can-use).

## Tłumaczenia [#translations]

Teksty trafiają do `links.<link>`: `label`, `description` i `fields.<field>.label`. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/translations#translatable-keys).

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `link.invalid` | Nieznany klucz, klucz o złej strukturze albo więcej niż 20 linków. | Popraw klucz wskazany w komunikacie. |
| `link.not_https` | Adres nie zaczyna się od `https://`. | Użyj adresu https. |
| `link.template_invalid` | Symbol zastępczy w hoście, nazwa użytkownika lub hasło albo symbol zastępczy innej postaci. | Wpisz host wprost; używaj tylko `{record.id}` i `{fields.<field>}`. |
| `link.host_not_declared` | Hosta nie ma w `permissions.links`. | Dodaj go z powodem. |
| `link.field_undeclared` | `{fields.<field>}` wskazuje pole, którego link nie deklaruje. | Dodaj je w `fields`. |
| `link.unknown_target` | Cel obiektu, który nie jest obiektem paczki. | Popraw klucz albo dodaj obiekt. |
| `link.field_not_on_object` | Zadeklarowanego pola brakuje w jednym z obiektów docelowych. | Dodaj pole do każdego celu albo usuń cel. |
| `link.mixed_targets` | Cele obiektów razem z typem wbudowanym albo więcej niż jeden typ wbudowany. | Podziel go na dwa linki. |
| `link.field_unknown` | Przy przesłaniu: pole spoza zestawu typu wbudowanego albo `externalId` bez `.<system>`. | Użyj pola z tabeli. |
| `action.permission_undeclared` | `permission` nie wskazuje niczego w `permissions.company`. | Zadeklaruj uprawnienie. |
| `permissions.unused_link_host` | Host linku, którego nie otwiera żaden link ani ekran. | Usuń go. |
