---

Filtr szablonów to mała funkcja, która formatuje albo przekształca jedną wartość. Po instalacji może jej używać każdy szablon organizacji. [Część 2 samouczka](/docs/pl/extensions/tutorial/call-a-service) dodaje taki filtr.

```yaml title="filters/shout/filter.yaml"
filter: shout
description: Upper-cases a text and adds an exclamation mark.
script: filter.js
```

```js title="filters/shout/filter.js"
/** @type {import('../../.opero/types').Filter} */
const filter = (value) => String(value ?? '').toUpperCase() + '!';
export default filter;
```

```txt title="Szablon"
{{ "hi" | x_hello_ext_shout }}
```

```txt title="Wynik"
HI!
```

## Nazwa w szablonach [#the-name-in-templates]

Filtr jest instalowany jako `x_<key>_<filter>`, a myślniki klucza zamieniają się w podkreślenia: `shout` z `hello-ext` to `x_hello_ext_shout`. [Słownik pojęć](/docs/pl/extensions/reference/glossary#names-after-install) wymienia nazwy wszystkiego, co instaluje rozszerzenie.

## Funkcja [#the-function]

Funkcja dostaje wartość przekazaną do filtra, argumenty filtra jako tablicę i kontekst szablonu. Zwraca przefiltrowaną wartość od razu.

```js title="filters/trackingurl/filter.js"
/** @type {import('../../.opero/types').Filter} */
const filter = (value, args) => {
  const carrier = String(args[0] ?? 'dhl');
  const number = encodeURIComponent(String(value ?? ''));
  return 'https://track.example.com/' + carrier + '/' + number;
};
export default filter;
```

Argumenty podaje się w szablonie po dwukropku, oddzielone przecinkami:

```txt title="Szablon"
{{ shipment.number | x_shipping_ext_trackingurl: "ups" }}
```

<Callout type="warn" title="Filtry odpowiadają od razu">
Filtr nie może być `async` i nie może na nic czekać. Domyślny eksport `async` jest odrzucany przy przesłaniu, a filtr, który wywołuje asynchronicznego pomocnika, jest odrzucany w przeglądzie instalacji.
</Callout>

## Kiedy filtry działają [#when-filters-work]

Filtr niczego nie wywołuje, więc działa także wtedy, gdy rozszerzenie nie jest uruchomione, np. gdy jego połączenie nie jest jeszcze skonfigurowane. Przestaje działać, gdy rozszerzenie zostanie wyłączone.

Pliki reguł tej samej paczki nie mogą używać jej filtrów: wykonaj przekształcenie w skrypcie.

## Filtr czy krok? [#a-filter-or-a-step]

| Użyj filtra, gdy | Użyj kroku, gdy |
| --- | --- |
| Przekształcasz lub formatujesz jedną wartość. | Wywołujesz usługę albo łączysz kilka wartości. |
| Wynik jest używany w szablonach. | Wynik zasila kolejne kroki reguły. |
| Nie potrzeba danych uwierzytelniających. | Praca wymaga połączenia. |

## Problemy [#problems]

| Kod | Przyczyna | Rozwiązanie |
| --- | --- | --- |
| `filter.invalid` | Nieznany klucz albo nazwa z `_`, wielkimi literami lub dłuższa niż 41 znaków. | Użyj małych liter i cyfr. |
| `filter.script_invalid` | `script` nie wskazuje pliku `.js` ani `.ts`. | Wskaż moduł skryptu filtra. |
| `script.invalid` | Skrypt nie jest modułem z jednym `export default` albo jego domyślny eksport jest `async`. | Zobacz [Skrypty](/docs/pl/extensions/reference/scripts#problems). |
| `name.duplicate` | Dwa filtry o tej samej nazwie. | Zmień jedną z nazw. |
| `rule.own_filter_unsupported` | Plik reguły paczki używa jednego z jej filtrów. | Wykonaj przekształcenie w skrypcie. |
| `filter.not_sync` | W przeglądzie instalacji: filtr wywołuje asynchronicznego pomocnika. | Spraw, żeby odpowiadał od razu. |
| `filter.save_validation` | W przeglądzie instalacji: skrypt nie przechodzi walidacji albo inny skrypt organizacji ma jego nazwę. | Popraw skrypt albo zmień nazwę filtra. |
