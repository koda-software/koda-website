title: Formularze, listy i strony
description: "Zbuduj rozszerzenie Opero, które przynosi ekrany do pracy dla członków: formularze na własnych obiektach, listy własne i stronę obszaru roboczego."
---

Obiekt jest przydatny dopiero wtedy, gdy członkowie mogą otwierać, przeglądać i tworzyć jego rekordy. Ten przewodnik buduje paczkę **Sklep**, która przechowuje zamówienia z ich pozycjami i przynosi do nich ekrany: formularz **Order** z pozycjami zamówienia, listę **Open orders** i stronę obszaru roboczego **Zamówienia**, która łączy licznik, listę, blok i formularz.

![Strona Shop w obszarze roboczym: licznik otwartych zamówień, lista, blok podsumowania i formularz nowego zamówienia](/docs/_assets/extensions/workspace-screens/shop-page.webp)

Ekrany wskazują się nawzajem odwołaniami, takimi jak `{ $ref: "list:open-orders" }`, nigdy identyfikatorem, bo identyfikatory są w każdej organizacji inne. Opero zamienia każde odwołanie na zainstalowany identyfikator. Zobacz [Odwołania](/docs/pl/extensions/reference/screens#references).

<Steps>
<Step>
### Napisz manifest [#write-the-manifest]

```yaml title="extension.yaml"
manifestVersion: 2
extension: shop
version: 1.0.0
name: Shop
description: Keeps orders with their lines, and the screens to work with them.
publisher: Your company
requires:
  modules: [objects, queries]
permissions:
  links:
    - host: shop.example.test
      reason: Opens an order in the shop.

objects:
  - objects/orders
  - objects/order-lines
queries:
  - queries/open-count
blocks:
  - blocks/order-summary
forms:
  - forms/order
  - forms/line
lists:
  - lists/open-orders
  - lists/order-lines
pages:
  - pages/orders

locales: [pl]
```

Lista otwiera zamówienia w sklepie, więc jej host jest w `permissions.links`. `opero-ext add form`, `add list` i `add page` zapisują folder startowy i dopisują go tutaj.
</Step>

<Step>
### Dodaj obiekty [#add-the-objects]

```yaml title="objects/orders/object.yaml"
object: orders
name: Order
namePlural: Orders
icon: package
fields:
  - { key: title, name: Title, type: TEXT }
  - { key: status, name: Status, type: TEXT }
  - { key: external_id, name: Shop id, type: TEXT }
```

```yaml title="objects/order-lines/object.yaml"
object: order-lines
name: Order line
namePlural: Order lines
fields:
  - { key: product, name: Product, type: TEXT }
  - { key: quantity, name: Quantity, type: NUMBER }
  - key: order
    name: Order
    type: REFERENCE
    options: { toObject: orders }
```

Każda pozycja wskazuje swoje zamówienie. Zobacz [Obiekty](/docs/pl/extensions/reference/objects).
</Step>

<Step>
### Dodaj zapytanie licznika i blok [#add-the-counters-query-and-the-block]

Strona liczy otwarte zamówienia zapytaniem, a strona i formularz pokazują mały blok.

```yaml title="queries/open-count/query.yaml"
query: open_count
name: Open orders
kind: FETCH
sql: query.sql
```

```sql title="queries/open-count/query.sql"
SELECT count(*) AS value
FROM {{object.orders}}
WHERE f_status <> 'closed'
```

```yaml title="blocks/order-summary/block.yaml"
block: order_summary
label: Order summary
html: block.html
inputs:
  title: { type: text, label: Title, default: Order }
tests: tests.yaml
```

```html title="blocks/order-summary/block.html"
<section class="summary">
  <h3>{{ inputs.title }}</h3>
</section>
```

```yaml title="blocks/order-summary/tests.yaml"
- name: shows its title
  inputs: { title: Order A-1 }
  contains: ["Order A-1"]
```
</Step>

<Step>
### Dodaj formularz zamówienia [#add-the-order-form]

`form.yaml` opisuje formularz, a `layout.yaml` to jego [układ widoku](/docs/pl/extensions/reference/screens#formyaml). `default` sprawia, że zamówienie otwiera się w tym formularzu, gdy obiekt nie ma jeszcze żadnego.

```yaml title="forms/order/form.yaml"
form: order
object: orders
name: Order
types: [view, edit, create]
default: [view, edit, create]
config:
  title: New order
  successMessage: Saved
layout: layout.yaml
```

```yaml title="forms/order/layout.yaml"
schemaVersion: 2
regions:
  main:
    - id: details
      kind: card
      children:
        - { id: f_title, kind: field, field: { source: dynamic, key: title } }
        - { id: f_status, kind: field, field: { source: dynamic, key: status } }
    - id: summary
      kind: component
      component: custom_block
      config:
        customBlockId: { $ref: "block:order_summary" }
        inputs: { title: "Order {{ record.title }}" }
    - id: lines
      kind: component
      component: layout.customList
      config:
        customListId: { $ref: "list:order-lines" }
        params: { order: "{{ record.id }}" }
```

Ostatni komponent osadza listę pozycji i przekazuje jej identyfikator zamówienia jako parametr `order`.
</Step>

<Step>
### Dodaj formularz pozycji [#add-the-line-form]

```yaml title="forms/line/form.yaml"
form: line
object: order-lines
name: Order line
types: [create, edit]
layout: layout.yaml
```

```yaml title="forms/line/layout.yaml"
schemaVersion: 2
regions:
  main:
    - id: line
      kind: card
      children:
        - { id: f_order, kind: field, field: { source: dynamic, key: order } }
        - { id: f_product, kind: field, field: { source: dynamic, key: product } }
        - { id: f_quantity, kind: field, field: { source: dynamic, key: quantity } }
```
</Step>

<Step>
### Dodaj listy [#add-the-lists]

```yaml title="lists/open-orders/list.yaml"
list: open-orders
name: Open orders
description: Orders that are not closed yet.
source: { object: orders }
config:
  columns: [{ field: title }, { field: status }]
  baseFilter:
    op: AND
    items: [{ field: status, operator: neq, value: closed }]
  modes: [table]
  views: [{ id: default, name: Default, default: true, config: { schemaVersion: 2 } }]
  builtInActions: [create, open]
  create: { formId: { $ref: "form:orders.order" } }
actions:
  - key: open_in_shop
    type: OPEN_LINK
    label: Open in shop
    config: { url: "https://shop.example.test/orders/{{ row.external_id }}" }
```

```yaml title="lists/order-lines/list.yaml"
list: order-lines
name: Order lines
source: { object: order-lines }
config:
  columns: [{ field: product }, { field: quantity }]
  parameters: [{ key: order, label: Order, required: true }]
  baseFilter:
    op: AND
    items: [{ field: order, operator: eq, value: "{{ params.order }}" }]
  modes: [table]
  views: [{ id: default, name: Default, default: true, config: { schemaVersion: 2 } }]
  builtInActions: [create, edit]
  create: { formId: { $ref: "form:order-lines.line" } }
```

Formularz wskazuje się jako `<obiekt>.<formularz>`. Lista pozycji przyjmuje parametr `order` i pokazuje tylko pozycje tego zamówienia. Lista może też czytać wbudowane źródło, na przykład kontrahentów, przez `source: { builtIn: contractors }`. Zobacz [list.yaml](/docs/pl/extensions/reference/screens#listyaml).
</Step>

<Step>
### Dodaj stronę [#add-the-page]

```yaml title="pages/orders/page.yaml"
page: orders
title: Orders
description: Open orders and how many there are.
surface: workspace
layout: layout.yaml
```

```yaml title="pages/orders/layout.yaml"
schemaVersion: 2
regions:
  main:
    - id: open
      kind: component
      component: page.counter
      config:
        savedQueryId: { $ref: "query:open_count" }
        valueTemplate: "{{ value }}"
    - id: list
      kind: component
      component: layout.customList
      config:
        customListId: { $ref: "list:open-orders" }
    - id: summary
      kind: component
      component: custom_block
      config:
        customBlockId: { $ref: "block:order_summary" }
        inputs: { title: Today }
    - id: new_order
      kind: component
      component: page.form
      config:
        formId: { $ref: "form:orders.order" }
        capability: CREATE
    - id: shop
      kind: component
      component: layout.button
      config:
        label: Open the shop
        action: open_url
        url: "https://shop.example.test/admin"
```

Strona zostaje zainstalowana z adresem `x-shop-orders`. Zobacz [page.yaml](/docs/pl/extensions/reference/screens#pageyaml).
</Step>

<Step>
### Przetłumacz [#translate-it]

```yaml title="locales/pl.yaml"
extension:
  name: Sklep
  description: Zamówienia z pozycjami i ekrany do pracy z nimi.
permissions:
  links:
    shop.example.test:
      reason: Otwiera zamówienie w sklepie.
blocks:
  order_summary:
    label: Podsumowanie zamówienia
forms:
  orders:
    order:
      config:
        title: Nowe zamówienie
        successMessage: Zapisano
pages:
  orders:
    title: Zamówienia
    description: Otwarte zamówienia i ich liczba.
```

Nazwy formularzy i list, etykiety kolumn i etykiety akcji są tylko po angielsku. Zobacz [Tłumaczenia](/docs/pl/extensions/reference/screens#translations).
</Step>

<Step>
### Zwaliduj, przetestuj i spakuj [#validate-test-and-pack]

```bash title="Terminal"
opero-ext validate .
opero-ext test . --server https://opero.example.com/mcp
opero-ext pack .
```

</Step>
</Steps>

## Po instalacji [#after-install]

[Zainstaluj plik zip](/docs/pl/extensions/install) jak zwykle. Przegląd wymienia ekrany w sekcji **Ekrany, które zobaczą członkowie**. W odróżnieniu od innych części rozszerzenia trafiają one do członków od razu:

| Ekran | Kto go widzi po instalacji | Co robisz |
| --- | --- | --- |
| Strona | Każdy członek każdej firmy. | Dodaj ją do menu firmy; paczka nie dodaje żadnej pozycji menu. W razie potrzeby zawęź jej firmy i odbiorców. |
| Formularze | Każda firma, w której jest udostępniony moduł `x-shop`, czyli wszystkie, dopóki tego nie zawęzisz. | Ustaw, kto może używać każdego formularza, tak jak dla własnych formularzy. |
| Listy | Członkowie widzą listę tam, gdzie osadza ją strona albo formularz. | Nic. |

Zamówienie otwiera się teraz w formularzu z paczki, z pozycjami poniżej:

![Zamówienie otwarte w formularzu z paczki, z blokiem podsumowania i pozycjami zamówienia](/docs/_assets/extensions/workspace-screens/shop-form.webp)

Formularze, listy i strona są tylko do odczytu i zmieniają się wyłącznie przy aktualizacji. Zobacz [Co organizacja robi dalej](/docs/pl/extensions/after-install#what-the-organization-does-next).
