Krok nie musi niczego wywoływać. Ta paczka dodaje krok **Margin** (`x-calc-ext.margin`), który przyjmuje cenę i koszt, a zwraca marżę i jej wartość procentową. Nie ma połączenia ani dostępu do sieci, więc działa zaraz po instalacji.

<Steps>
<Step>
### Utwórz szkielet [#scaffold]

Zacznij od szkieletu, dodaj akcję i usuń przykładowy folder `actions/hello`. `init` zapisuje też wizytówkę i pliki dla edytora, jak w [samouczku](/docs/pl/extensions/tutorial/start-the-package).

```bash title="Terminal"
opero-ext init calc-ext --name Calc
cd calc-ext
opero-ext add action margin
```
</Step>

<Step>
### Napisz manifest [#write-the-manifest]

Zastąp `extension.yaml`, który nie wymienia już `actions/hello`:

```yaml title="extension.yaml"
# The package's contents: every feature it installs is listed here.
manifestVersion: 2
extension: calc-ext
version: 0.1.0
name: Calc
description: Calculation steps for rules.
publisher: Your company
requires:
  modules: [rules]

actions:
  - actions/margin
```
</Step>

<Step>
### Opisz akcję [#describe-the-action]

Pola wejściowe stają się formularzem kroku; `help` otwiera się ze znaku zapytania obok etykiety.

```yaml title="actions/margin/action.yaml"
action: margin
label: Margin
description: Computes the margin and the margin percentage of a price and a cost.

input:
  price: { type: text, label: Price, help: "A decimal number, written as text.", required: true }
  cost: { type: text, label: Cost, required: true }
output:
  margin: { type: number, label: Margin }
  marginPercent: { type: number, label: Margin (%) }

run: run.js
tests: tests.yaml

expose:
  ruleStep: { category: data }
```

<Callout type="warn" title="Deklaruj wejścia jako tekst">
Wartości, które reguła podaje krokowi, są sprawdzane względem jego pól wejściowych przy zapisie reguły, więc pole typu `number` przyjmie tylko stałą liczbę, a nie `{{ record.price }}`. Nadaj wejściom typ `text` i przelicz je w skrypcie.
</Callout>
</Step>

<Step>
### Napisz skrypt [#write-the-script]

Rzucenie błędu kończy krok błędem.

```js title="actions/margin/run.js"
/** @type {import('../../.opero/types').Action<'margin'>} */
const run = ({ input }) => {
  const price = Number(input.price);
  const cost = Number(input.cost);
  if (!Number.isFinite(price) || !Number.isFinite(cost) || price <= 0) {
    throw new Error('The price and the cost are numbers, and the price is above zero.'); // [!code highlight]
  }
  const margin = Math.round((price - cost) * 100) / 100;
  return {
    margin,
    marginPercent: Math.round((margin / price) * 10000) / 100,
  };
};
export default run;
```
</Step>

<Step>
### Przetestuj [#test-it]

Pierwszy przypadek porównuje dokładny wynik, drugi dowodzi, że błędne wejście kończy się błędem.

```yaml title="actions/margin/tests.yaml"
- name: a price of 200 and a cost of 150 give 25 percent
  input: { price: "200", cost: "150" }
  returns: { margin: 50, marginPercent: 25 }

- name: text that is not a number fails the step
  input: { price: abc, cost: "150" }
  fails: true
```
</Step>

<Step>
### Zwaliduj i spakuj [#validate-and-pack]

```bash title="Terminal"
opero-ext validate .
opero-ext pack .
```

</Step>
</Steps>

## Po instalacji [#after-install]

[Zainstaluj plik zip](/docs/pl/extensions/install) jak zwykle. Nie ma niczego do skonfigurowania: ani ustawień, ani połączenia, więc rozszerzenie od razu ma status **Działa**. Krok jest w kategorii **Dane** edytora reguł, bo deklaruje `category: data`.

W regule krok zapisuje swój wynik jako `margin`, więc kolejne kroki odczytują `{{ margin.marginPercent }}`:

```json title="Krok w jednej z reguł organizacji"
{
  "type": "x-calc-ext.margin",
  "contextKey": "margin",
  "config": { "price": "{{ trigger.data.price }}", "cost": "{{ trigger.data.cost }}" }
}
```

## Gdy krok to za dużo [#when-a-step-is-too-much]

Jeśli obliczenie przelicza pojedynczą wartość, [filtr szablonu](/docs/pl/extensions/reference/filters) jest lżejszy niż krok. Jeśli potrzebuje go tylko jedna reguła, krok **Uruchom skrypt** napisany bezpośrednio w tej regule w ogóle nie wymaga rozszerzenia.
