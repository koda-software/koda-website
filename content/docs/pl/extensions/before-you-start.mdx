Rozszerzenie to folder plików YAML i skryptów, który sprawdzasz i pakujesz narzędziem wiersza poleceń, a potem przesyłasz do organizacji. Ta strona wymienia, czego potrzebujesz do każdej z tych dwóch części pracy.

## Do budowania [#to-build]

| Potrzebujesz | Dlaczego |
| --- | --- |
| Narzędzia wiersza poleceń | `opero-ext` tworzy szkielet paczki, sprawdza ją, pakuje plik zip i go przesyła. Zobacz [Zainstaluj narzędzie wiersza poleceń](#install-the-command-line-tool). |
| Edytora z obsługą YAML | Opcjonalnie. Folder utworzony przez `init` podpowiada VS Code (z rozszerzeniem YAML), jakiego schematu używa każdy plik, więc klucze uzupełniają się w trakcie pisania. |
| Dokumentacji API usługi | Dokładnych adresów URL, sposobu uwierzytelniania i tego, co usługa zwraca. |
| Testowych danych uwierzytelniających do tej usługi | Tylko do końcowego sprawdzenia na żywo. Własne testy paczki ich nie potrzebują. |
| Modułu **Tworzenie rozszerzeń** | Tylko dla `opero-ext test` (testy w Opero) i `opero-ext pull` (eksport). Przesyłanie i instalacja go nie wymagają. |

## Do instalacji [#to-install]

| Potrzebujesz | Dlaczego |
| --- | --- |
| Konta administratora | Przesyłanie i instalacja wymagają uprawnień `org.extensions.*` oraz uprawnień do tworzenia tego, co przynosi paczka. Wbudowana rola administratora ma je wszystkie; wymienia je strona [Instalacja rozszerzenia](/docs/pl/extensions/install#before-you-start). |
| Modułu Reguły | Rozszerzenia instalują reguły. Paczka z obiektami potrzebuje też modułu Obiekty, paczka z zapytaniami modułu Zapytania SQL, a paczka, która generuje dokumenty, modułu Dokumenty. |
| Roli właściciela organizacji | Tylko dla paczki, która deklaruje [zakresy danych](/docs/pl/extensions/reference/data-permissions). |

## Zainstaluj narzędzie wiersza poleceń [#install-the-command-line-tool]

`opero-ext` to jeden plik wykonywalny z wbudowanym Node.js. Nie wymaga uprawnień administratora.

<Tabs items={['Linux, macOS', 'Windows']}>
<Tab value="Linux, macOS">

```bash title="Terminal"
curl -fsSL https://hub.kodasoft.pl/extension-cli/install.sh | sh
```

</Tab>
<Tab value="Windows">

```powershell title="PowerShell"
irm https://hub.kodasoft.pl/extension-cli/install.ps1 | iex
```

</Tab>
</Tabs>

Sprawdź je poleceniem `opero-ext version`, które wypisuje wersję i platformę. Aktualizuj je poleceniem `opero-ext update`, które sprawdza podpis wydania. [Narzędzie wiersza poleceń](/docs/pl/extensions/reference/cli#install) wymienia platformy i podpowiada, co zrobić, gdy przeglądarka zablokuje pobieranie.

<Callout title="Licencja">
**Tworzenie rozszerzeń** to osobny, licencjonowany moduł, domyślnie wyłączony. Bez niego `opero-ext test` i `opero-ext pull` kończą się kodem 4, a cała reszta działa. Administrator włącza go w modułach organizacji, gdy obejmuje go licencja.
</Callout>

## Najpierw poznaj edytor reguł [#know-the-rule-builder-first]

Plik reguły to reguła zapisana jako tekst, więc warto zbudować w Opero choć jedną regułę z krokiem **Wywołaj webhook**. Jeśli jeszcze tego nie znasz, przeczytaj [Reguły](/docs/pl/opero/07-automatyzacja/reguly-wprowadzenie) i [Akcje](/docs/pl/opero/07-automatyzacja/akcje).

## Wybierz właściwe narzędzie [#choose-the-right-tool-for-the-job]

Rozszerzenie nie zawsze jest najlżejszym rozwiązaniem.

| Chcesz | Użyj |
| --- | --- |
| Przeliczyć lub sformatować pojedynczą wartość w szablonach | [Filtra szablonu](/docs/pl/extensions/reference/filters) w rozszerzeniu albo skryptu własnego, jeśli potrzebuje go tylko twoja organizacja. |
| Uruchomić trochę logiki tylko w jednej regule | Kroku **Uruchom skrypt** napisanego bezpośrednio w tej regule. Rozszerzenie nie jest potrzebne. |
| Dać wielu regułom albo wielu organizacjom jeden czytelny krok, który wywołuje usługę | Rozszerzenia z [połączeniem](/docs/pl/extensions/reference/connection-and-secrets) i akcjami. |
| Reagować na zdarzenia w usłudze zewnętrznej | Rozszerzenia z [wyzwalaczem](/docs/pl/extensions/reference/triggers) i [harmonogramem](/docs/pl/extensions/reference/schedules), który odczytuje usługę i zgłasza zdarzenie dla tego, co się zmieniło. |
| Pracować z własnym kontem każdego członka w usłudze | Rozszerzenia z [połączeniem członka](/docs/pl/extensions/reference/member-connections). |
| Przenieść słowniki, obiekty, zapytania, filtry albo bloki zbudowane już w jednej organizacji do innych | Rozszerzenia [wyeksportowanego z tej organizacji](/docs/pl/extensions/start-from-your-organization). |

## Czego rozszerzenie jeszcze nie potrafi [#what-an-extension-cannot-do-yet]

| Nie możesz | Zamiast tego |
| --- | --- |
| Sięgać do własnych obiektów organizacji | Paczka odczytuje i zapisuje tylko swoje obiekty i kontrahentów. Pozostałą pracę na rekordach wykonuje z wynikiem reguła, która używa twojego kroku. |
| Umieszczać czegokolwiek w menu | Administrator dodaje strony paczki do menu. |
| Dostarczać formularzy dla obcych obiektów, formularzy publicznych, stron portalu ani akcji list, które uruchamiają regułę albo skrypt | Zbuduj je w organizacji. |
| Wysyłać ze skrzynki pocztowej ani przynosić szablonów e-maili i dokumentów | E-maile idą przez usługę e-mail instalacji, a dokumenty korzystają z szablonu, który wybiera organizacja. |
| Odbierać webhooków | Odczytuj usługę według [harmonogramu](/docs/pl/extensions/reference/schedules). Przychodzące webhooki są zaplanowane. |
| Zgłaszać zdarzeń z kroku | Zgłaszaj je z uruchomienia harmonogramu albo z akcji połączenia członka. |
| Uruchamiać się według wyrażenia cron albo w odstępie wybranym przez administratora | Wybierz jeden z siedmiu stałych odstępów harmonogramu. |
| Odnawiać tokenu członka | Członek łączy się ponownie, gdy usługa przestanie go przyjmować. |
| Przynosić obrazów, czcionek ani innych plików dla swoich bloków | Używaj obrazów udostępnianych przez usługę. |
| Używać w blokach akcji formularzy (`open-form`, `set-field`, `<opero-rating>`) ani uruchamiać reguły po identyfikatorze | Przyciski bloków uruchamiają własne akcje paczki. |
| Zgłaszać zdarzeń ani używać połączenia członka z akcji bloku czy polecenia rekordu ani uruchamiać polecenia w tle | Do pracy w tle użyj harmonogramu. |
| Oferować akcji bloków, poleceń i linków tokenom API, w zewnętrznym API ani w MCP | Członkowie używają ich w aplikacji. |
| Wywoływać hosta, którego nie zadeklarowano, ani niczego, co nie jest HTTPS | Zadeklaruj każdy host w `permissions.network`. |
