Potrzebujesz konta administratora w organizacji z modułem Reguły, narzędzia wiersza poleceń i dokumentacji API usługi, którą chcesz wywoływać.

| Potrzebujesz | Dlaczego |
| --- | --- |
| Konta administratora | Przesyłanie i instalacja wymagają uprawnień `org.extensions.*` oraz uprawnień do tworzenia tego, co przynosi paczka: reguł i skryptów własnych, w paczce z danymi także modułów własnych, słowników i zapisanych zapytań, a w paczce z ekranami modułów własnych (formularze), list własnych i stron. Wbudowana rola administratora ma je wszystkie. Paczkę, która deklaruje [zakresy danych](/docs/pl/extensions/reference/data-permissions), może zainstalować tylko właściciel organizacji. |
| Włączonego modułu Reguły | Rozszerzenia instalują reguły. Paczka z obiektami potrzebuje też modułu Obiekty, paczka z zapytaniami modułu Zapytania SQL, a paczka, która generuje dokumenty, modułu Dokumenty. |
| Modułu Tworzenie rozszerzeń | Tylko dla narzędzi autorskich: uruchamiania testów paczki w Opero (`opero-ext test`) i eksportu konfiguracji organizacji jako paczki (`opero-ext pull`). Przesyłanie, instalacja, aktualizacja i działanie rozszerzeń go nie wymagają. |
| Narzędzia wiersza poleceń | `opero-ext` tworzy szkielet folderu albo go eksportuje, sprawdza go, zapisuje plik zip, testuje go w Opero i instaluje. Zobacz [Narzędzie wiersza poleceń](/docs/pl/extensions/reference/cli). |
| Edytora z obsługą YAML | Opcjonalnie. Folder utworzony przez `init` podpowiada VS Code (z rozszerzeniem YAML), jakiego schematu używa każdy plik, więc klucze się uzupełniają, a błędy są podkreślane w trakcie pisania. |
| Dokumentacji API usługi | Potrzebujesz dokładnych adresów URL, sposobu uwierzytelniania i tego, co usługa zwraca. |
| Testowych danych uwierzytelniających do tej usługi | Do końcowego sprawdzenia na żywo. Testy kontraktowe ich nie potrzebują. |

## Zainstaluj narzędzie wiersza poleceń [#install-the-command-line-tool]

`opero-ext` to jeden plik wykonywalny z wbudowanym Node.js. Nie wymaga uprawnień administratora.

<Tabs items={['Linux, macOS', 'Windows']}>
<Tab value="Linux, macOS">

```bash title="Terminal"
curl -fsSL https://hub.kodasoft.pl/extension-cli/install.sh | sh
```

</Tab>
<Tab value="Windows">

```powershell title="PowerShell"
irm https://hub.kodasoft.pl/extension-cli/install.ps1 | iex
```

</Tab>
</Tabs>

Sprawdź je poleceniem `opero-ext version` i aktualizuj poleceniem `opero-ext update`, które sprawdza podpis wydania. [Narzędzie wiersza poleceń](/docs/pl/extensions/reference/cli#install) wymienia platformy, to, co sprawdzają instalatory, i co zrobić, gdy pobranie przez przeglądarkę zostanie zablokowane.

<Callout title="Licencja">
**Tworzenie rozszerzeń** to osobny, licencjonowany moduł, domyślnie wyłączony. Bez niego organizacja nadal może przesyłać, instalować, aktualizować i uruchamiać rozszerzenia; tylko `opero-ext test` i `opero-ext pull` kończą się kodem 4, odpowiadające im ścieżki API zwracają `403 MODULE_UNAVAILABLE`, a odpowiadające im narzędzia MCP nie są oferowane. Administrator włącza go w modułach organizacji, gdy obejmuje go licencja.
</Callout>

## Najpierw poznaj edytor reguł

Warto zbudować w Opero choć jedną regułę z krokiem **Wywołaj webhook**, bo plik reguły to dokładnie to samo, tylko zapisane jako tekst. Jeśli jeszcze tego nie znasz, przeczytaj [Reguły](/docs/pl/opero/07-automatyzacja/reguly-wprowadzenie) i [Akcje](/docs/pl/opero/07-automatyzacja/akcje).

## Wybierz właściwe narzędzie

Rozszerzenie nie zawsze jest najlżejszym rozwiązaniem.

| Chcesz | Użyj |
| --- | --- |
| Przeliczyć lub sformatować pojedynczą wartość w szablonach | [Filtra szablonu](/docs/pl/extensions/reference/filters) w rozszerzeniu albo skryptu własnego, jeśli potrzebuje go tylko twoja organizacja. |
| Uruchomić trochę logiki tylko w jednej regule | Kroku **Uruchom skrypt** napisanego bezpośrednio w tej regule. Rozszerzenie nie jest potrzebne. |
| Dać wielu regułom albo wielu organizacjom jeden czytelny krok, który wywołuje usługę | Rozszerzenia z [połączeniem](/docs/pl/extensions/reference/connection-and-secrets) i akcjami. |
| Reagować na zdarzenia w usłudze zewnętrznej | Rozszerzenia z [wyzwalaczem](/docs/pl/extensions/reference/triggers) i [harmonogramem](/docs/pl/extensions/reference/schedules), który odczytuje usługę i zgłasza zdarzenie dla tego, co się zmieniło. Usługa nie może wywołać paczki: przychodzące webhooki nie są jeszcze obsługiwane. |
| Pracować z własnym kontem każdego członka w usłudze | Rozszerzenia z [połączeniem członka](/docs/pl/extensions/reference/member-connections). |
| Przenieść słowniki, obiekty, zapytania, filtry albo bloki zbudowane już w jednej organizacji do innych | Rozszerzenia [wyeksportowanego z tej organizacji](/docs/pl/extensions/start-from-your-organization). |
